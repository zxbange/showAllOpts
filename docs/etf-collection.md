# 国家队动态：页面配置与采集

管理员登录后，在「市场情绪 → 国家队动态 → 采集配置」完成设置，不需要编辑环境文件或运行采集命令。普通用户只能看图表和采集状态。

## 页面操作

1. 使用可信的 HTTPS 地址打开网站。HTTP 页面可以按现有站点规则登录，但不能提交或测试数据库凭据。不要绕过浏览器证书警告。
2. 在图表和明细下方展开页面最底部的「采集配置」。填写数据库主机、端口和库名，默认带入现有连接。保存后，ETF采集、ETF图表读取及缓存同步共同使用此目标；其他业务模块仍使用原数据库。切换目标会要求重新同步ETF缓存，不会展示旧库快照或迁移、删除任一库的业务数据。
3. 输入具备所需权限的账号和密码，可以与应用当前账号相同，无需另建账号。密码不会回显，已保存后留空表示保留；更换主机、端口、库名或账号后必须重新输入，旧密码不会发给新目标。不按账号名称限制使用，是否可用由实际连接与权限决定。
4. 按需设置自动采集开关和每日一个时间（北京时间，默认09:00）。日常接口仅更新最新已收市交易日；2024-01-01起的历史由聚宽平台脚本手动补齐，不再通过页面接口补历史。旧配置中的历史范围、批量日期数为兼容保留，不再决定接口请求范围。旧版多时段读取时合并为09:00，原有单一自定义时间保留。改时间不会造成当天新增第二次自动采集，失败重试仍属于同一轮。
5. 点击「测试连接（只读）」检查连接和三张表的读取。测试不写入、不保存配置，不证明写权限已经具备。缺表、权限或连接失败会明确提示。
6. 点击「保存采集配置」，立即生效并持久保存，不需要重启。点击「立即采集」异步提交一轮日常更新；排队/运行期间按钮变为可点击的「取消采集」。点击取消后等待当前网络请求或数据库事务在安全边界结束，页面再显示「已取消」。已提交数据与账本保留，未提交的本轮数据不计入成功。任务终止后再次明确点击会创建新一轮。自动采集关闭时仍可手动运行，采集运行/排队期间不能修改配置。
7. 本轮目标日达到自动重试上限时，可手动发起新一轮；勾选重新尝试还会重置该目标日失败观测的计数。操作不会重置历史缺口、删除已完成记录，也不会通过接口补历史。

页面顶部刷新只读取已经保存的数据，不采集交易所数据。手动请求有独立幂等编号，网络响应不确定时重试相同请求不会重复创建任务。取消按任务编号持久保存，其他API进程也能取消当前任务，不会误取消后续的新任务。若服务重启中断任务，页面显示「已中断」；重启前已经请求取消的任务恢复为「已取消」，不会自动重新采集。数据库写入仍是幂等的。

## 权限与传输保护

采集账号只需以下三表的 SELECT、INSERT、UPDATE：

- etf_share_daily
- etf_price_daily
- etf_trading_day

若首次采集需要创建缺失表，还需这些表的 CREATE 权限。已有表不会删除或重建；不需要 DELETE、DROP、ALTER 或全库管理员权限。应用不会创建数据库账号、授予权限或更改任何账号权限。所填账号具备以上权限即可，不要求与应用账号分开。

ETF 数据库连接固定不启用 TLS，页面和接口不再提供 TLS 选项或额外确认项；连接测试、自动/手动采集及已配置的 ETF 自定义数据源读取均使用该行为。服务器到 MySQL 的凭据交换和查询数据不受 TLS 保护，跨不可信网络时可能被窃听或篡改，应使用可信网络和最小权限账号。浏览器到网站仍必须使用 HTTPS，认证、管理员、同源和 CSRF 要求保持不变；其他模块的数据库和网站 HTTPS 配置不受影响。

旧加密配置的 db_tls 和确认字段在读取时忽略，原密文、密码、版本号及账本不改写；下次保存时去除旧字段。旧 ETF_COLLECTION_WRITER_URL 的 TLS 查询参数也不会启用加密。要求加密传输或客户端证书的数据库会连接失败，不会自动修改数据库服务端策略、账号权限或回退到其他目标。更新后的 ETF 自定义数据源缓存标识不再包含 TLS 选项，旧缓存需重新同步一次，期间不会将其误用为新目标数据；其他模块缓存保持不变。

页面凭据使用既有受限权限密钥存储机制加密保存，不在 API 响应、验证错误或日志中回显。密钥与状态数据库分开存放，缺失/不匹配时停止操作，绝不生成替代密钥覆盖原配置。备份时应一并保护整个持久 LOG_DIR。源连接、手动操作均保留管理员、同源及 CSRF 检查。

## 时间、数据与故障状态

默认每天09:00，给深市次日发布份额留出时间，并尽量在开盘前读取上一交易日已核验的收盘价。自动及手动采集均更新份额和可信收盘价；15:00前只处理此前已收市日期，15:00后仍须官方日历和行情快照确认收市才接纳当日，绝不将盘中报价当收盘价。深市价格仍必须与同日盘后报价交叉核验；若来源已经转为当日盘中报价或尚未公布，保持缺失并有限重试，不推算补值。交易所官方日期和值为准，不保证09:00必然已全部发布。

启动不立即访问交易所，之后的计划时段才触发；此前已有的同日失败/部分任务按原有重试规则恢复。每个计划时段最多两次，至少相隔 30 分钟。交易所请求和数据库连接均有超时与有限重试。周末/节假日仍可复核及小批补历史。

每日接口仅更新最新已收市交易日，不扫描或补采旧账本的历史缺口。每次都重新核验该日的份额与可信收盘价，只有本次数据都齐全才显示「本次日常采集完成」；仍缺份额/价格时显示部分完成，历史完整度不由该状态推断。旧历史账本及数据库记录保留，不能因为旧账本缺口而阻塞最新日。写库失败不消耗缺口重试额度，成功写库后才更新观测账本。

历史从2024-01-01起在聚宽平台运行补采脚本，写入同一ETF三张表后，手动同步ETF缓存即可让页面显示。完整脚本、预览和写库步骤见 [聚宽历史补采说明](etf-joinquant-history.md)。源数据缺失、上市前无数据或拆分风险不能填0、前值续填或推算。份额图的日期轴包含已核验交易日，缺失点保留为断线；流通市值要求同日全部成分的份额和未复权收盘价齐全，并继续排除疑似拆分错位日期。

只更新 ETF 缓存，其他模块待同步状态保留。缓存暂时无法发布时显示等待更新，后台至少间隔五分钟重试发布，不重复抓交易所。原 07:00 数据库到缓存同步保持不变。

状态接口保留最近计划运行记录、最近手动任务和本轮目标日进度。待采、受限、重试耗尽及缺口计数只描述本轮目标日，不表示聚宽历史是否补齐；详细缺口列表最多返回500项。数据库失败以ERROR记录安全诊断（阶段、异常类型、MySQL/OS错误码、固定表名、目标指纹），不含连接字符串、原始SQL/参数或数据库驱动原始文本。

## 既有部署兼容

未通过页面保存前，继续使用既有 ETF_COLLECTION_ENABLED、ETF_COLLECTION_WRITER_URL、ETF_COLLECTION_LOOKBACK_DAYS、ETF_COLLECTION_BATCH_DAYS。首次页面保存后，以页面的加密配置为准；不会改写原服务配置或 DB_*。缺失/错误的旧写入配置可直接在页面修复。旧版固定目标配置仍能读取，保存新的主机、端口和库名后变为ETF专用目标。切换目标时，旧采集账本归档保留、新目标重新核验数据，避免沿用旧库的已完成记录。不会自动复制业务表或替用户变更权限。

所有进程须使用同一持久 LOG_DIR，文件锁和 SQLite 账本防止同一主机多进程并行采集。此方案不是跨不同主机磁盘的分布式锁，多主机部署只在一个主机启用采集。
