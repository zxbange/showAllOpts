# 短线选股胜率研究

独立脚本：[短线选股胜率_研究版.py](../collectors/短线选股胜率_研究版.py)。直接在聚宽研究环境展示结果，不连接业务数据库，不生成 CSV，不加入每日批量采集。

## 运行

上传脚本到聚宽研究环境，然后执行：

```python
%run -i 短线选股胜率_研究版.py
```

也可以将整份代码粘贴到一个 Notebook 单元格执行。脚本包含三个策略的全部筛选逻辑，不需要上传其他策略文件，也不需要数据库配置。

脚本自动从当前命名空间、`jqdata` 和聚宽注入的 `builtins` 中依次加载接口，支持新建 Notebook 直接粘贴运行。更新接口兼容修复后，原有研究断点可以继续使用。

默认参数：

```python
START_DATE = '2026-07-01'  # 包含7月1日
END_DATE = None           # 入选截止日，默认最近已收盘交易日
AS_OF_DATE = None         # 观察截止日，默认最近已收盘交易日
PRICE_BATCH_SIZE = 50
USE_CACHE = True
CACHE_DIR = 'short_term_winrate_cache'
```

北京时间16:00前不使用当天日线。可以把入选截止日固定在一个历史日期，观察它之后的表现：

```python
research_result = run(
    start_date='2026-07-01',
    end_date='2026-09-30',
    as_of_date='2026-10-23',
)
```

## 如何看结果

控制台首先显示 **3个策略 × 3个观察期限，共9行胜率**：补票龙、红悬停龙、蓄力龙分别统计第2、第4、第10个交易日。

- 入选日是第0天，周末和节假日不计天数，股票停牌不顺延市场交易日。
- 收盘涨幅 = （观察日收盘价 / 入选日收盘价 − 1）× 100%，使用前复权价。同一次查询取得两个端点，不直接使用旧缓存的入选价作为新行情的分母。
- **胜率 = 涨幅严格大于0%的次数 / 有效样本数。** 持平计入分母，不算获胜；没有有效样本时显示“--”，不是0%。
- “超过50%”按实际次数判断，恰好50%显示“否”，不按显示时四舍五入的百分比判断。
- 同一股票在不同日期入选分别计一次；同日符合多个策略，各策略分别计一次。这里统计的是入选次数，不是去重股票数。
- 每个期限使用自己已走满观察期、价格及停牌状态有效的样本作为分母，因此三个期限的样本数可能不同。未走满的显示“待观察”。
- 退市或缺少端点价格/停牌状态的显示“数据缺失”，不虚构0收益，不进入胜率分母。评估结果时应同时查看缺失数量。
- 停牌沿用平台前收盘填充值估值，明细标明两端停牌状态，完整汇总单列“停牌估值样本”。这部分并不表示当日可成交。

接着展示六个累计门槛的次数：`>0%`、`>5%`、`>10%`、`<0%`、`<-5%`、`<-10%`。例如上涨12%同时计入三个上涨门槛；恰好上涨5%不计入`>5%`，恰好下跌5%不计入`<-5%`。

整份脚本执行后，可在 Notebook 中查看：

```python
winrate_df                 # 完整汇总：胜率、样本数、平均/中位涨跌幅等
threshold_df               # 六个门槛的次数
detail_df                  # 每个策略、入选日、股票、观察期限的明细
research_result.daily_counts  # 每日扫描数量及三个策略的入选数量
```

直接调用 `run(...)` 时，分别使用返回对象的 `summary`、`distribution`、`details` 和 `daily_counts` 属性。例如：

```python
research_result.summary[['策略', '观察期限（交易日）', '有效样本',
                         '胜率（%）', '超过50%', '平均涨跌幅（%）']]
```

## 历史筛选及续跑

业务数据库只保留最近3个交易日，无法从当前名单还原7月以来的历史记录。脚本按每个历史交易日重新取当时已上市股票、ST状态及总市值，统一剔除ST和总市值低于30亿元的股票；不是用今天的股票名单、市值或ST状态筛过去。

筛选函数与现有短线数据库版保持一致，仍用90个交易日预热；补票龙内部取60条、蓄力龙取65条，红悬停龙沿用实际涨停阈值逻辑。测试会核对两份脚本的筛选函数一致性。

市值/ST先批量过滤，三个策略共用一份日线扫描；不采集本研究不需要的行业、PE/PB、图表数据。后续收盘价只获取入选股票，单次最多50只。首次从7月开始逐日回放需要时间，控制台显示当前日期、行情批次与入选数量。

研究环境的 `short_term_winrate_cache/short_term_returns_v1/` 保存按日 JSON 断点：

1. 完整扫描一天后保存名单，零入选日也保存。
2. 后续行情按批提交断点；若中断，已完成名单和有效观察结果保留。
3. 重跑复用名单和有效结果，只补未完成、刚到观察期限或缺价的记录。
4. 修改入选/观察日期范围可复用已有断点；较晚观察日期的缓存不会泄漏进较早的统计截止日期。
5. 不主动重新修订已完成名单及有效收益。如需用源数据最新版本完整重跑，更换 `CACHE_DIR`，或设置 `USE_CACHE=False`。不要同时运行两个写入同一断点目录的任务。

## 解释范围

这项研究衡量的是**按当前规则回放的入选后收盘表现**，不是历史实际保存的入选名单，也不是可成交的交易回测。入选条件使用收盘数据，不能据此假定可以在已知信号后仍以同日收盘价买入；统计未扣手续费、滑点，也不模拟涨跌停限制。

样本胜率超过50%不保证盈利，更不保证未来胜率。应同时看有效样本数、平均涨跌幅和下跌尾部；连续多日入选同一股票会形成相关、重叠样本，不把这些次数当作相互独立的实盘交易。行情或复权数据修订也可能导致回放名单与当时运行结果不同。

API参数参考：[聚宽官方 JQData 源码](https://github.com/JoinQuant/jqdatasdk/blob/master/jqdatasdk/api.py)，包括历史日期查询、`panel=False`、前复权及停牌填充约定。Notebook实际调用聚宽研究环境提供的接口。兼容Python 3.6语法和旧版pandas，未使用 `to_numpy()`。

本地测试使用模拟接口，不产生真实市场胜率；真实结果需要在聚宽运行后取得。
