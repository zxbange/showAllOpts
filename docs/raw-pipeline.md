# 恢复聚宽计算入库模式

全部采集策略统一采用：聚宽研究环境采集、过滤并计算 → MySQL保存结果 → 项目同步到本地SQLite → 页面展示。之前的原始采集/本地计算方案已取消。批量脚本仍是单文件、串行执行，控制台保留进度与结果。

## 升级顺序

1. 更新聚宽中的完整 `collectors/策略批量采集_数据库版.py`，保留私有连接与策略参数；独立脚本也已恢复计算入库。先完整运行需要更新的模块。
2. 已有结果表继续增量使用：行业动量保留180个交易日；历史型策略只新增；净利润断层同季度已有股票不更新；高股息和高增长事务更新最新名单。
3. 如果之前只运行过原始采集，缺少结果的部分需要聚宽重新计算，不能通过页面同步自动转换。ETF/LOF仍保留大于30亿元、国内LOF及此前跨境/债券范围限制。
4. Linux在 `/home/ubuntu/showAllOpts` 执行 `bash deploy.sh`。已有 `config/app.config` 显式写了旧同步时间时，将其改成 `CACHE_REFRESH_TIME=20:00` 并重启后端。Windows更新后完整关闭旧进程，再运行 `start.cmd`。
5. 页面手动同步对应模块或全部模块。新缓存签名首次会重新同步结果；以后按结果表的增量规则同步。每天自动同步改为北京时间20:00，手动同步无需密钥。

源库 `raw_*` 与 `etf_momentum_bar` 原始表不再读取或更新，不会自动删除。历史结果、原始表和旧本地快照都不要在确认恢复前手工清理。项目不向源MySQL写入计算结果，仅维护本地缓存。

计算完成后才提交结果；采集失败保留已提交日期/基金，后续重跑续采。缓存同步失败继续保留上一份完整快照。详细参数和各策略规则见[批量采集](collector-batch.md)、[本地缓存](local-cache.md)及[ETF/LOF热度](etf-momentum.md)。
