# 原始采集与本地计算

九个模块统一采用“聚宽获取所需原始数据 → MySQL 保存 → 定时/手动同步 → 项目本地计算并保存 SQLite → 页面查询”。网页请求不运行聚宽代码、不触发同步，也不重新执行选股模型。

## 每个模块的分工

| 模块 | 聚宽采集与基础过滤 | 同步时本地计算 |
| --- | --- | --- |
| 行业动量 | 当日行业及成分、满足上市期限条件的股票、同一复权基准下的20日涨幅端点价格 | 涨幅阈值、行业强势股数量、动量和排名；零分行业保留 |
| 抱团拥挤度 | 当日A股股票名单及每只股票成交额，不预先只保留成交额前5% | 前TOP_PCT成交额占比及相关统计 |
| 微盘温度计 | 排除原规则不合格股票后的估值、5日换手率、成交额、归母净利润同比、上一期候选的价格端点 | 微盘池、估值中位数、拥挤比、历史分位、温度和连续指数 |
| 微盘新高新低 | 沿用原ST/上市期限/板块过滤，按市值筛出微盘池，采集31日完整收盘价 | 5/10/20/30日新高新低数量 |
| 高股息 | 基础股票池、估值、收盘价、分红逐条明细、财务指标、行业 | 一年股息率、三年分红比例、两套策略筛选及各自前25名 |
| 高增长 | A股累计财报，每类最新三期及修订版本；估值、行业。不先按增长率选股 | 四类报告的利润/EPS增长检查、年报增长排序 |
| 净利润断层 | 最新已结束季度公告，按原财务门槛初筛、获取相应行情及估值行业 | 公告对应交易日跳空检查、最终股票名单及证据；首次入选结果冻结 |
| ETF份额 | 份额本身就是原始数据，沿用现有采集 | 沿用本地份额查询与展示层的日增减、区间变化计算 |
| ETF/LOF动量热度 | 规模/范围筛选后的基金名单、实际与后复权收盘价、停牌状态 | 加权回归、年化趋势收益率、R²、热度及排名 |

允许采集端进行必要的日期归一化、数据校验和便宜的基础过滤。不会为了减少上传而只保存最终入选名单：例如拥挤度要保留全部成交额，高增长要保留不达标公司的财报。微盘温度计需要全体合格样本计算相对指标，也不能仅上传最小市值的一部分股票。

## 运行与升级顺序

1. 更新聚宽中的完整 `collectors/策略批量采集_数据库版.py`。文件名保持不变，默认入口已切换为原始采集。只运行某一个模块时，也可完整复制该模块现有 `*_数据库版.py`；七个计算型独立入口同样已更新。
2. 顶部 `DB_CONFIG` 填写自己的数据库连接；`STRATEGY_CONFIG` 按策略配置日期和参数。独立文件只展示本策略配置。独立与批量文件均可直接粘贴到 Notebook，无外部文件依赖、没有 `__file__` 要求。进度条及结果只打印到控制台。
3. 先在聚宽完整运行一次新版采集。旧得分无法还原原始数据，所以首次需要按各模块原来的起始范围重新采集，所需时间和数据库空间会明显多于仅保存结果。建议按模块完成采集，再逐模块同步；不必重复运行已经完成的模块。
4. Linux 在 `/home/ubuntu/showAllOpts` 执行 `bash deploy.sh`，安装新增的后端 pandas 依赖并重启服务。Windows 更新后完整关闭旧进程，再运行 `start.cmd`。保持 `CACHE_ENABLED=true`。
5. 页面“数据同步”选择对应模块或全部模块，点击立即同步。每天北京时间18:00仍会自动同步，采集应提前完成。同步成功后页面直接查询本地结果。

新版本缓存指纹发生变化，首次需要重建本地缓存。模块尚未开始新版采集时，项目可读取旧结果表兼容展示；一旦该模块有原始数据，就改用本地计算。原始数据不完整时明确失败，不悄悄退回旧算法。关闭缓存后访问已迁移模块会提示开启缓存，避免展示不再更新的旧MySQL结果。

`collectors/legacy/` 归档迁移前的七个计算入库脚本，供公式对照及完整版本回退使用，不应与新版入口混跑。源库旧结果表保留、不再由新版采集维护；不要在迁移验证前手动删除。净利润断层会只读导入旧表中已经存在的首次入选记录，作为冻结基准。

## 原始数据格式与写入规则

七张新表分别为 `raw_industry_momentum`、`raw_market_crowding`、`raw_microcap_temperature`、`raw_microcap_breadth`、`raw_dividend_selection`、`raw_high_growth`、`raw_earnings_gap`。

每个原始快照使用版本化 JSON，压缩后按48KiB分片存储。主键为 `(scope, trade_date, part)`，包含总分片数、SHA-256校验值、协议版本和更新时间。日期、Decimal及表格显式编码；不使用pickle，不保存可执行代码。快照所有分片在同一个事务提交。大报表分片避免单个BLOB超过MySQL字段大小；失败不会留下半个日期的完整标记。

- 行业动量：按实际运行日的交易日历清理，只保留最近180个交易日的原始快照；本地同步相应删除。
- 拥挤度：首次从2020-01-01起，随后增量追加，历史保留。
- 微盘温度计：首次从2021-01-01起，每5个交易日采样；之后接续原采样锚点，历史保留。
- 微盘新高新低：首次近180个自然日内的交易日，随后逐日增量，历史保留。
- 高股息、高增长：只保留最新原始快照；内容和参数摘要不变时不重复写入，发生变化时事务替换。
- 净利润断层：保留各季度的逐日原始扫描快照，同一交易日不重复覆盖。同步按日期依次筛选，同季度同股票只保留第一次命中的估值、公告和信号数据。晚到数据可在下一交易日采集后新增；不会覆盖已入选股票。
- ETF份额及ETF/LOF热度沿用各自的原始表和增量规则。

历史型模块按已提交日期续采；相同主键不会重复插入。源接口失败停止当前模块，已完成日期保留，批量入口继续后续模块。每个回补快照带该批目标完成日期；初次或长间隔回补尚未完成时，不发布半批计算结果。手工删除历史中间日期不属于正常续采流程，应核对备份后修复，不能只改最大日期冒充完整历史。

## 同步与本地计算

同步首先比较主键及 `updated_at`，只从公网下载新增/变化分片，同步源库删除的键。轻量清单仍需读取；这并不等于完全不扫描源表。二进制数据每页最多32行，避免大批缓冲占用内存。

历史或最新原始数据发生变化后，在未发布的本地副本上校验、解压、按日期重新计算。完整重算保证微盘历史分位及连续指数一致，不把不同算法结果混在一起。无原始变化时跳过重算。净利润断层只在首次或强制重建时导入旧的冻结基准，后续复用本地首次入选结果，不重复下载旧季度。ETF/LOF沿用自身的本地重算流程。

计算成功和SQLite校验通过后才切换快照。下载、分片校验或计算任何一步失败，都保留上一份本地结果。计算期间页面仍可查询旧快照。后端日志记录各模块、日期与计算进度。结果表结构保持原接口兼容，页面仍可进行轻量分页、排序、日期范围统计；不在请求中重跑选股及指标模型。

自动同步不会修复聚宽侧错误，也不会自行访问聚宽。更改采样步长、原始字段需求或采集范围时可能需要重新采集；仅更改本地公式则可重用已有原始数据，但必须提升计算版本并验证后重建缓存。不要直接修改分片或校验值；人工修改源数据须同步更新时间。

## 验证范围

离线测试覆盖七个模块计算、原始数据往返与分片完整性、微盘指数续算、重复运行、净利润首次入选冻结、损坏时保留旧快照、源数据库断开后的API读取，以及旧版公式对照。实际聚宽权限、历史数据覆盖、首次采集耗时与MySQL容量需要在用户环境验证。
