# 业绩选股统一调度

系统配置中的「业绩选股（高股息 / 奶牛股）」是三个标签页唯一的自动任务时间入口，默认交易日北京时间 23:00，管理员可修改。银行与非银行高股息共用一次数据采集、分别排名；结束后才启动一次奶牛股 3/5/10 年统一计算。旧奶牛股月末独立调度已移除，旧配置迁移到新入口，保留原开关及通知选择，时间改为本次要求的 23:00。已有结果、源库数据、旧调度状态文件不删除。

队列按交易日保存于 `LOG_DIR/market-data/earnings-schedule/schedule.sqlite3`。周末、节假日及未核验日历日期暂停自动运行；已入队的休市或未知日期标为跳过。休市日允许手动采集，但由此产生的失败不进入自动重试或补采。参见[统一采集日历](collection-calendar.md)。协调器的短期锁防止多个 API worker 重复发起同一队列；采集执行锁覆盖手动和自动入口。遇到手动任务占用时队列等待，不并行、不消耗该任务。单项启动或采集失败后记录失败，继续下一个任务；残留 active 状态但执行锁已释放时记录中断，不反复重跑。重启继续当日持久队列；未启动的历史时点跳过，不能用当天现成数据补跑历史时点。已校验的待发布载荷仍按日期与来源校验恢复；首次安装不会虚构昨日任务。

自动任务不在未经确认的固定总时长后强杀，避免中断合法长任务或写入事务。网络读取使用已有源超时配置，取消由采集器在边界协作处理。运行中的任务确实无法响应取消时，需要定位线程/进程后处理，不能宣称后续任务已执行。

高股息公开源执行当前 v10 规则，非银行最多 50、银行最多 20。每轮仍严格核验候选池、同日估值、分红及权益覆盖；核验失败保留原成功结果，队列继续处理奶牛股。任务失败与数据已提交但缓存尚未同步不同，`publication_pending` 表示双写尚未全部确认。

手动更新按点击时的最近到期计划限定日期；配置早于 16:00 时，当前公开数据最早在 16:00 才纳入当日范围。若可采上限早于今天，当前只可查询最新状态的公开接口不能重建高股息或奶牛股的历史快照；接口返回本次未采集的说明，已有结果继续可读。若已有日期不晚于上限的已校验待发布载荷，可以继续发布原数据，不请求当天快照。

## 数据库与本地的可恢复双写

高股息先将验证完成的双组 payload 和目标数据库身份写入本地持久待发布表，再在统一数据库同一个事务中替换两组。随后同步执行既有本地缓存同步，并核对日期、规则、元数据及全部两组行。只有核对完成才清除待发布表、标为 complete。数据库已提交而本地失败时状态为 publication_pending，不宣称跨库原子或双写完成；重试先重放原 payload，数据库相同结果保持原更新时间，不重新请求数据源。目标数据库改变时暂停恢复，不把旧任务写入新库。已有待发布数据重试不需要重新拉取上游行情。

数据库事务与本地缓存不是一个分布式事务：中途可以存在远端新、本地旧的窗口。待发布日志确保该窗口可观察、可恢复；两组在各自存储内部成对发布。崩溃后同一日任务不会被盲目重复启动，管理员可手动重试恢复，后续正常调度也会先恢复普通 pending；休市日手动失败隔离载荷不自动重放。恢复前日 payload 后，当日队列仍保持待采集，不把前日恢复当作当日新数据完成。
