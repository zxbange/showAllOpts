# 数据库连接超时下限

所有项目管理的 MySQL 有限连接、读取和写入超时下限均为 60 秒；更大值不降低。
高股息公开采集显式使用 connect/read/write = 60/60/60 秒。

路径盘点：
- 共享数据库引擎：API、缓存、创红比/奶牛股发布、CLI 等继承下限；缓存默认 600 秒读取保留，已有低于 60 秒的旧配置在建连接时提升至 60 秒。
- 数据源验证连接：驱动和预先建立的 socket 均使用 60 秒连接，读取/写入均 60 秒。
- ETF 独立配置：普通和自定义目标连接均 60/60/60 秒，预先建立 socket 同步更新。
- ETF 模块直接 CLI：显式连接超时 60 秒；原来未设置（无界）的驱动读写等待不缩短。
- 聚宽/独立采集脚本统一使用 `collectors/mysql_connector.py`：连接超时下限 60；显式有限读写超时也取至少 60。未配置/None/0 的读写等待保持驱动无界语义，已有 120、600 等值不降低。

HTTP 数据源请求超时、SQLite 锁等待、任务总时限及 MySQL 服务端变量不在本次调整范围。
系统配置中旧的缓存读取小值可以继续加载，但实际连接最低 60 秒，不需要重写含凭据配置。

高股息数据库关键操作输出固定阶段名、耗时、异常类别/数字错误码；不输出 SQL、参数、连接字符串或异常消息。
连接超时不等同任务总时限。等待期间取消只能在数据库调用返回后检查；客户端超时也不能证明 DDL/提交未在服务器完成，重试前仍以持久待发布数据及字段核验为准。
