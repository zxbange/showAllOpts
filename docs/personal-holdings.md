# 个人持仓（管理员）

入口 `/personal-holdings`。复用站点账号体系，只有管理员可见导航和访问页面；所有持仓、历史、配置、连接测试、启停API均要求管理员会话，写请求继续校验同源和CSRF。普通用户无法通过直接API读取个人持仓。

在页面填写MySQL主机、端口、数据库、只读用户名、密码和表名，测试后保存，再明确点击“开始监控”。保存和测试不自动启动监控。表名仅支持字母、数字和下划线且首字符非数字，使用数据库字段指定schema，不允许在表名中填写SQL或跨库路径。更换任意实质连接字段、密码或表名后停止监控、建立新基准；历史不删除。同配置重复保存复用，未修改时可以保留密码；改连接字段须重新输入密码。密码占位只是固定提示，不是实际密码。

源表字段：`strategy2`策略文本、`name`中文名文本、`code`代码文本、`amt`非负有限数量（最多6位小数，最大999999999999999999.999999）。代码保持前导零，不自动将数值代码补零。同一`(strategy2,code)`重复行合计股数；同键名称冲突、NULL、负数、数量超限、超过100000行或查询中途出错均拒绝整份候选快照，保留原数据。零数量视为无持仓。名称变化更新展示但不产生买卖记录；策略迁移按原策略清仓、新策略买入记录。

首次成功完整查询建立基准，不记买入。后续完整成功空表会记录全部清仓；失败/超时绝不等同空表。源发布方应在同一事务原子更新整张持仓表：若分开提交“清空”和“重新写入”，观察者无法区分已提交的临时空表和真实清仓，无法凭四个字段推断其发布意图。

按Asia/Shanghai交易日09:25（含）至15:10（不含）监控，包含午间。正常按15秒间隔查询；查询超时或超过间隔不重叠、不补发积压轮次。后台在关页后继续，窗口外/停止/退出释放连接，后续窗口重新连接。单个leader通过跨进程文件锁保持长连接，所有快照读取使用独立短事务，读取结束立即结束事务，空闲期间不保留MVCC快照。断连后丢弃连接，下轮重连，不隐式重放未完成查询。

交易日历来源为上交所官方年度休市安排，版本化保存在`backend/app/services/holdings_calendar.py`，当前覆盖2026-01-01至2026-12-31：[上交所2026年休市安排](https://www.sse.com.cn/disclosure/dealinstruc/closed/c/c_20251222_10802510.shtml)。排除周末，即使国家调休安排周末上班仍休市。当前项目历史行情日历不能确认未来日期，因此不复用为当天开市判定。官方下一年度公告发布后核对并更新该文件、测试和发布；临时休市公告同样需更新。未覆盖年份（包含2027年）明确显示日历不可用并停止源库轮询，不自动退化为周一至周五。运行时不请求第三方日历。

本地存储`${LOG_DIR}/personal-holdings/data/monitor.sqlite3`：独立配置密文、当前快照、按上海日期分组的历史变动，无TTL或自动清理。配置使用现有认证加密设施，密钥独立保存于`${LOG_DIR}/personal-holdings/short-validation-secrets/source.key`（沿用密钥组件目录名称），不会写源库。源连接目标校验、DNS固定解析与危险地址阻断复用已有实现；部署者若设置`VALIDATION_ALLOWED_TARGETS`则仍遵守该限制。部署/备份应保留整个personal-holdings目录，不能只保留SQLite而丢失密钥。

源快照、变动记录和版本在一个SQLite事务提交；读中修改配置或停止会通过持久化epoch拒绝旧工作提交。重启后接续上次成功快照，新交易窗口首次读取与上次成功快照比较。记录时间是实际观察到变化的时间，停机、盘外和两次轮询之间只能看到净变化，不代表真实成交时间或逐笔交易。页面按需分页展示每日全部记录，历史不随连接配置切换删除。

不提供公开行情接口、全量清空或自动下单。尚未连接真实持仓库，部署前需要用户自行在页面填写配置并确认启动。

“立即同步”使用已保存配置，通过后台队列执行一次完整读取；盘外、休市、日历未覆盖或持续监控关闭时均可用，不改变监控开关、时间表或自动轮询计划。未保存的编辑须先保存。请求幂等ID持久化，等待中的点击合并；与自动采样共用跨进程锁，不重叠执行。关页后继续，重启后接续待处理请求；停止/启动或修改配置会取消尚未提交的旧请求。失败保留快照和历史，需重新点击。盘外单次完成释放源连接；交易时段自动监控中的单次复用其连接。变动按实际观察的上海日期记入历史。

盘外页面仍从SQLite读取最后成功持仓，并展示最近读取时间。配置为认证加密密文；持仓快照、事件历史和幂等请求标识本身是SQLite明文，受目录0700/文件0600权限保护，不宣称持仓内容已加密。页面内存仅用于展示，后台持久化不依赖浏览器。

### 断连诊断

轮询失败先记录 `stage`（连接、读取或本地保存）、异常类型、驱动异常类型和数字 `mysql_errno`；无可用 MySQL 错误码时为 `None`。不记录原始异常文本、SQL、参数、连接地址或持仓内容。清理失败另外记录，不覆盖首个异常，也不阻止保存失败状态。

轮询失败同时保留共享诊断函数输出的有界异常链与安全调用位置。`source_connect` 包含 SQLAlchemy 首次连接初始化，不只指 TCP 建连或认证。PyMySQL 的 `InterfaceError(0)` 表示在已经关闭的 socket 上发送命令；例如初始化查询先出现 2013 断连，SQLAlchemy 随后的清理回滚可能再产生 0，旧日志只显示最后一层。应结合 `context_type`、后续 `mysql_errno`、`reason` 和 `frames` 找最初失败点，不能仅凭 0 判定密码、网络、连接池或服务端原因。该日志改进不改变连接、重试或超时策略。

读取仅四个字段，SQL 保留 `LIMIT 100001`，使用驱动缓冲结果，避免断连后 SSCursor 关闭时继续排空失效连接。正常轮询仍复用同一物理连接，每轮事务结束；失败关闭连接，下一轮重新建立。缓冲增加本次查询的临时内存占用，行数有上限但字节数取决于源字段长度。超限或读取失败仍拒绝整份快照，不产生清仓记录。此修复解决清理路径及诊断问题，不保证消除源网络断连。
