# 超短线历史研究数据

脚本：[超短线历史行情采集_研究版.py](../collectors/超短线历史行情采集_研究版.py)。独立运行，不加入每日批量任务，不修改已有业务表，不下单。首次运行采集最近已收盘交易日往前推三个自然年，并额外采集起始日前120个交易日作为指标预热；以后默认从最后完整采集日之后接续。日期按北京时间判断，16点前不采当天。

## 聚宽研究环境运行

需要 pandas、SQLAlchemy、MySQLdb或PyMySQL，以及聚宽研究 API 权限。默认使用PyMySQL，DB_DRIVER可设为auto、mysqldb或pymysql。GitHub脚本顶部 `DB_CONFIG` 仅有占位值，复制到私有环境后填写真实连接；运行时不读取其他项目文件，也不要求预先定义 Notebook 变量。

将整份脚本复制到聚宽 Notebook 单元格即可执行；也可以仅上传这一个脚本后运行：

```python
%run 超短线历史行情采集_研究版.py
```

需要指定日期时，直接修改脚本顶部的 `START_DATE`、`END_DATE`，例如：

```python
START_DATE = '2023-10-24'
END_DATE = '2026-10-23'
```

聚宽必须能够连接现有 MySQL。脚本不会在本地自动连接或写入真实数据库。MySQL账号需有新建表、查询和写入权限。

数据库连接方式参考项目的批量采集脚本：支持MySQLdb和PyMySQL驱动，单连接池，连接超时10秒，最多重试5次、间隔10秒；参数集中在本文件的 `DB_OPTIONS`。启动时先验证连接，最终失败或中断会释放引擎。新表显式指定InnoDB与utf8mb4，保证数据和断点同事务提交；此设置不会自动更改已存在表的存储引擎。脚本运行时不导入或读取批量采集脚本。

证书验证失败时停止自动重试。`DB_TLS_VERIFY=True` 为默认设置；私有CA可将PEM证书全文填入 `DB_TLS_CA_PEM`，仍无需读取外部文件，host需与服务端证书身份匹配。只有明确接受无法验证服务器身份的临时排查才设置 `DB_TLS_VERIFY=False`，不会由脚本自动切换；排查结束应恢复True并修复证书配置。

## 数据口径

如果MySQLdb 1.3.x报告 `SSL connection error`，可在Python 3.6研究内核中运行 `import sys; import subprocess; subprocess.check_call([sys.executable, '-m', 'pip', 'install', '--user', 'PyMySQL==1.0.2'])`，安装成功后将本文件 `DB_DRIVER` 改为 `'pymysql'` 再运行。显式选择驱动时不会回退到旧MySQLdb。PyMySQL连接使用系统CA与主机名验证的TLS；证书错误需使用匹配证书的数据库域名或由服务端修复证书，不会自动关闭加密。该版本的Python兼容性参考：https://pypi.org/project/PyMySQL/1.0.2/ 。

连接诊断会打印目标地址、端口、数据库名、用户名、驱动及版本、每次尝试耗时；失败时保留异常类型、底层DBAPI错误码及错误消息。密码及其URL编码形式会替换为 `***`，不会输出完整配置字典。最终异常保留脱敏后的错误详情。

| 表 | 用途 |
| --- | --- |
| `ultra_research_calendar` | 市场交易日历；观察第1、2、3日应使用市场日历，不能跳过个股停牌日 |
| `ultra_research_universe` | 每日历史沪深A股名单、上市日期、历史ST、当日总市值、eligible筛选标志 |
| `ultra_research_bar` | 沪深A股及三个市场指数的日线；日期与股票代码为联合主键 |
| `ultra_research_task` | 完成任务的断点，与相应数据在同一事务中提交 |

采集沪深主板（含原中小板）、创业板和科创板，不含北交所、B股和存托凭证。逐日按当时已上市名单获取，保留期间已退市股票的历史记录。`eligible=1` 要求当日明确非ST且 `valuation.market_cap >= 30`（单位亿元）。状态或市值缺失时 `eligible=0`，控制台报告缺失数量；这些缺失不等同于确认不合格，分析时应检查。股票名称是该历史查询返回的展示字段，不用于识别历史ST。

为支持均线预热和入选后的完整观察，行情表保留不合格日的上下文行情；它们不能作为入选日。30亿元筛选针对总市值，而非流通市值。保存完整上下文会比只保存当日合格股票占用更多空间，但避免因事后状态改变而丢掉退出样本。

`open/high/low/close`、成交量与成交额、涨跌停价均来自未复权查询；`adj_open/adj_high/adj_low/adj_close` 独立查询后复权OHLC。均线与收益使用后复权价格，涨跌停可成交判断使用原始价格；不要混用两种价格。`factor` 原样保存，不假设其方向或直接用它代替后复权价格。指数无ST、市值或涨跌停字段，行情表对应不适用字段为空。

均线不从平台重复下载，可在本地按日期用 `adj_close` 计算任意周期；停牌日沿用平台默认填充行情，保留 `paused` 标志。这意味着默认是按市场交易日计算均线，需要按实际成交日计算时须显式另定口径。

## 读取示例

在装有 pandas、SQLAlchemy、PyMySQL 的分析环境中（`ultra.make_engine(DB_CONFIG)` 返回引擎）：

```python
from sqlalchemy import text
engine = ultra.make_engine(DB_CONFIG)
with engine.connect() as conn:
    df = pd.read_sql_query(text('''
        SELECT b.*, u.eligible, u.market_cap, u.is_st, u.listed_date
        FROM ultra_research_bar b
        JOIN ultra_research_universe u
          ON b.trade_date=u.trade_date AND b.code=u.code
        WHERE b.asset_type='stock'
        ORDER BY b.code, b.trade_date
    '''), conn, parse_dates=['trade_date', 'listed_date'])
df['ma20'] = df.groupby('code')['adj_close'].transform(
    lambda s: s.rolling(20, min_periods=20).mean())
df['ma60'] = df.groupby('code')['adj_close'].transform(
    lambda s: s.rolling(60, min_periods=60).mean())
# 完成所有回看指标后，再选择信号候选；不要先过滤历史行情再计算均线。
candidates = df[(df.eligible == 1) & (df.trade_date >= '2023-10-24')]
```

查询全市场数据可能占用较多内存，建议按股票批次读取；每批须保留完整预热区间。

第1、2、3日必须从日历表定位，再关联该日行情。禁止只对 `eligible=1` 的行做 `shift(-1)`，否则得到的是下次合格日。缺失、退市、停牌和观察期未走满应分别标注，不能填0或静默剔除后只报告胜率。尾部尚无未来3日数据时，等待后续增量采集。

信号日收盘到后续收盘的表现是预测统计，并非可成交收益。若收盘确认信号、次日开盘买入，第1日收盘不能卖出该新买仓位（T+1）；还需考虑涨跌停不可成交、交易费用和滑点。日K不能确定同一天先触发止盈还是止损，也不能证明最高价处可成交。

本次仅采集原始研究数据，没有实现前述策略规则或产生真实胜率。若要验证“跑赢行业”等条件，还需另外采集历史行业归属与行业收益，现有三个指数只能用于市场环境/基准比较。

## 续采与修订

当前版本为 `2026-10-25.7`。公共进度读写、旧库接续判断和行情字段校验已合并，保持单文件、原有四张表和已有断点格式兼容。快照和行情分别保存续采进度：`snapshot-day-v1:范围标识:日期` 只表示ST、市值快照已写入，`complete-day-v1:范围标识:日期` 表示该段股票和指数行情全部提交。两种标记均保存在原任务表，不新增表。行情失败不会推进行情完成日期，已经写完的快照也不会重新遍历。旧库缺少快照专用标记时，只检查最新快照日的行数和规则版本来登记进度。

因此，快照写完但行情尚未开始时，下次整段跳过快照并采集缺少的历史行情；行情部分写入时保留已提交批次，仅补其自身未完成区间，不会把快照最大日期当作行情续采起点。快照800多个交易日已经入库时，不再逐日显示检查进度。

启动时显示脚本版本及Python、pandas版本。`2026-10-25.4` 修复聚宽旧版pandas将日期索引自动转为Timestamp后，与datetime.date主键做集合比较而误报缺行的问题：内部行情索引统一使用ISO日期文本和规范股票代码，比较前显式规范化，写入数据库时再转回Date。返回日期及记录数都正确却仍报缺行时，不应直接据此判断账号权限不足。该修复同时适用于原始行情、复权行情、补采合并和代码bytes/空格的兼容处理，真实缺行和重复记录仍会检查。

`2026-10-25.5` 默认采用按最后完整采集日追加的方式，停止每次重查三年历史：

- 首次空库运行仍采集三年及120个交易日预热数据。
- 此后从任务表中读取同一股票范围、筛选规则和指数范围的最后完整日期，仅处理该日之后至最新已收盘交易日的数据，不重复预热。没有新交易日则直接结束，不扫描历史股票池或行情。
- 股票和指数当月全部提交成功后，在现有 `ultra_research_task` 中保存 `complete-day-v1:范围标识:日期` 记录；日期位于任务键中，行数仍表示该段预期记录数，不新增数据库表。跨月失败不会推进未完成月的日期标记，下次从上一完整日期之后恢复，只补未完成区间中的缺口。
- 首次升级旧数据库且尚无完整日期标记时，只读取行情最大日期并核对该日的股票和指数记录。最新日完整则直接接续；最新日不完整或范围已改变，则只检查该最新月份，保留其中已有完整记录并补齐未完成部分。旧库升级不会自动审计更早月份。
- 默认追加模式不再自动修复已完成边界之前的删行、缺字段或数据源历史修订。确有历史修复需求时，显式指定 `start_date`、`end_date` 并设置 `force=True`；这会重采指定研究区间及其预热数据。较早区间重采不会把已登记的最后完整日期向前回退。

在本次待采集区间内，日历仍只插入缺失日期，股票池仅请求缺行或关键字段不全的股票，行情仍按实际主键和关键字段补缺口。非连续缺口分开查询；已完整记录不重复下载、不修改采集时间。源ST或市值无法获取时按不合格保留并报告，不虚构状态；该日期完成后默认不再回扫这些源字段。

行情每批最多50只股票，API异常最多重试3次。数据与断点在同一事务中提交；事务失败后下次继续检查实际记录。首次查询约三年沪深A股历史及预热，须留意聚宽配额与数据库空间。

当行情接口批量返回缺行时，先在内存保留已返回记录，仅对缺失的日期/股票缩小请求；全部为空时逐步拆分股票或日期。最小到单股单日仍为空时，再用 `end_date + count=1` 验证，并严格检查返回日期是否就是目标日，不能拿前一个交易日替代。未复权和后复权查询各自检查；两者均完整才提交当前批数据与断点。若仍缺失，报错包含目标股票/日期、复权方式、请求字段及实际返回日期范围，便于检查接口权限、配额或源数据。该机制不把缺失行情当作停牌、不补零，也不会把部分结果标成已完成。

采集过程中使用进度条，显示当前阶段、日期或月份、进度比例、补采行数、跳过行数及总耗时。终端使用回车刷新同一行；聚宽Notebook在固定显示区域更新。筛选阶段按交易日计算进度，行情阶段按月份计算，并显示当前补采批次；百分比不是剩余时间预测。连接诊断、最终汇总与异常信息单独显示；中断后进度条标记失败，已提交数据保留。`PROGRESS_ENABLED=False` 可关闭进度显示。

平台更正历史数据后可用 `force=True` 重采指定区间，不要删除业务表或复用旧脚本的历史清理函数。同一数据库不要并发运行多份本脚本。`collected_at` 和断点时间为UTC，行情日期为中国市场日期。

接口字段参考：[聚宽官方API源码](https://github.com/JoinQuant/jqdatasdk/blob/master/jqdatasdk/api.py)。实际使用研究环境 `jqdata` 接口；离线测试不能代替聚宽账户权限、配额和远程MySQL连接验证。

股票范围仍为沪深主板、创业板和科创板，规则版本为 `shsz_a_nonst_cap30_v2`。若旧库仅含主板，追加模式不会自动补齐更早三年的新增板块，需显式指定历史范围并使用 `force=True` 重采。无需删除已有表或断点。
