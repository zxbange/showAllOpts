# 市场热度与抱团拥挤度：AShareHub 原始日行情

## 替换范围

配置后，两项指标共用 AShareHub `GET https://asharehub.com/v2/market/technical-factors-pro?trade_date=YYYYMMDD` 的单交易日响应，替换原 TDX 日行情包中的以下输入：

- `close`：未复权收盘价，元。
- `vol`：手，乘以100换为股。
- `amount`：千元，乘以1000换为元。

每个交易日只请求一次全市场数据并保存经过校验的精简行情缓存。市场热度和抱团拥挤度共享同一输入；20日窗口复用缓存。请求只发送到固定 HTTPS 域名，密钥只置于 `X-API-Key` 请求头，不进入 URL。重定向不跟随，鉴权失败和限流立即停止本轮，不换接口绕行。

**没有替换的口径和安全核验：**

1. 股票池仍来自东方财富逐日报告，并用目标日真实成交、明确全天停牌记录和交易所逐板块数量交叉核验。不会把接口返回行数当股票池，也不会因缺行情删除个股。北交所数据不会扩大原沪深股票/CDR范围。
2. 热度仍使用原20个市场交易日、全精度新浪前复权因子和合格证券分母；保留停牌向前填充、新股不足20日排除和严格比较规则。**不使用接口提供的 `ma_qfq_20`、`close_qfq` 或 `adj_factor` 代替原计算。**
3. 拥挤度仍以完整日期股票池 N 为基数，取成交额前 floor(N×5%) 只证券；已确认停牌证券保留在 N 中。
4. 交易日历、复权因子、历史股票池、停牌、交易所分类数据及聚宽历史恢复脚本不变。沪深300月度权重不能代替逐日生效成分，本次未接入。
5. 只有全部独立核验通过才发布；空响应、混合日期、重复代码、无效数值或未解释的缺失均阻止相应结果。单日请求避免长区间接口截断，但并不把单日返回视为自动完整。

AShareHub成交额存在源端舍入。2026-11-06审计样本中，5218只交易证券的原始收盘价与独立行情一致；单股成交额最大差5元。完整股票池为5224只（含6只已证实停牌），前261只相同，拥挤度均显示43.47%，但数据库10位小数比值不完全一致。这是数据源精度差异，不宣称逐位等价。

## 启用与回退

代码发布不会保存或自动配置之前用于测试的凭据。服务器管理员在受保护的服务环境变量中配置 `ASHAREHUB_API_KEY`，然后按既有方式重启 API。应用既有服务端配置文件也支持此字段，但不要把真实密钥提交到仓库、聊天或日志。示例文件仅保留空值。

- 未设置或为空：继续原 TDX 输入，旧配置正常工作。
- 非空：后续未完成采集选择 AShareHub；没有运行时失败后偷偷切回 TDX 的逻辑。
- 删除此配置并重启：后续未完成采集重新选择 TDX。
- `/api/v1/market-collection/status` 的 `raw_price_source` 返回当前配置选择的 `asharehub_technical_factors_pro` 或 `tdx_daily_archive`。它不是某条历史结果实际来源或实时可用性的证明，不返回密钥。

精简行情缓存在 `LOG_DIR/market-data/market-collection/source-cache/asharehub-daily-v1`，不包含密钥、响应头或衍生技术因子。日期核验缓存与 TDX 使用不同目录；未完成任务的旧源快照需要重建，但已发布结果与原审计记录保留，不自动回写覆盖历史。

接口响应上限64MiB、精简缓存单文件上限8MiB；格式校验之外仍依赖原全市场完整性审计。首次无缓存的20日窗口可能需要20次请求，请根据账户实际额度安排历史补采。账户额度、生产密钥配置和实时服务可用性须另行确认。
