# 模块诊断日志

日志写入现有 `app.log` 与 `error.log`，按日轮转。所有日志都有时间、级别、进程号和模块名；ERROR 同时进入 `error.log`。无需开启 DEBUG 即可看到采集与错误边界。

## 排查入口

- API 操作：响应头 `X-Request-ID` 对应日志的 `request`。日志记录 HTTP 方法、路由模板、状态和耗时，不记录查询参数、正文或具体路径参数。HTTP 拒绝、数据库异常和未处理异常分别有失败位置。未处理异常由 ASGI 外层生成响应时，响应可能没有此头，应按时间和路由查找。
- ETF：`ETF collection start/stage/finish` 记录独立 run、触发方式、日期、阶段、处理数量、结果和耗时；`ETF source plan/finish` 汇总目标、已耗尽重试的观察项、份额/行情条数及失败数。单次采集最多详细打印前 5 个观察项失败，其余计入 `suppressed_failures`。
- 创红比：交易日历、待补窗口和点数、失败窗口、最终 success/partial/cancelled/market_closed/failed、处理条数与耗时。
- 现金牛：股票池数量、年度筛选阶段、3/5/10 年各自的匹配/排除/资料不足数量、是否发布与最终结果。不打印逐只股票数据。
- 两融担保比例：目录数量、请求日期、报告失败原因/错误码、最终处理数量和结果。不打印原始报告 URL。
- 社交监控：平台暂停、限流等待、抓取失败与失败位置；Telegram/飞书通知输出渠道、HTTP 状态、有限范围的数字业务码以及失败分段位置，不输出通知正文、接收人或 Webhook。
- 自选持仓数据库连接：校验地址、创建驱动、连接 socket、认证等阶段与安全驱动错误码。持仓数据、用户名、库名和连接字符串不进入新增诊断日志。
- 缓存、商品和持仓后台：保留原有业务阶段/数量日志，补充后台异常的安全类型、原因链与位置。
- 工作进程：启动和关闭调用记录模块及耗时；`shutdown checked` 表示 stop 调用返回，不承诺使用限时 join 的线程已退出。

## 错误格式与保密

共享诊断函数只输出已知异常类型、HTTP 状态、MySQL/SQLite/OS 数字错误码、有限原因链和 `文件名:行号:函数名`。不格式化原始异常消息、SQL、参数、响应正文、请求头、变量值或源码行。异常链与位置数量均有上限。

格式化器对第三方日志额外屏蔽完整 URL、Authorization/Cookie、常见令牌字段及已知配置秘密。原始 traceback 改为 `Traceback diagnostics`，保留安全位置而不输出异常原文；原始 stack_info 不输出。独立诊断脚本仍可导入原有脱敏辅助常量。

## 降噪与范围

成功的缓存、ETF 和市场采集状态轮询继续不写 access 日志；失败/重定向仍保留。普通快速 GET 不增加第二条业务日志；修改操作、失败请求和超过 1 秒的非轮询请求有摘要。健康检查不增加常规业务日志。

此改动覆盖公共 API 边界和主要后台任务，不等于为每个解析分支或内部函数逐项打印。聚宽独立采集器仍使用已有的策略起止、条数、耗时和汇总机制；浏览器端尚未增加独立遥测上传。市场情绪日采集内部阶段由其自身模块维护。本次验证使用离线测试，不验证真实外部服务、生产磁盘日志轮转或线上部署状态。
