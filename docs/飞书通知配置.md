# 飞书通知配置

博主动态、雪球组合调仓和平台暂停提醒支持 Telegram、飞书两个渠道。进入“博主动态监控 → 通知设置”，可单独开启或关闭任意渠道，也可同时开启。监控总开关控制数据采集；通知渠道开关只控制消息发送。

飞书采用**群自定义机器人**，不需要创建企业应用、填写 App ID / App Secret 或配置公网回调。配置入口以飞书[自定义机器人官方说明](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot?lang=zh-CN)为准；若组织限制添加机器人，需要群管理员协助。

## 1. 在飞书创建机器人

1. 打开希望接收消息的飞书群，进入群设置中的“群机器人”。
2. 添加“自定义机器人”，填写名称，例如“研究动态通知”。
3. 复制机器人的 Webhook 地址，其格式为 `https://open.feishu.cn/open-apis/bot/v2/hook/机器人标识`。
4. 打开机器人的安全设置，启用“签名校验”，复制签名密钥并保存设置。

签名密钥是机器人安全设置中的密钥，不是企业应用的 App Secret。项目会自动生成请求时间戳和签名，无需手动计算。

## 2. 在本项目保存配置

1. 打开“博主动态监控 → 通知设置”。
2. 在飞书配置区分别填写 Webhook 和签名密钥并保存。
3. 开启“飞书通知”。Telegram 可按需要保留开启或关闭；只用飞书时关闭Telegram即可，无需填写Telegram凭据。
4. 点击飞书测试按钮，确认目标群收到测试消息。

已保存的凭据只显示配置状态/掩码，不会回显原文。修改时填写新值；留空不会自动删除之前保存的凭据。测试按钮要求对应渠道已配置并开启，可在监控总开关关闭时主动测试。

首次使用博主监控，还需要添加博主或雪球组合、完成平台登录并开启监控总开关。仅保存通知配置不会自动开始抓取。

## 3. 两个渠道如何配合

| Telegram | 飞书 | 新消息行为 |
| --- | --- | --- |
| 开启 | 关闭 | 只发 Telegram |
| 关闭 | 开启 | 只发飞书 |
| 开启 | 开启 | 分别向两个渠道发送 |
| 关闭 | 关闭 | 继续采集并在网页展示，不发送通知 |

每条新消息按入库时启用的渠道建立独立发送记录。一个渠道失败不影响另一个渠道发送；下轮只重试尚未成功的部分，不重发本地已确认成功的渠道。旧 Telegram 待发消息会保留原分段进度，升级不会重放已经发送的历史消息。若远端收到消息后连接中断或本地尚未保存进度，重试仍可能重复该分段。

新开启一个渠道只影响之后的新消息，不会补发过去的动态。关闭渠道会跳过该渠道尚未发送的部分；重新开启不会恢复这些已跳过的部分。两个渠道都关闭期间产生的消息只保留在网页，不会在重新开启后集中补发。

自动动态通知继续遵守已有夜间休息和组合监控时段；测试通知和平台暂停提醒沿用独立的人工验证/提醒行为。渠道开关不改变平台采集频率。

## 常见问题

- **测试成功但没有新通知**：检查飞书渠道开关、监控总开关及博主/组合开关，确认消息是在启用渠道后新采集的；已有历史不会补发。
- **签名校验失败**：确认保存的是该机器人的签名密钥。服务器系统时间须正确，官方要求请求时间戳距当前时间不超过一小时；换过密钥后应同步更新项目配置。
- **关键词/IP 校验失败**：若机器人额外启用了关键词或IP限制，所有条件都要满足。普通博主正文不保证包含指定关键词，建议采用签名校验；使用IP限制时须填写部署服务器出口IP。
- **HTTP 成功但提示发送失败**：飞书响应中的业务错误码也要成功，项目不会仅凭HTTP 200判定已送达。检查机器人是否删除、群设置是否改变以及安全校验是否一致。
- **长消息或消息较多**：程序会分段发送并控制频率。飞书官方限制单次请求体20KB、单机器人每分钟100次及每秒5次；失败的分段保留独立进度，下轮重试。
- **想发到另一个群**：在新群创建自定义机器人，替换本项目的 Webhook 和对应签名密钥。自定义机器人只向创建它的群发送，不支持直接私信个人。

## 配置保存与迁移

配置位于 `${LOG_DIR}/social/monitor.sqlite3`，Webhook、签名密钥及已有 Telegram 凭据均加密保存。迁移服务器时须一并保留同目录 `secrets.key`；不要把真实 Webhook、密钥或本地数据库提交到 GitHub。飞书开关不删除已保存的配置，关闭后可直接重新开启。

升级代码后安装项目依赖、构建前端并重启后端，新增的本地通知记录结构会自动初始化。原 Telegram 配置保持可用；首次升级默认保留 Telegram 渠道、关闭飞书渠道。配置和测试通过网页完成，无需在聚宽研究环境运行任何脚本。
