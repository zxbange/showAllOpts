# 微盘新高新低

## 运行与入库

独立采集文件是 `collectors/微盘新高新低数量统计_数据库版.py`，可在聚宽研究环境直接粘贴运行，或执行 `%run -i 微盘新高新低数量统计_数据库版.py`。在顶部 `DB_CONFIG` 填写私有数据库配置；参数集中在 `STRATEGY_CONFIG['微盘新高新低']`。

也可以运行新版 `策略批量采集_数据库版.py`，该策略已作为第六项串行执行，统一使用连接和参数配置。两个入口使用相同的采集逻辑，均只新增，不覆盖已有记录，不生成日志文件。单独运行失败会停止；批量模式记录失败结果后继续其他策略。

默认配置：

```python
'微盘新高新低': {
    'start_date': None,
    'end_date': None,
    'micro_num': 400,
    'initial_days': 180,
    'batch_size': 500,
    'price_batch_size': 100,
}
```

- 首次从运行截止日往前 180 个自然日开始；不是 180 个交易日。可设置 `start_date='2021-01-01'` 等固定日期。
- `end_date=None` 每次取北京时间当天；16:00 前不写入当天数据。
- 已有数据时，只查询当前序列最新日期，从其后开始采集，长时间未运行也不会因为初始窗口滚动而漏掉中间日期。修改 `start_date` 不会自动重算已有历史或补更早缺口。
- 每个交易日保存一行、一个事务；只计实际新增日数。任何接口不完整或计算失败立即停止，不越过失败日期推进进度。已提交日期保留，重跑继续。
- 保留已入库历史，不自动清理。唯一键为 `(series_id, trade_date)`；已有快照即使源后续修订也不覆盖。并发冲突会回滚报错，请勿同时运行两个入口。
- 默认序列为 `micro400_hl_v1`。修改 `micro_num` 会产生新序列，网页当前固定显示默认 400 只序列，不会混合不同样本口径。

## 统计口径

每天获取当日股票列表，过滤代码以 `68`、`4`、`8` 开头的股票、ST 和上市不超过 240 个自然日的股票。按当日总市值从小到大取 400 只；市值相同时按代码升序，保证结果稳定。使用历史日期查询上市信息、ST 状态和市值，成分股每天可以变化。

一次获取每只股票截至当天的 31 个交易日收盘价，计算 5、10、20、30 日四个窗口：当日收盘价与此前 N 日比较，`>=` 过去最高价计为新高，`<=` 过去最低价计为新低。当前日不放入比较窗口。沿用默认前复权、保留停牌填充值的口径；价格持平可以同时计入新高和新低，因此两者不能相加当作互斥人数。

股票列表、ST、市值、历史收盘价必须完整，缺失或重复时停止该日写入，不静默跳过股票，不补零。按批获取估值和行情，行情每批 100 只，四个窗口共用同一份数据，减少逐股票逐周期调用。

相对原分析脚本的调整：

- 不再先算股票收盘价均值作为“等权指数”；该均值不是累计收益指数，也不是新高新低统计所需的数据。
- 直接为首个统计日读取此前 30 个交易日行情，不再白白丢弃首次采集区间的前 30 个交易日。
- 保留新高/新低含持平的核心规则，但不再忽略数据异常后以全部样本为分母计算，避免低估统计值。
- 页面“新高占优天数比例”对应原程序所谓胜率：最近 15 个已采集交易日中，新高数量大于新低数量的天数比例；不是交易盈利概率。样本不足 15 日时明确显示实际天数。
- 加权强度 = 四个周期的“新高比例－新低比例”分别乘 48%、24%、16%、12%；比例按 0–100%，差值按百分点表示。权重沿用原代码的实际计算结果。
- 情绪加权值 = 各周期比例差乘 `exp(-N/20)` 后求和，不归一化。6 / 12 日变化采用强度点数差，避免对可能为零或负数的强度计算百分比涨幅；不足历史时返回空值，不补零。

## 数据表与 API

采集脚本负责创建 `microcap_breadth`（InnoDB）。表中保存日期、序列、样本数量、四个周期的新高/新低数量、成分股 JSON 和更新时间。比例和衍生统计由只读网页后端根据数量计算，避免重复存储及小数截断。

接口：`GET /api/v1/microcap-breadth/history?days=180`。支持 `days=30/90/180/300`，表示最近相应数量的已采集交易日；可传 `end_date=YYYY-MM-DD`，不允许未来日期。

后端使用复合主键筛选默认序列并按日期倒序限量查询，一次 SELECT 最多 314 行，不读取成分股文本，不写入数据库。额外读取 14 行使近 15 日统计和 6/12 日变化不受页面范围切换影响。历史由实际记录构成，手工删除造成的缺口不会自动补齐。

如果网页使用单独的只读数据库账号，需要让管理员授予它对新表的 SELECT 权限。没有数据时显示空状态；表尚未创建、配置不通或权限不足时会显示数据库读取错误。

## 网页与部署

总览新增“微盘新高新低”模块和独立图形入口，路径 `/microcap-breadth`，支持：

- 四个周期的最新新高/新低数量、比例与比例差；
- 点击周期卡片切换数量、比例和差值历史图；
- 加权市场强度、情绪加权趋势和强度点数变化；
- 新高占优持续性、最后 10 条明细，以及 30/90/180/300 日范围；
- 手机端布局、图表缩放、加载/空数据/失败重试。

先在聚宽运行独立脚本或批量采集，写入网页连接的同一数据库。Linux 更新代码后，按照 README 的增量发布步骤重建前端、重启 `showallopts-api` 并发布静态文件；Windows 关闭旧启动进程后重新运行 `start.cmd`。后端不重启会缺少新接口。此次无新增 Python/npm 依赖。

离线测试使用模拟聚宽接口和 SQLite，不连接实际 MySQL；真实聚宽行情权限、历史覆盖及数据库写入需在研究环境验证。
