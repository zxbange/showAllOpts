# 市场指标每日采集实现与验收边界

## 状态

代码实现调度、源库逐指标补缺、东方财富目标日报表、公开日行情适配及严格证据校验。既有调度和诊断版本与本次未发布的来源切换分别记录；本次恢复不代表提交、部署或生产采集成功。**真实补缺链路仍未完成端到端验收，不能宣称两项指标已经可以无人值守地全部成功。**

主要会明确阻断的条件：

1. 默认按完整东方财富目标日报表提出候选池，不再下载上交所/深交所完整证券目录。每个候选证券必须有目标日真实成交，或明确全天停牌；池外出现真实成交或已确认停牌身份也会阻断。最后逐板块核对两交易所四类官方数量，不能仅凭总数相同放行。通过后标注“经多源核对的逐日重建”，不声称取得聚宽历史清单。没有上市区间的报表不伪造上市/退市日期。无任意旧年覆盖承诺；源不覆盖、分类不明或身份冲突的日期保留缺口。
2. 热度需要截至目标日的完整20个市场交易日全部通过相同成员、日期、身份和分类数量审计。连续20日均存在才直接证明足够历史；缺少前缀不能自行视为IPO。只有显式IPO日期等于首个present交易日、此前每天已审计且absent、此后连续present，才允许不足20日排除。换码、旧IPO、重新进入、中间缺口、未知上市时间均保留缺口。当日拥挤度核验完整时仍独立发布。
3. 新浪 CDR 复权因子可能为空。空因子不是恒等因子。仅此情况下允许一个受限证据路径：腾讯显式 `qfqday` 的20个交易日收盘必须逐项等于TDX原始收盘，目标成交量必须同单位一致，且收盘与MA20的差距必须大于各显示数值一个最小单位传播出的最坏误差。缺日、任何调整、成交量单位不明或误差边界均继续待核验。双源窗口一致不证明与聚宽所有场景一致，不把腾讯有除权窗口当作聚宽等同算法。普通股票仍逐只使用新浪完整因子。公开股本变迁包没有可靠覆盖截至日，因此不启用普遍无事件快路径。

## 两个指标共用的数据链路

- 目标日报表：`https://datacenter-web.eastmoney.com/api/data/v1/get`，`reportName=RPT_VALUEANALYSIS_DET`，固定列 `SECURITY_CODE,SECUCODE,SECURITY_NAME_ABBR,TRADE_MARKET,TRADE_DATE,CLOSE_PRICE,CHANGE_RATE`，`filter=(TRADE_DATE='YYYY-MM-DD')`，按证券代码升序、每页5000条。全部分页的总数、日期、唯一代码、市场身份和字段均核验后才选择`.SH/.SZ`全部记录；北交所不进入目标范围。保留689开头CDR与302证券，不靠当前行情池或固定股票名单补齐。报表名称可能是供应商当前回填，不能证明历史ST身份。
- 板块只对已经由报表选择的身份分类：沪60为主板A、688/689为科创板，深00为主板A、30（包括302）为创业板。风险警示市场字段与行业名称不能当作交易板块；未知代码类别保留在候选池并阻断，而不是静默过滤。四类官方数量是独立完整性守门，不是身份本身的证明。
- 报表使用共享约每秒一次的请求节流与取消检查。单响应原始及解码后25MiB、单请求120秒协作预算、完整报表600秒预算，最多20页；HTTPX阶段超时约连接30秒/读取60秒。不是硬墙钟截止。403/429、重定向、错页/错日期/API错误或数量变化立即拒绝，不回退大名单、另一个主机或clist。
- 完整报表缓存按来源/版本/日期隔离：32日期、128MiB总量、单封装32MiB；每日完整审计缓存另限32日期/256MiB、单文件32MiB。原子写入、SHA256、目录描述符与`O_NOFOLLOW`保护；加载重验所有身份与数量证据。坏缓存本轮拒绝，不同轮才受控重取；不缓存半份报告，不修改已发布数据库指标。重叠20日窗口复用已核验缓存，窗口逐股仅携带日期、presence与证据摘要，不复制20份全市场报告。
- 单证券IPO候选：`https://push2.eastmoney.com/api/qt/stock/get`，`secid`绑定市场及代码，请求`f57,f58,f189,f13`；要求响应代码及明确0/1市场一致，日期有效、非零且不晚于目标日。`f189`字段映射参考AKShare，但本次任务没有取得该接口成功HTTP响应，候选契约仍未经真实调用验收；缺字段直接保留缺口。仅连续短后缀需要查询，全20日存在无需查询；不调用全量clist回退。
- IPO适配器每实例最多32次请求、180秒累计活跃处理时间、单请求30秒协作预算，阶段超时10秒/读20秒，原始与解码响应64KiB。共享网络故障终止该次provider，字段失败只缓存为对应证券/日期的待确认状态。成功元数据缓存128条/8MiB，按自身旧条目有界淘汰，损坏本轮拒绝并安全移除，下次受控恢复；不因满缓存永久锁死。完整有限原始响应与SHA256随quote保存，纯计算与聚合均重新验证，缓存淘汰不会删除既有IPO证明或已发布结果。
- 历史官方数量守门：SSE `commonQuery.do` 的 `COMMON_SSE_SJ_GPSJ_CJGK_MRGK_C`，目标日 `SEARCH_DATE`，01主板A/03科创板；SZSE `ShowReport/data` 的 `CATALOGID=1803_sczm`、`txtQueryDate`、`TABKEY=tab1`，主板A/创业板A。记录官方响应及摘要；默认报表成员使用上述明确证券命名空间派生分类，原交易所区间注入路径仍保留原规则。显式0接受，类别缺失不补0；尚未核验的旧中小板分列结构会透明阻断。
- 原始收盘、量、成交额：`https://www.tdx.com.cn/products/data/data/g4day/{YYYYMMDD}.zip`。匹配日期 URL 和 `.cod/.md1` 文件名后解析，不把二进制首四字节当成日期。缓存经校验的原始包及摘要，压缩包不解压到任意路径。
- 前复权因子：`https://finance.sina.com.cn/realstock/company/{symbol}/qfq.js`。只解析 JSON 数据赋值，不执行返回的脚本。空、重复、非正值、不完整计数均拒绝。与原始收盘保持同一因子基准，按20个市场交易日计算。
- 空因子受限证据：`https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param={symbol},day,{start},{end},40,qfq`。只接受显式`qfqday`，不接受`day`替代；保留20日逐值证据和误差界限。此接口不作为网络失败/403/429后的切换目的地。
- 停牌证据：`https://datacenter-web.eastmoney.com/api/data/v1/get`，报表 `RPT_CUSTOM_SUSPEND_DATA_INTERFACE`。接口日期过滤会返回以后事件，必须按实际起止时间求交集；盘中停牌不能作为全天停牌。只有明确覆盖全天的事件允许缺日填充，缺失记录不是停牌证据。
- 交易日历：复用现有新浪编码交易日历 `https://finance.sina.com.cn/realstock/company/klc_td_sh.txt`。不用周一至周五代替交易日，不硬编码年份。

拥挤度保留原聚宽规则：N 包括已确认当日停牌的零金额证券，K=`max(floor(N*0.05),1)`，前K成交额除以总成交额。已核验的带日期快照允许拥挤度先入库，热度仍单独等待完整因子和状态。

热度排除当日停牌及上市不足20个市场交易日的证券；历史明确停牌日填前一已复权收盘价；站上比较沿用相对容差1e-12。不足数据不缩小分母、不补零、不换成未复权MA20。

## 调度与补缺

- 每个交易日北京时间18:30启动，30秒轮询；这是开始时间，不是保证完成时间。源HTTP请求统一约每秒一次，流式下载也受节流、取消和403/429停止约束。
- “立即采集”和自动任务共用同一路径。18:30之前手动触发以此前最近已收市交易日为目标；之后包含当天，仍检查来源日期和就绪情况。
- 每轮独立读取现有MySQL两张结果表，拥挤度只读top_pct=0.05系列；每项只从各自最后已有日期的下一个交易日起，补到目标交易日。例如周五执行而最后数据为周一，则计算周二至周五；周一之前是否缺失不检查、不补算。任意旧洞及没有本次计划标记的旧失败记录不重开；进入本次范围的逐指标日期先登记持久缺口，之后即使更晚日期成功使MAX前移，已登记而未完成的缺口仍保留。已存在结果保留；单项空表仅初始化最近已结束交易日，不按另一项较早日期扩展。
- 每项首轮按日期从早到晚完整处理，遇到局部失败先跳过，后续日期和独立指标仍可成功；完整首轮结束后，仅对未完成项追加最多三轮重试。每只股票每轮最多请求一次，验证样本和正文共用预算，成功证券、已入库指标和保存快照不重复采集或发布。拥挤度写入失败不妨碍热度独立入库，同轮不在热度事务重复写失败的拥挤度；明确的表权限/缺表等公共写入故障不会对每个日期反复访问同一表。两项起点不同的日子只计算范围内的项，另一项明确显示“不在本次补缺范围”，不冒充已入库。
- 同一持久目录的文件锁防止多进程重复跑；逐日、逐股状态和写入意图持久化，重启后续跑。自动预算按最近已到北京时间18:30的日期持久化，每个目标日期最多四轮；30秒轮询、退避和进程重启不能重置该预算；手动执行的轮数同时计入当前已到期自动计划，避免手动失败后后台立即再跑四轮。三轮追加重试仍失败的项保留，下一个18:30计划或新的手动请求才获得新预算。缺少历史/方法证明等确定性阻断不会在同次执行中空转，后续有界重查仍共享预算。日历、主表、共享日包及连接建立失败按公共依赖终止当前执行；公共依赖按30分钟退避且每自动计划最多四次，不扩散成逐股请求。新提供者不能复用来源或证据版本不兼容的旧快照，取得替代快照后归档旧证据，只重建未发布的输入，已入库结果保留。403/429立即停止整个执行并保留已成功结果，暂停到次日18:30；手动请求也不能清除尚未到期的来源冷却。来源库查询失败不当成空表。
- 热度写入同时维护result_sync日志；两个模块完成后定向刷新缓存。源库写入成功但缓存失败会保留待刷新标记。
- 页面展示两项各自最新源库日期与缺口状态。数据来源与方法绑定到实际入库行哈希，不把旧新浪或聚宽结果重新标成公开行情。

## 排错日志

日采集日志包含阶段、目标交易日、运行编号摘要、数据源、证券/行情覆盖数量、两项缺口数、有效/停牌/新股/待确认计数、写入或保留状态和安全错误码。逐股失败与原始证据保留在采集状态中，不把每只股票的成功请求刷入服务日志。日志不输出数据库连接、密码、令牌、完整请求URL或来源异常原文。

证券主表失败保留固定枚举的 `source_id`、`source_stage`、`source_code` 及 HTTP 状态。网络错误额外保留传输类型，例如连接超时或读超时；只有异常链中存在可验证的标准 SSL/DNS 异常类型时才标记对应原因，不根据异常文字猜测。`network_error` 或 HTTP 200 本身都不能证明响应完整，证书校验、403/429 停止及发布前的完整性门禁保持不变。

结构有效但证券覆盖不足的日包会移到按摘要命名的审计缓存，下一轮有限重试重新下载，避免半份日包永久占用缓存。403/429仍直接停止，不因缓存失效另换接口或立即重试。
