# 创红比与科创红利比

入口为“市场情绪 → 创红比”，地址 `/growth-dividend`。该模块从外部接口采集指数日线，写入 MySQL 后发布本地 SQLite；页面始终读取本地历史，数据库同步仅用于恢复外部采集结果。公开源路线不需要聚宽账号或行情接口密钥。

“市场情绪”的标签顺序为：国家队动态 → 创红比 → 抱团拥挤度 → 市场热度 → 两融担保比例。

## 指标口径与图表

| 曲线 | 代码或公式 | 线型 | 坐标轴 |
| --- | --- | --- | --- |
| 创业板指 | 399006，原始收盘点位 | 实线 | 左轴，指数点位 |
| 中证红利 | 000922，原始收盘点位 | 实线 | 左轴，指数点位 |
| 科创50 | 000688，原始收盘点位 | 实线 | 左轴，指数点位 |
| 创红比 | 同一交易日创业板指 ÷ 中证红利 | 虚线 | 右轴，比值 |
| 科创红利比 | 同一交易日科创50 ÷ 中证红利 | 虚线 | 右轴，比值 |

五条曲线使用不同颜色。指数采用价格指数点位，不使用ETF价格、全收益指数、市盈率或归一化净值。两个比值均为无量纲数，不乘100，也不显示为百分比。任一分子、分母缺失时对应比值为空，不使用前日数据拼接。

历史起点设为2018-01-01，首个实际交易日为2018-01-02。科创50的基日为2019-12-31、基点1000；上交所在2020-07-22发布回溯历史、次日开始发布实时行情，见[上交所原始公告](https://www.sse.com.cn/aboutus/mediacenter/conference/c/c_20200619_5130972.shtml)。当前公开接口提供的首日为2020-01-02，因此更早的科创50与科创红利比为空，不合成2018年的历史，也不把基点当作接口采集值。

后端始终返回完整历史，前端默认显示以最新有效数据日为终点的五个自然年。可选择近1年、近3年、近5年、全部，或输入日期、拖动底部滑块与在图内缩放。图例可分别开关五条曲线，后台更新保留用户当前缩放范围。缺失交易日显示断点，不补零、不前向填充；正常周末及休市日不作为缺口绘制。

### 最新比值的历史分位

创红比、科创红利比各绘制一条淡色细虚线，横线位于各自最新有效比值的实际右轴位置，轴外短标签显示该比值在完整历史样本中的百分位（取整显示），不是比值乘100。

- 创红比只取2018-01-01及之后的真实有效比值，实际首个采集交易日为2018-01-02。
- 科创红利比从首个真实有效比值起算；当前历史接口的科创50首日为2020-01-02，更早日期不补零。
- 两组分别排除缺失、非有限和非正数比值，各自在剩余观测中按日期取最新值，缺失的末日不会覆盖上一条有效观测。
- 对各自完整有效样本升序排序。沿用原有线性分位口径 (n - 1) × p 的逆向排名：唯一值的零基位置除以 n - 1；重复值取其排序位置区间中点；单样本取50%，无有效样本不画线。
- 切换日期范围、手动缩放只改变展示范围，分位保持不变；新增、修正或补齐数据后重新计算。隐藏某个比值同步隐藏其分位线及标签，右轴覆盖当前显示比值的实际参考线。

## 公开数据来源与完整性

日线优先使用腾讯公开行情接口：

```text
https://proxy.finance.qq.com/ifzqgtimg/appstock/app/newfqkline/get
```

例如参数 `param=sz399006,day,2018-01-01,2018-12-31,640,`。另外两个证券标识分别为 `sh000922`、`sh000688`。返回数组中的日期、开盘、收盘、最高、最低、成交量需按原字段顺序读取，收盘价位于第三项。

接口可能忽略请求开始日，并围绕截止日返回最多约640条记录，不能用一次请求宣称2018年以来历史已经完整。采集按年度窗口请求，再在本地严格筛选日期。对代码、返回结构、日期、正数且有限的收盘值进行校验；超出本次已结束交易日范围的数据不入库。

独立交易日历来自[新浪公开交易日历](https://finance.sina.com.cn/realstock/company/klc_td_sh.txt)。程序只按已知格式解码日期，不执行下载的JavaScript。日历与行情分别保存；每次用日历计算所有应有的“指数 × 交易日”，因此三个指数同时缺某一天也能发现。不能以工作日代替交易日，不能在日历未知时把本次采集标记为全部成功。

## 初始化、每日更新与失败补采

启用自动任务且日历确认当天开市时，服务启动可在后台回填历史，网页可查看进度，API与其他模块不必等待全量下载。科创50从2020-01-02开始计入应有记录，之前的空值不计为采集失败。

默认每个交易日北京时间18:00触发更新，使用 `Asia/Shanghai` 时区，不依赖服务器系统时区；新加坡时间与北京时间相同。手动更新按点击时最近已到的配置时点限定采集和当日日线复核，默认 18:00 前仅覆盖此前已结束的交易日。如果配置晚于 18:00，在配置时点前仍不请求当天日线；即使配置早于 18:00，也不会把盘中点位写为当天收盘价。任务优先处理最近日期，再补齐范围内已核验的历史缺口；界面历史和已发布数据保留。

每个窗口校验并提交后，已保存日期形成断点。下次任务只请求仍缺失的窗口和当天数据，不重复回填全部历史。远端网络错误、空响应、日期缺失、取消或进程中断不会删除已保存行情；待补项保留并在之后的任务中重新检查。所有应有记录齐全且交易日历可确认时，才更新“最近成功时间”。

周末、节假日或未核验日历日期不启动自动任务；仍可手动更新，休市日手动失败不纳入自动重试或补采。相关待发布结果可能隔离，已提交批次不会因此删除。参见[统一采集日历](../operations/collection-calendar.md)。

采集使用进程间文件锁，两个API worker或手动与定时任务同时触发也只允许一个任务运行。取消保留已提交批次；再次更新继续补缺。数据、日历、任务状态保存在 `LOG_DIR/market-data/growth-dividend/`，部署沿用现有日志持久化路径。

配置项 `GROWTH_DIVIDEND_WORKER_ENABLED` 默认 `true`，无需修改既有配置即可启用。设置为 `false` 可关闭自动回填和定时任务，手动更新仍可用。采集时间在系统配置独立设置，不受数据库快照同步时间控制。

## API

以下接口沿用站点账号认证，写操作沿用浏览器CSRF校验。

| 请求 | 返回或行为 |
| --- | --- |
| `GET /api/v1/growth-dividend/history` | 完整 `points`、`latest`、起止日期和采集 `status` |
| `GET /api/v1/growth-dividend/status` | 是否运行、处理进度、待补日期及记录数、最后检查/成功时间与下次计划 |
| `POST /api/v1/growth-dividend/refresh` | 异步启动补采，返回 `{ "started": true/false }` |
| `POST /api/v1/growth-dividend/cancel` | 请求停止当前任务，保留已保存记录 |

每个历史点包含 `date`、`chinext`、`dividend`、`star50`、`chinext_dividend_ratio`、`star50_dividend_ratio`。缺失值为JSON `null`。历史查询不会触发公网采集，数据更新时间与采集记录分开。页面右上显示可核验的秒级数据更新时间，不把行情交易日或最近尝试时间冒充更新时间。

## 外部采集与数据库存储

创红比和科创红利比统一以腾讯财经／东方财富接口结果为准，聚宽独立脚本及批量入口已移除。

- 沿用 `growth_dividend_index_history` 和 `growth_dividend_trading_day`，无需删除或迁移旧表。
- 使用网站系统设置中的 MySQL 配置，账号需要现有表的读写权限；空库首次运行还需要建表权限。
- 每个行情窗口先校验并暂存，再事务写入 MySQL，成功后发布到本地 SQLite。网页仍只读本地。
- 写库或本地发布失败会保留待发布数据，下次先续写，不重新下载该窗口。配置切换后不会把旧待发布结果误写到新库。
- 升级后的首次更新会将已有外部行情补写到当前 MySQL；旧聚宽记录保留，逐日由核验后的外部行情替换，不再混入比值计算。
- 同一天的新外部结果可以修正旧值；本地保留差异记录。较旧任务不会覆盖较新的外部结果。
- 创红比不在通用数据同步中心；专用发布链路仅使用核验通过的外部数据。新采集完成后无需另行同步。

日常仍按缺口增量补采，并复查当日收盘。创红比从2018年起，科创红利比从2020-01-02起；缺失数据不补零。

已校验并暂存的旧任务结果可继续数据库／缓存发布，不重新请求行情。重新配置数据库后镜像已有验证点位同样是恢复动作，不代表手动采集扩大了新的来源请求范围。
