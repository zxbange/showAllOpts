# ETF 历史：聚宽平台手动补采

入口：[ETF历史补采_聚宽研究版.py](../../collectors/ETF历史补采_聚宽研究版.py)。采集逻辑可粘贴到聚宽研究 Notebook，需一并上传 `collectors/mysql_connector.py`，不需要上传完整项目、调用项目 HTTP 接口、安装/登录外部 `jqdatasdk` 或运行交易所历史接口。后续每日自动更新仍由项目的交易所采集器负责，不改原批量采集脚本，也不设定新的定时任务。

## 范围和数据口径

- 默认 `START_DATE=None`，从所选18只跟踪基金中的最早上市日扫描。可显式指定日期缩小范围。截止范围为北京时间昨日，再按聚宽交易日历取最近实际交易日。周末/节假日不会生成记录；本脚本拒绝当天及未来日期，避免尚未收盘或尚未完成校对的数据。
- 覆盖项目当前固定 **18只ETF、7个指数组**：沪深300、中证500、创业板、科创50、中证1000、上证50、上证180。不是只补旧版10只，也不会根据最新排名偷偷替换名单。
- 每只基金先读取 `get_security_info` 的上市/退市日期，只在有效上市期请求及统计缺失，上市前不补零。
- 份额：平台 `finance.FUND_SHARE_DAILY` 的 `code/date/shares`，沿用项目既有聚宽脚本的整数“份”口径。**不乘10000**，不把成交量、资产净值或市值当份额。第一次运行应在平台字段字典和一只ETF的官方同日份额中核对这一单位。
- 价格：单只证券 `get_price(..., frequency='daily', fields=['close', 'paused'], skip_paused=True, fq=None)`。`None` 是 Python 值，不能写成 `'None'` 或 `'none'`。仅保存未复权收盘价，单位元/份；停牌日不使用前收填充，不以净值代替价格。
- 日历：`get_trade_days`，记录实际前一交易日，不能把“数据库上一条”当前一交易日。
- 为检查请求区间首日，会在内存额外读取前一交易日的份额和价格；该参考日不入库。上市前既不要求份额/价格，也不补零。

原始数据三张表和网页模型完全一致：

| 表 | 主键 | 新增来源标记 |
| --- | --- | --- |
| `etf_share_daily` | `fund_code, trade_date` | `JQDATA.FUND_SHARE_DAILY` |
| `etf_price_daily` | `fund_code, trade_date` | `JQDATA.GET_PRICE_UNADJUSTED` |
| `etf_trading_day` | `trade_date` | `JQDATA.GET_TRADE_DAYS` |

## 在聚宽运行

1. 将完整脚本粘贴到聚宽研究 Notebook 的一个单元格。
2. 在 `mysql_connector.py` 填写 `DB_CONFIG` 并上传研究目录，核对采集脚本的 `START_DATE` 和 `END_DATE`。目标应与网页 ETF 采集配置一致，数据库本身需预先创建。
3. 执行整个单元格，自动完成采集、校验、缺表创建和数据写入，打印各表新增及保留数量。无需再运行第二条入库命令。

顶部运行开关：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `WRITE_DATABASE` | `True` | 采集后直接入库；改为 `False` 则只预览，不连接数据库 |
| `CREATE_TABLES` | `True` | 自动创建缺少的三张表；账号无建表权限且表已由管理员建好时可改为 `False` |
| `ALLOW_PARTIAL` | `None` | 自动最早历史模式保存有效记录并持久记录未知缺口；显式指定起点时仍严格拒绝部分入库。`False` 总是严格；`True` 显式允许部分 |

修改顶部参数后重新运行整个单元格，确保函数使用新的默认值。源返回异常和校验错误仍会停止执行，`ALLOW_PARTIAL` 不会绕过这些检查，也不补零或前向填充。

使用平台已有的 `jqdata`、SQLAlchemy（1.3及以上）和 MySQL 驱动；脚本不自动安装软件。`mysql_connector.py` 中的 `DB_OPTIONS['driver']='auto'` 优先使用 `MySQLdb`，否则使用 `PyMySQL`。研究接口按 Notebook 全局变量、`jqdata` 模块和平台注入的 `builtins` 依次解析；缺少接口时列出具体名称。Python 内置函数显式通过 `builtins` 使用，避免 Notebook 中 NumPy 同名函数覆盖。

建表只针对缺少的数据表及自动历史模式的覆盖表，不改已有表；已有表须为 InnoDB。MySQL DDL 可能自动提交，因此建表与后续数据事务不是同一回滚边界。补采写入需要 `SELECT`、`INSERT`，缺表时还需要 `CREATE`；不执行 `UPDATE/DELETE/DROP/ALTER`。不要将真实连接配置提交 GitHub。

返回值 `RESULT` 保留原始记录、缺失清单、风险提示、写入状态及计数。默认从所选基金最早上市日检查整个请求区间，重复执行仍会检查历史中间缺口，不只是从数据库最新日期向后追加。

## 缺失、重复执行与权威来源

- **任何已有主键一律保留**，不仅交易所来源，还包括旧聚宽来源。现有值、来源和 `updated_at` 不变；没有 `UPDATE`、`DELETE`、`REPLACE` 或覆盖式upsert。同一份数据重跑不会产生重复行。
- 份额、价格、日历在同一数据事务内新增。原始响应错误、重复日期、错误代码、非交易日、异常数值或API异常会在连接数据库前停止。数据库写入失败请求整批回滚；提交时网络中断可能使结果不确定，安全重跑即可按已有主键核对补缺，不能仅凭报错断言未写入。
- 写入前查询已有数据，控制台报告各表新增、保留、以及“值不同但仍保留”的数量。后一项需要人工核对来源；脚本不会自行纠正或清洗既有数据。
- 若已有日历的前一交易日与聚宽冲突，停止并回滚本次新增，不覆盖交易所日历，也不沿用冲突关系继续入库。
- 本次聚宽源数据有缺失且 `ALLOW_PARTIAL=False` 时不写库，`RESULT['written']=False`。检查的是源返回是否完整，不代表数据库一定缺同一条数据。确认要先保存有效记录时，把顶部 `ALLOW_PARTIAL` 改为 `True` 后重新执行整段脚本。

这不是填补缺失：缺少的日期仍不写入。后续重复运行会补新出现的记录。全部缺失列表保存在返回值中，控制台只打印前20项，不会把部分完成称为全历史完整。

- 停牌、源数据尚未发布、账号历史权限或配额限制都可能导致缺失或报错。不要把源缺失解释为零份额或零价格。没有数据的基金也会明确列在缺失清单中。
- 与日更并发发生同主键竞争时，数据库唯一约束会阻止覆盖并回滚本次事务；避开日更时段重新运行即可，不会静默忽略数据库错误。

## 拆分、合并和异常份额保护

原始份额和未复权价格保留独立列，脚本不根据比例猜拆分因子、不修改原始份额或复权价格。沿用网页保守筛查口径：份额相邻交易日达到1.5倍或降至2/3及以下；价格达到1.25倍或降至0.8倍及以下时提示风险，并覆盖相邻可能错位交易日。这可能包含真实的大额申赎，**不是已核实公司行为**。

正常范围内的原始数据仍入库，由网页现有拆并防护排除可疑市值。唯一额外边界是补采首日：前日只在内存不入库，若首日比较已发现风险或前日参考缺失，则本次**不新增该首日价格**，列入 `RESULT['quarantined_prices']`，避免网页缺少历史基线时计算失真。已有价格仍不动，须单独人工核对。脚本不会宣称隔离这些价格后数据库完全无风险。

## 补采后刷新页面

在网站右上角打开「本地数据 / 数据同步」，选择 **国家队动态（ETF）**；已有本地缓存时，历史补采后请选择“完整重新同步（修复历史）”，再刷新图表。日常同步仅复核最近3个交易日并追加新日期，不读取更早的补采记录；首次同步会完整建立缓存。只点页面顶部刷新不会重新读取MySQL源表；也不必点击「立即采集」，该按钮触发的是交易所日常更新，不能代替这次聚宽历史入库。若网页切换过ETF目标库，确认连接目标与聚宽 `DB_CONFIG` 一致后再同步。

项目继续按已保存的自动采集时间使用交易所接口日更；不需要每天到聚宽运行本脚本。历史完整度以缺失/隔离清单和实际图表为准，不能用“日常采集完成”推断2024年以来已全部补齐。

## 最早历史与持久覆盖报告

自动模式不假设份额源与价格源同时开始。`source_coverage` 按基金/来源给出首末观测、缺失数量及 `unknown_or_partial`，不是平台最早可用日的保证。IPO之前不生成数据。只有真实来源记录才能入库，不前向填充、不把缺失写成零。

自动模式按最多120交易日一个事务保存数据及 `etf_history_coverage`。覆盖表主键为 `fund_code,trade_date`，`share_status`/`price_status` 为 `observed`、`source_missing_unknown` 或价格的 `quarantined`，附 `checked_at`。它描述本次来源可见性，不用既有数据库记录掩盖本次源缺失。覆盖表须为InnoDB；已有字段/主键不兼容会停止。该表的状态可更新，原始份额/价格仍只新增缺失主键。

`written=True` 仅表示有效批次已保存，须同时检查 `completion_status`、`source_complete` 和覆盖表；`partial_unknown` 不能称全历史完成。中途失败保留已提交的完整窗口，当前窗口回滚；重跑扫描整个区间、只补缺并刷新覆盖标记。源查询阶段报错仍不写任何本轮数据，不绕过权限/配额错误。显式指定起点仍沿用原有全批严格事务语义。

网页默认同步三张原始表；覆盖表留在源数据库供采集审计，不改网页数据口径或ETF名单。
