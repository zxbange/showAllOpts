# 行业动量：采集窗口与历史保留

独立脚本 [行业动量计算_数据库版.py](../../collectors/行业动量计算_数据库版.py) 和批量入口均不再自动删除旧结果。`RETENTION_TRADE_DAYS=180` 只限制普通日常采集窗口，不是数据保存期限。旧脚本已删除的数据不能自动出现，须通过历史入口重新取得。

普通 `run()` 和独立文件直接执行均使用近期增量，16:00前不写当天；不回扫早于水位的旧洞。完整历史须显式使用 `run_history(start_date=None)` 或批量 `history_mode=True,start_date=None`。该模式核验完整平台日历、逐日历史行业成员与全部价格预热，并修复早期和中间缺口。详见 [历史采集及入库说明](industry-breadth-history-recovery.md)。

逐日结果、恢复凭据和结果日志在同一事务中提交；失败保留此前成功日。不能把来源异常记成零动量或无股票。现有结果不覆盖，没有恢复凭据的旧行也不会因日常任务而被清理。底层 `cleanup_old_data()` 仅保留显式维护兼容，正常与历史入口都不以它作为恢复步骤。

使用者自行在聚宽上传脚本及 `mysql_connector.py` 配置目标数据库。不要把真实连接配置提交仓库，不并行运行多个研究内核写同一策略。完成后网页同步行业动量，使用结果日志；旧无日志来源对账完整主键清单。

当前历史重建使用聚宽本次可见的可能修订数据，不是原始PIT，也不是已在生产验证完成的声明。离线测试覆盖保留原值、日历、事务、旧洞、来源异常与缓存发布。
