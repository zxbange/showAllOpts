# 国家队动态：ETF 采集与配置

「市场情绪 → 国家队动态」展示跟踪 ETF 的份额及合计流通市值。管理员统一在[系统配置](../operations/system-configuration.md)管理 MySQL 和「国家队动态」自动任务；功能页不再提供独立数据库账号、连接测试或调度配置。旧模块配置可能参与迁移，不会将旧库的数据复制进共享库。生产权限、网络、数据完整性以实际运行结果为准。

## 页面操作

- 管理员在标签行右侧点击「更新数据」，异步更新最近已到的自动采集时点对应的交易日并补采之前的近期缺口；普通用户可查看图表和状态。关闭自动任务不影响手动执行，仍使用配置中的时间。普通页面刷新只读取已发布快照。
- 手动运行中可以点击「取消采集」。在当前网络请求或数据库事务安全结束后确认取消；已经提交的数据不撤销。重启造成的中断不会被当作成功，同一请求编号重试不会重复提交。
- 当前目标出现重试耗尽时可勾选「重新尝试当前目标日已耗尽重试的数据」再执行。仅调整本次已核验、写入完成的目标日重试额度，不改变上次目标、历史日或休市日的自动重试规则。
- 进度表示已处理的份额/价格目标数，包含因限流而暂缓的项目，不代表已发送这些请求或写库。需继续查看写入、发布以及终态；图表下方展示最近五次采集和脱敏失败原因。来源汇总日志分别列出本轮请求目标、异常、限流跳过及未核验的份额/价格数量；未核验范围不等于 HTTP 失败次数，也不代表数据库从未有过这些记录。

## 日常任务

采用同一共享 MySQL 目标，读取交易所官方日历、份额及行情，写入 `etf_share_daily`、`etf_price_daily` 和 `etf_trading_day`，随后定向发布 ETF 缓存。共享账号需对上述表有 SELECT、INSERT、UPDATE，首次建表还需 CREATE；不创建用户或授予权限。DB 连接和读写阶段分别使用 60 秒超时，不是整轮采集的墙钟总上限；安全要求见[数据库连接超时](../operations/database-timeouts.md)及[系统配置](../operations/system-configuration.md)。

- 默认 A 股交易日北京时间 **09:00** 执行一次。自动任务不得在周末、交易所节假日及未知日历日期运行。手动仍可运行，且闭市日手动失败不会消耗自动重试额度。详见[运行日历](../operations/collection-calendar.md)。
- 普通失败或部分完成后，同一自动时点最多两次尝试，重试间隔至少 30 分钟，跨日不继续重试旧时点。提交结果不确定时不自动重试该时点。任务登记、锁及缺口持久化以同一主机的共享日志目录为边界，不是多主机分布式锁。
- 自动采集只更新最新已确认收市的交易日，不遍历历史缺口。北京时间 15:00 前排除当天；之后仍由日历和行情核验决定是否可写当天。深市当天收盘价必须与同日盘后实时报价交叉核验；目标是早于北京时间当天的交易日时，使用深交所官方按日基金行情报表「今收」，无需用今天的实时报价验证旧日。
- 应用后台（自动/手动）采集沪市 ETF 份额均按跟踪基金代码和确切交易日查询上交所，不下载全市场日报。相同基金/日期每轮至多请求一次，按顺序发出，不因有效空表重试或用其他日期填补。收到 HTTP 429 后，本轮不再请求其他沪市份额，未请求项不消耗尝试额度；深市份额及收盘价任务继续。每个请求服从系统配置和 25 秒 I/O 超时中的较小值，另有 30 秒边界检查及取消检查，不是整轮硬截止。独立交易所 CLI 的全市场查询行为不变。
- 份额、价格缺失不填零；部分获取不抹去有效旧记录。成功写库后才更新观测账本。已入库数据的待发布处理不受自动采集开关及休市日限制，缓存重试至少间隔五分钟；不会因此补跑自动时点或重新访问交易所。普通 07:00 数据库同步不包含国家队动态。
- 状态 API 为 `GET /api/v1/etf-shares/collection-status`，缺口列表上限 500 项，描述当前目标而非历史完整度。写入诊断包含安全阶段、错误类型、MySQL/OS 错误码和目标指纹，不记录凭据、SQL 参数或原始异常正文。
- 采集确认提交的份额、价格主键及最早受影响日期单独保存在本地待发布状态中。定向发布使用同一共享数据库，核对源清单和实际 SQLite 快照中是否包含这些主键后再清除待发布标记。目标/来源不符、锁占用、读库或校验失败时，不把等待标记视为最新交易日已入库或已显示；保留旧快照及待核验范围。图表旁会说明等待原因、已核验到的日期（如有）和最近一次发布尝试。
- 系统配置启用 Telegram 通知后，自动与手动使用相同的结果格式，即使没有新增或变更也通知。显示目标交易日、份额和收盘价的来源核验进度、已知或本轮核验的历史缺口，以及各跟踪大类的当日与前一交易日份额总和和增减（万份）。只有固定名单在两日都完整才比较，未核验的基金或上日缺项不补零、不回退其他日期。最新日写入未确认时不展示未核实入库的份额；缓存待发布按部分完成通知，单独补发缓存不另发通知。

## 写库诊断

份额、价格以基金代码与交易日的组合主键分批查询已有记录；每个处理日只按主键读取及补写本日及其真实前一交易日；两条记录各自的前一交易日均来自完整核验的交易所日历。这不会扫描或补写其他历史日历缺行；需要全覆盖校对时使用独立交易所 CLI 的写入流程。写库优化不降低交易所日历和真实前一交易日的校验标准，不增加业务库迁移或索引变更。有效且未变化的数据保留原更新时间。

写入日志可按本轮运行标识分别定位表检查、连接、批量读取已有份额/价格/日历、提交前写入（flush）与事务提交（commit）的耗时。含表名的阶段可继续定位到对应表；只在有明确超时证据时标记为 socket 超时。抓取、写库与后续缓存发布属于不同阶段，不用 HTTP 请求成功或写入进度推断事务已经提交。若提交阶段出现有明确证据的 socket 超时或 MySQL 2013 断连，事务是否已提交无法确认，本时点不再自动重试。后续新时点按正常调度执行；如需手动补跑，先核实数据库持久化结果及快照状态，再决定是否执行。已提交但缓存发布失败，仍按待发布流程处理。

数据库连接与系统配置测试共用地址校验及连接入口（测试只运行 `SELECT 1`，不代表业务表读写验证通过）。同一采集轮复用一个连接池，分段归还连接，访问交易所时不借出数据库连接，也不保持事务。连接取得阶段或独立历史键只读核查出现明确的临时断连时，每轮最多换新连接重试一次。鉴权或权限错误、未知错误、建表检查、普通写入事务查询、写入和提交异常不会在轮内重放；提交确认丢失的处理规则不变。

Telegram 对比仅在通知启用且本轮有份额完整的大类时读取前一交易日。复用最新日已完成提交的连接，只按基金主键批量读取对应的一天，不新开连接、不访问交易所；读取失败仅提示对比未核验，不改变采集、提交或缓存结果。

## 页面手动补缺

- 点击时冻结请求时间与已配置自动采集时间（北京时间）。只使用已到且官方日历核验为开市的最近时点；时点在 15:00 前对应上个交易日，在 15:00 后还需核验当日已收市。例如配置为 08:00 时，周二下午或周三 07:59 点击只采到周一，周三 08:00 才采到周二。排队跨过时点、配置修改、自动关闭或漏跑都不会扩大已接受任务的范围；配置无效或无法核验时点时不猜日期。
- 从最近一个份额和价格都已覆盖的记录起，补到上述目标日。未到期日期不进入本轮，也不会清掉已有的待补记录。已有的更早待补日期不被较新的成功日期盖过；未补齐的日期保留给下次手动更新，不加入自动采集重试。
- 没有完整成功基准时，只检查最近三个已收市交易日（含未运行过的日期），不扫描全历史。旧日只填共享 MySQL 里缺少的记录，已有份额、收盘价和更新时间不覆盖；最新日期仍正常复核。按日期独立提交，某天缺数不会撤销其他日期的有效数据。
- 回补沪市历史份额时只请求数据库确实缺少的基金/日期。有效空响应、请求或校验失败、因限流未请求分别记录，未验证项目保留给下次手动处理。最新日期仍接受交易所同日修订。
- 深市历史补价使用深交所[历史行情](https://www.szse.cn/market/trend/index.html)的基金报表，精确校验证券代码、交易日期及「今收」，不使用「前收」。每只基金每个日期只发一次限定请求，分辨合法空表、明确归档和请求/校验失败；不猜归档边界，不填空、不改用其他日期。HTTP 429 只暂停本轮余下深市按日报表请求，不影响其他独立价格和份额路径。无法核验的价格保持缺失，已有旧日行仍不覆盖。
- 手动修补涉及较早日期时，ETF 缓存会从最早受影响日期定向重新核验；暂时无法发布时保留待发布状态。通常的自动采集和缓存增量范围不变。

## 已入库但图表未更新

先核对日志中采集目标、数据库提交、数据库写入汇总及 `ETF cache publication`/ `Cache refresh failed module=etf-shares` 行。缓存等待锁不等于读取失败；`SOURCE_DATA_INCOMPLETE` 表示应进入缓存的已确认主键在读取来源或快照中不完整，不会通过填零、移用其他交易日或清除待发布标记伪造成功。已有旧图表继续可查询。单独补发缓存不会重新执行交易所采集、修改 MySQL 或补发 Telegram，也不会改写以前采集的终态记录。

在项目根目录、与正常服务相同的账号及配置下，可查询并定向恢复：

```bash
backend/.venv/bin/python scripts/refresh_cache.py --module etf-shares --status
backend/.venv/bin/python scripts/refresh_cache.py --module etf-shares
# 仅在外部历史回填或确有旧快照损坏时，需要完整重建：
backend/.venv/bin/python scripts/refresh_cache.py --module etf-shares --full
```

CLI 和服务使用同一持久缓存命名空间。退出码 0 表示已验证发布（如关闭缓存，则说明使用直读），1 表示失败，2 表示任务锁被占用；不能仅凭文件锁存在或数据库同步总状态判断 ETF 是否发布。自定义配置路径、解释器和权限须与服务一致，见[本地缓存](../operations/local-cache.md)。

## 更早历史或交易所无法核验的数据

在聚宽独立运行[历史补采](etf-joinquant-history.md)并写入应用共享库。这个流程还用于交易所无法可靠核验的历史数据；不等同于网页手动补缺。另行导入的较早数据可按历史补采指南完整重建实际服务使用的 ETF 快照。重建不删除业务历史。
