# 个人持仓（管理员）

入口 `/personal-holdings`。复用站点账号体系，只有管理员可见导航和访问页面；所有持仓、历史、配置、连接测试、启停API均要求管理员会话，写请求继续校验同源和CSRF。普通用户无法通过直接API读取个人持仓。

在「系统配置 → 数据库」配置统一 MySQL，在「系统配置 → 自动任务 → 个人持仓」填写表名、启用监控并保存；也可配置保存后在持仓页点击「开始监控」。连接测试不启动监控，也不代表已验证业务表权限。表名仅支持字母、数字和下划线且首字符非数字，不接受 SQL 或跨库路径。切换数据库目标或表名后建立新基准，不删除旧历史；只轮换密码会重新连接但保留基准。密码占位只是固定提示，不是实际密码。

源表字段：`strategy2`策略文本、`name`中文名文本、`code`代码文本、`amt`非负有限数量（最多6位小数，最大999999999999999999.999999）。代码保持前导零，不自动将数值代码补零。同一`(strategy2,code)`重复行合计股数；同键名称冲突、NULL、负数、数量超限、超过100000行或查询中途出错均拒绝整份候选快照，保留原数据。零数量视为无持仓。名称变化更新展示但不产生买卖记录；策略迁移按原策略清仓、新策略买入记录。

首次成功完整查询建立基准，不记买入。后续完整成功空表会记录全部清仓；失败/超时绝不等同空表。源发布方应在同一事务原子更新整张持仓表：若分开提交“清空”和“重新写入”，观察者无法区分已提交的临时空表和真实清仓，无法凭四个字段推断其发布意图。

默认按 Asia/Shanghai 交易日 09:25（含）至 15:10（不含）监控，包含午间。默认每 15 秒查询，窗口及间隔可在系统配置调整；查询超时或超过间隔不重叠、不补发积压轮次。后台在关页后继续，窗口外/停止/退出释放连接，后续窗口重新连接。单个leader通过跨进程文件锁保持长连接，所有快照读取使用独立短事务，读取结束立即结束事务，空闲期间不保留MVCC快照。断连后丢弃连接，下轮重连，不隐式重放未完成查询。

交易日历来源为上交所官方年度休市安排，版本化保存在`backend/app/services/holdings_calendar.py`，当前覆盖2026-01-01至2026-12-31：[上交所2026年休市安排](https://www.sse.com.cn/disclosure/dealinstruc/closed/c/c_20251222_10802510.shtml)。排除周末，即使国家调休安排周末上班仍休市。当前项目历史行情日历不能确认未来日期，因此不复用为当天开市判定。官方下一年度公告发布后核对并更新该文件、测试和发布；临时休市公告同样需更新。未覆盖年份（当前包含2027年）停止自动持仓轮询及收盘价采集，不自动退化为周一至周五。运行时不请求第三方日历。

本地存储`${LOG_DIR}/personal-holdings/data/monitor.sqlite3`：保存当前快照、同步状态、配置引用和按上海日期分组的历史变动，无 TTL 或自动清理。数据库连接当前以服务器选中的私有应用配置为准，不再在持仓页面单独保存；旧来源状态和密钥可能仍用于迁移。不会写源库。源连接目标校验、DNS固定解析与危险地址阻断复用已有实现；部署者若设置`VALIDATION_ALLOWED_TARGETS`则仍遵守该限制。备份应保留私有应用配置及整个 personal-holdings 目录（含仍存在的旧密钥与迁移数据）。

源快照、变动记录和版本在一个SQLite事务提交；读中修改配置或停止会通过持久化epoch拒绝旧工作提交。重启后接续上次成功快照，新交易窗口首次读取与上次成功快照比较。记录时间是实际观察到变化的时间，停机、盘外和两次轮询之间只能看到净变化，不代表真实成交时间或逐笔交易。页面按需分页展示每日全部记录，历史不随连接配置切换删除。

不向站外公开持仓或行情 API，不提供全量清空或自动下单。真实环境应由管理员确认表配置及读取结果后启用自动监控。

「更新数据」使用已保存配置，通过后台队列执行一次完整读取；盘外、休市、日历未覆盖或持续监控关闭时均可用，不改变监控开关、时间表或自动轮询计划。未保存的编辑须先保存。请求幂等ID持久化，等待中的点击合并；与自动采样共用跨进程锁，不重叠执行。关页后继续，重启后接续待处理请求；停止/启动或修改配置会取消尚未提交的旧请求。失败保留快照和历史，需重新点击。盘外单次完成释放源连接；交易时段自动监控中的单次复用其连接。变动按实际观察的上海日期记入历史。

盘外页面仍从SQLite读取最后成功持仓，并展示最近读取时间。连接密码仅保存在受限的服务配置或环境中，不随页面回显；持仓快照、事件历史和幂等请求标识本身是SQLite明文，受目录0700/文件0600权限保护，不宣称持仓内容已加密。页面内存仅用于展示，后台持久化不依赖浏览器。

## 收盘价与策略总市值

管理员在「系统配置 → 数据接口与消息凭证」配置 [Tushare Token](tushare-settings.md)。个人持仓原有监控开关同时控制收盘价自动采集；仅在交易日执行，不因打开页面而请求行情。该任务与日内 MySQL 持仓轮询分开：北京时间 **15:05** 开始核查当天日线，尚未取得可用数据时同日每 **5 分钟**重试，到 **16:30** 截止。达到截止时点仍缺数据不跨日追跑；休市日、日历未覆盖或监控关闭时不自动查询。持仓页「更新数据」仍只读取持仓表，不会触发历史行情回填。

行情来自 Tushare Pro `daily`。每次仅按一个 `trade_date=YYYYMMDD` 请求全市场当日数据，字段为 `ts_code,trade_date,close`，使用人民币未复权收盘价。向 Tushare 只发送接口凭据、日期和字段要求，不发送持仓代码列表、名称、股数、策略、MySQL 连接信息或成交历史。报价在服务器本地与持仓关联；不向外部提交组合，也不因单只缺价改为逐只查询。

每条报价须与目标日一致。空响应、重复代码、日期不符、无效价格、标记有后续页或达到 6000 行上限的响应都不能视为成功；停牌、尚未发布、源权限或不受支持的标的可能造成缺价。页面区分收盘价更新状态、实际报价交易日和持仓最近读取时间。每个持仓来源只保留最近一批可用报价；新报价没有通过校验前，页面继续显示上一批及其真实日期。当天缺价可以在窗口内继续重试，但不接受使当天已有报价覆盖变差的结果。不把旧价冒充当天收盘，也不把不同日期的价格拼成同一个策略市值。

策略总市值按页面当前显示的股数乘相应已核验收盘价后求和；整次估值只使用最新一批报价的日期，不冻结某天的持仓。策略内有无法唯一匹配或未获有效报价的持仓时，不显示部分金额为总值，也不补零、沿用其他日期该证券的价格或使用盘中价。总市值是已观察持仓按所示日期收盘价的估值，不是实时资产净值或收益率。

### 历史与校验边界

报价用于显示策略市值，不提供历史市值或涨跌比较，也不从个人持仓变动倒推历史策略市值：项目记录的是轮询看到的净变化，既不是完整历史日终持仓快照，也不是逐笔交易或成本。聚宽即使提供部分市场的同日未复权报价，仍不能还原这里的历史私有组合及原来源核验状态；因此本功能不提供聚宽持仓入库或历史市值补采入口，也不要求上传私有表、持仓清单或连接凭据。单独下载公开的历史行情并不能使缺失的历史持仓估值变成可核验结果。

出现持续失败时先检查监控开关、目标交易日期、Tushare 日线权限与配额，再区分报价缺失、请求失败和持仓表读取失败；不要在日志或排查材料中粘贴 Token、原始响应或私有持仓。管理员可核对一组受支持股票的同日收盘价，以及本地股数×价格之和；历史变动和业务表不因估值更新而改写。

### 断连诊断

轮询失败先记录 `stage`（连接、读取或本地保存）、异常类型、驱动异常类型和数字 `mysql_errno`；无可用 MySQL 错误码时为 `None`。不记录原始异常文本、SQL、参数、连接地址或持仓内容。清理失败另外记录，不覆盖首个异常，也不阻止保存失败状态。

轮询失败同时保留共享诊断函数输出的有界异常链与安全调用位置。`source_connect` 包含 SQLAlchemy 首次连接初始化，不只指 TCP 建连或认证。PyMySQL 的 `InterfaceError(0)` 表示在已经关闭的 socket 上发送命令；例如初始化查询先出现 2013 断连，SQLAlchemy 随后的清理回滚可能再产生 0，旧日志只显示最后一层。应结合 `context_type`、后续 `mysql_errno`、`reason` 和 `frames` 找最初失败点，不能仅凭 0 判定密码、网络、连接池或服务端原因。该日志改进不改变连接、重试或超时策略。

读取仅四个字段，SQL 保留 `LIMIT 100001`，使用驱动缓冲结果，避免断连后 SSCursor 关闭时继续排空失效连接。正常轮询仍复用同一物理连接，每轮事务结束；失败关闭连接，下一轮重新建立。缓冲增加本次查询的临时内存占用，行数有上限但字节数取决于源字段长度。超限或读取失败仍拒绝整份快照，不产生清仓记录。此修复解决清理路径及诊断问题，不保证消除源网络断连。
