# 估值标尺

入口：市场情绪 → 估值标尺。支持沪深300、上证50、中证1000，静态/滚动切换、日线缩放及P20/P50/P80历史参考线。

## 日常更新

默认每天北京时间 **18:30** 从东方财富公开接口采集，不需要人工运行聚宽。管理员可在系统配置修改时间或开关，也可在页面手动采集。旧默认20:00迁移为18:30，其他自定义时间保留。

- 成分：`RPT_INDEX_TS_COMPONENT`，类型1/2/7对应三个指数；每页最多500条，验证300/50/1000只唯一成分。
- 个股估值：`RPT_VALUEANALYSIS_DET` 的 `PE_TTM`、`PE_LAR`、`TOTAL_MARKET_CAP`；每批200只，沪深300和上证50的重复成员共用查询。总市值由元换算为亿元。
- 指数收盘：东方财富日K接口，不复权；成分、估值与收盘必须属于同一交易日。
- 先保存当日成分快照，再取估值。数据未齐或接口失败保留快照，失败任务15分钟后重试；不将旧行情充当当天数据。工作日休市而接口没有新日线时也只等待，不制造数据。

三个指数验证完成后，在MySQL同一事务写入日汇总、原始成分JSON及变更日志，再事务写入本地SQLite。数据库失败不发布本地；数据库成功而本地失败，重试复用已提交记录，避免重复写入。已存在的聚宽或东方财富记录保留原值，不自动覆盖修订。

沿用系统配置里的数据库连接，账号需要两张v2表和结果日志的建表、读取及写入权限。采集与数据库历史同步使用同一把锁。

## 计算与存储

静态、滚动分别计算整体、等权和中位数PE。等权/中位数只取 `0 < PE <= 300`；整体PE为 `Σ总市值 / Σ(总市值/个股PE)`，包含负PE及超300的样本。缺少参与成分的PE/市值或合计利润非正时，整体PE留空；有效样本的等权和中位数仍可计算。

普通停牌不剔除；暂停上市状态未独立核验。来源、样本数、缺失数和成分指纹随结果保存。东方财富为 `EASTMONEY.VALUATION.V2`，聚宽为 `JQ_PLATFORM.VALUATION.V2`；相同算法不保证上游财报口径和修订值完全一致。

- `valuation_ruler_daily_v2`：每指数日一条汇总，六个PE和指数收盘。
- `valuation_ruler_member_v2`：每指数日一条完整成分JSON。
- `result_sync_head/change`：模块 `valuation-ruler-v2`，与业务记录同时提交。
- 本地：`LOG_DIR/market-data/valuation-ruler/history.sqlite3`，页面直接读取。

## 历史覆盖

**不能用已核实的东方财富公开接口承诺补齐2010年至今的六项估值。** 2026-11-15实测：600519的上述个股估值接口最早返回2018-01-02；当前成分接口查询2010-01-04返回空数据。市场估值汇总 `RPT_VALUEMARKET` 中的000300记录统计了5230家公司，不能当作沪深300成分估值使用。

日常只计算已归档成分快照对应的日期，不把当前成分套用到历史。长时间停机、从未保存的历史成分或超出自动行情窗口的缺口，用[聚宽历史补采](joinquant-market-valuation-history.md)恢复。历史补采和日常自动采集可以并存；最新东方财富记录不会推进聚宽的历史补采断点。

聚宽脚本按200只分批取估值；批次中缺少的代码再单独复核。确认缺失时保留成分和NULL并计入缺失统计；整批全部无估值、重复代码、字段不全或日期错位仍停止。已完成指数日保留。

网页数据库同步只读日汇总，增量复查最近三个已保存交易日并追加新日期；不下载全部成分JSON。v1旧历史保留，不与v2不同算法混用。

## 验证

`test_index_valuation_public.py` 覆盖公开接口分页、日期、缺失、事务回滚、本地失败恢复及定时重试；`test_index_valuation_collector.py` 覆盖聚宽批量/独立一致、历史断点和缺失复核；`test_index_valuation_sync.py` 覆盖汇总增量同步。测试均使用模拟数据和隔离SQLite。
