# 高股息选股与高增长：当前名单和历史档案恢复

## 能恢复什么

两个完整单文件入口均保留原选股算法及网站当前表契约：

- `collectors/高股息选股_数据库版.py`：纯高股息、低估值非银行、低估值银行三组完整计算。
- `collectors/高增长_数据库版.py`：四类累计财报分别最新三期、归母净利润与基本 EPS 双增长。

`mode='latest'` 仍计算当前名单并更新原有 snapshot/stock 表，同时将当日第一次成功采集结果保存为 `observed` 档案。`mode='history'` 按聚宽目前可见的历史数据逐交易日重新计算，只写独立档案表，绝不写网站最新表，不改变原筛选算法，也不把仅银行或仅低估值结果冒充整个高股息功能。

**历史结果标识为 `revised_asof`，不是原始时点 PIT。** 聚宽[技术支持说明](https://www.joinquant.com/community/post/detailMobile?postId=21247)指出：披露差错产生的修正只保留最新披露版本；报告期财务表虽保留部分调整前后数据，仍不保留全部差错修正前版本。因此，仅有 `pub_date <= 截止日` 不足以证明恢复了当时实际看到的所有值。`get_fundamentals(date=...)` 有日期选择语义，但不使被覆盖的旧版本重新出现。名称、分红等源数据也可能事后修订。程序不承诺原始交易实盘回放；传入 `source_kind='point_in_time'` 会在写库前明确拒绝。

历史回算仍执行日期约束：高增长使用 `pub_date <= 截止日`、`end_date <= 截止日`、`report_date == end_date`，只接受当年1月1日开始的累计报告；高股息按日期取得股票池、ST、估值、行业、财务，分红按已发生登记日/除息日及原365/1095天窗口计算。所有模式仍拒绝返回的未来财务日期。高增长财务短页继续分页到真正空页，不能以短页误判没有后续报告。

## 在新的数据库中执行

由操作者将需要的单文件脚本和 `mysql_connector.py` 上传至聚宽研究目录。修改配置文件内目标数据库地址、库名、用户和密码；不将真实配置公开或提交 Git。两个策略互不导入，无需其他策略文件。也可以在 `run(database_config={...})` 中传入完整自定义连接配置；不要打印该字典。

建议先导入模块，再明确调用需要的模式。直接 `%run 文件名.py` 会运行默认最新名单，而不是历史模式。

```python
import importlib
selection = importlib.import_module('高股息选股_数据库版')
# 高增长用 importlib.import_module('高增长_数据库版')，下列调用相同。

# 核验从聚宽完整交易日历最早日期到最新完整日的候选范围。
# 只查询日历，不连接/创建数据库，不采股票。模块导入仍读取配置副本。
preview = selection.run(mode='history', dry_run=True)
print(preview)

# 一次执行从最早交易日到本次启动时确定的最新完整日。
# 范围固定，不监视未来日期；每个日期仍单独事务提交。
result = selection.run(mode='history', max_days=None, allow_partial=True)
print(result)

# 也可分批：每次最多尝试20个尚未完成、尚未记录缺口的日期。
# 早期财报不可用的日期留下gap并继续，不伪造空名单。
result = selection.run(mode='history', max_days=20, allow_partial=True)
print(result)

# 重复相同调用，直到remaining==0。仍需检查gaps/previous_gaps，不等于历史完整。
# 可限定区间，不必从头运行。
result = selection.run(mode='history', start_date='2020-01-01',
                       end_date='2020-12-31', max_days=20, allow_partial=True)

# 权限/字段/源接口恢复后，显式重试已记录缺口；已完成日期始终不重写。
result = selection.run(mode='history', start_date='2020-01-01',
                       end_date='2020-12-31', retry_gaps=True,
                       max_days=20, allow_partial=True)

# 网站仍需其当前两张表。在历史档案恢复后，独立运行当前名单。
current = selection.run(mode='latest')
```

`start_date=None` 使用 `get_all_trade_days()` 的最早交易日，不硬编码某个“有完整财报”的起点。每次范围查询 `get_trade_days(start_date, end_date)` 必须与完整日历过滤结果完全一致；缺日、重复、乱序、空日历会失败，不建立完成标记。默认截至北京时间最近完整日：当日16点前不使用当日行情。历史档案按交易日生成，高增长周末最新运行可能有周末 `as_of_date`，不会被虚构为交易日历史点。

`max_days` 默认为20；整数必须为1至250，限制本次尝试天数。显式 `max_days=None` 在一次执行中处理本次固定日历范围内所有待处理日期，范围在运行开始时确定，不等待或轮询未来日期；逐日事务和缺口规则不变。`allow_partial=False`（默认）遇到第一个失败日写入缺口后中止；此前完成日保留。大跨度初次恢复建议显式 `allow_partial=True`。已经记录的缺口默认不再次尝试，以免最早无数据时期一直占满批次；使用 `retry_gaps=True` 重试。仍失败的早期缺口可能持续占满重试批次，需限定具体起止区间处理后续缺口。

结果字段：`added` 本次新增完整日期数，`skipped` 已完整日期数，`remaining` 尚未尝试的待处理日期数，`gaps` 本次失败日期，`previous_gaps` 本次开始前已有缺口。重试成功的日期仍可能出现在该次 `previous_gaps`（它是运行前记录）；以数据库最终状态或下一次运行结果为准。`unresolved_gaps` 是本次运行结束后请求范围内数据库仍为 gap 的实际数量；只读预览不读库，返回 `None`。`remaining==0` 不证明没有缺口：只有 `remaining==0` 且 `unresolved_gaps==0` 才表示本次请求范围没有未处理日或已记录缺口；有未解决缺口应显示 PARTIAL，不得显示完整成功。`dates` 是请求范围候选日历，不是已恢复日期证明。

## 档案表、完整性和恢复边界

新增表为 `dividend_selection_archive`、`high_growth_archive`。不迁移、不删改旧表。复合主键为日期、来源种类、原规则版本。每行包括：

- `status`：`complete` 或 `gap`；`captured_at` 是本次实际采集北京时间。
- `snapshot_json`、`stocks_json`：元信息与所有股票在同一事务内保存；MySQL 使用 LONGTEXT，支持高增长大量匹配股，避免普通 TEXT 长度不足。
- Decimal 以十进制字符串、日期以 ISO 字符串编码，不经过 float；高增长累计报告证据保留在股票 JSON 中。
- `provenance_json`：JoinQuant、档案格式版本、原规则版本、来源种类、`original_point_in_time=false`、修订限制及文档链接。
- `error_code`：失败异常类型，不保存原异常、连接地址、密码或 SQL 参数。

完整档案不可覆盖，包括合法的零匹配日；失败日期可事务替换为完整档案。每次写入前验证既有档案字段、主键、类型、长度和空值约束；不兼容时明确停止，不自动改造旧表。事务失败不会留下半个名单。避免多个研究内核同时写同一策略，首次并发插入冲突不会吞掉错误。

源接口完整性守卫包括非空股票池、股票/字段范围、价格/ST/估值/行业完整性、分页主键/顺序、日期边界、分组数量和排名。历史高股息若候选池中财务记录未完整返回或报告期/公告日期缺失，整日记缺口，而不是把这些股票悄悄当作不满足条件。高增长若完全无财报或没有任何股票具备完整四类三期财报，整日失败；正常上市不足三年或缺少某类报告的单股仍按原算法不入选。无法仅凭 API 响应区分供应商合法缺报与未显式报告的源端遗漏，不宣称源数据库完整性已获独立证明。较早年份、权限不足或数据表尚无覆盖时留下缺口，不填零、不复用其他日期、不用今天股票池代替历史股票池。

`observed` 是**该日期、该规则第一次成功采集时的实际结果**，不是保证当日实时生成，更不是该日所有修改版本。后续同日最新名单重算可变化，但已有 `observed` 档案保持第一次结果。已有最新名单不会被历史模式覆盖；原历史版本若此前从未留存，不可从最新表凭空找回。

在有 `observed` 档案但原最新表丢失的新库，可执行：

```python
selection.run(mode='restore', day='2026-11-11')
```

只允许恢复匹配当前规则的 `observed` 完整档案；拒绝把 `revised_asof` 自动升级为网站当前名单。恢复仍走原校验和原最新快照事务，拒绝旧日期覆盖更新日期。档案与最新表属于两个独立事务：最新表成功而后续归档失败时，应排查并重跑，不能把这一情形说成最新写入也已回滚。

新库可通过历史模式恢复全部源数据支持且通过校验的交易日档案，再用 `latest` 生成网站需要的当前表。历史档案保存在新库并可 SQL/JSON 查询，**本次没有添加网站历史名单界面或自动读取档案的网页接口**。按现有网站同步机制同步当前表，不应把档案覆盖范围说成网页历史展示覆盖范围。

## 验证范围

离线测试覆盖日期限额、最早日期、完整日历交叉校验、缺口推进/重试、精度、现有表schema拒绝、事务回滚、合法空名单、成功档案不覆盖、仅observed恢复、拒绝旧日期回退，以及财报短页和缺字段守卫。使用模拟聚宽数据与 SQLite，并编译 MySQL LONGTEXT 类型。没有在真实聚宽账号或生产数据库执行采集，因此实际最早可恢复日期、账户权限和真实覆盖率须运行后以complete/gap记录确认。
