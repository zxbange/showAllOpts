# 净利润断层观察名单

## 使用方式

1. 将 `collectors/净利润断层_数据库版.py` 上传到聚宽研究环境。在私有副本的 `MysqlEarnings` 中填写与项目相同的 MySQL 数据库连接信息。
2. 直接粘贴运行，或在 Notebook 中执行：

   ```python
   %run -i 净利润断层_数据库版.py
   ```

3. 采集账号需要建表、查询、插入、删除权限；网页账号只需 SELECT。脚本自动创建 `earnings_gap_run`、`earnings_gap_stock` 两张 InnoDB / utf8mb4 表，不修改现有业务表。
4. 运行成功后，打开“发奋墙 → 净利润断层”。列表支持搜索、季度、行业、触发公告类型、排序和分页。点击股票查看三类公告原始数据、约 200–300 字的原因分析以及信号前 10、后最多 20 个交易日日线。
5. 每次需要更新时在聚宽重新运行。网页不会自动执行聚宽，也不包含下单逻辑。

仓库中的采集脚本只包含脱敏配置。本地 `original` 私有副本与网页的 `config/app.config` / `backend/.env` 均不应上传真实凭据。

## 筛选口径

- **统一报告季度**：运行所在季度之前的最近一个完整季度。例如 2026-10-17 取 2026-09-30；2027-01-01 取 2026-12-31。季度末当天仍取上一季度，下一季度开始自动切换。不自动混入上一期财报。
- **范围**：聚宽 `get_all_securities(types=['stock'])` 提供的全部 A 股，不限 3/5 只，不使用原策略的行业白名单、私人黑名单和持仓限制，也不额外排除 ST。覆盖范围受聚宽数据权限和股票支持范围约束。
- **三条财务路径取并集**：快报归母净利润为正且同比 ≥ 20%；预告增幅下限 ≥ 20%（沿用原程序，不增加盈利为正限制）；正式财报归母净利润为正且同比 ≥ 20%。
- 只读取目标报告期并且截止日期前已披露的记录。目标期的快报、预告可以早于季度结束发布，也会检查其对应行情。
- **价格条件**：公告对应交易日的开盘价 > 前一交易日收盘价 × 1.03，且收盘价 ≥ 开盘价。等于 3% 不算。当天停牌、无成交，或者没有可验证前收盘价时不产生信号。
- **公告日期映射**：交易日公告使用当日日线，沿用用户确认的原程序口径；非交易日公告顺延到下一个交易日，绝不使用公告前的价格。不会跳过停牌一直寻找未来的上涨日。
- **不是严格缺口策略**：不要求当日最低价高于前日最高价，也不检查 5 日不回补。
- **不是公告因果验证或回测**：日期级数据无法区分盘前/盘后披露。股价和利润同时符合条件，不代表公告导致上涨，不代表超出分析师预期。复权行情和源表更正可能使重采结果变化。
- 一只股票可有多个命中事件。列表以最新信号日期为主，同日按高开幅度、来源编码确定稳定顺序；详情保留该股票该期取得的全部公告和命中标记。不会用最新不合格公告替换历史命中事件。
- 正式财报查询通过 `get_fundamentals(date=截止日)`，并限定利润表与指标表同一报告期；两个发布日期不一致时，以较晚日期关联行情。该接口返回截止日可见的财报版本，不提供完整的财报修订历史。快报和预告使用主键分页，避免行数上限截断。

## 数据与分析

| 字段 | 单位 / 含义 |
| --- | --- |
| 总市值、流通市值 | 亿元，截止交易日的估值快照 |
| PE（TTM）、PB | 倍，保留负数；缺失显示 —，不补零 |
| 归母净利润 | 标准化金额为元；正式财报沿用原策略单季度字段，快报使用源表报告期金额 |
| 利润同比 | 百分数，25 表示 25%；预告列表展示区间下限 |
| 高开幅度 | 相对前一交易日收盘价 |
| 当日变动 | 收盘相对开盘价 |
| 细分行业 | 截止日优先申万三级，缺失依次回退二级、一级，并标注实际层级 |
| 公告原始数据 | 保存源表字段、报告期、发布日期、来源类型；未标准化的预告金额字段保留原值，不猜测单位 |
| 原因分析 | 每条 200–300 字，随采集生成并入库；依据与原始数据一同展示 |

快报/预告与正式财报的数据口径不同：前两者通常为报告期累计，正式财报的 `income` / `indicator` 沿用单季度接口。页面分别标注，不能把三季报累计同比与第三季度单季同比直接当作同一指标比较。归母净利润及增幅以触发信号的来源为准。

**原因分析是规则化证据解读，不是联网新闻调查，也不依赖外部大模型。** 首先解释业绩和价格如何触发筛选。只有触发公告返回明确 `change_reason`、`profit_change_reason` 或 `reason` 文本字段时，才引用其片段（完整原文保留于详情）；没有字段时明确说明“未取得经营原因说明”。不会编造订单、涨价、政策、主力买入或国家队等原因。聚宽表不一定提供原因全文，因此不少股票可能只有量价与财务层面的解释。

- 默认结束日期为北京时间当天；16:00 前只处理此前的完整交易日，周末使用最近交易日。建议收盘数据发布后运行。
- 每次重查**当前目标季度**，而不是仅从上次日期之后查询。这样能补进迟到披露、修订数据，避免把缺失记录永久跳过；不是扫描所有历史季度。
- 只在所有数据获取、校验成功后连接业务数据库，以一次事务替换该季度快照和元数据，保留其他季度。合法“零命中”会保存零数量，不冒充尚未采集。接口异常或写入异常时旧快照保留。
- 这是每季度最新观察快照，重采会替换该季度结果，不是每天的历史名单存档。列表默认请求当前目标季度，没有数据时不自动回退旧季度。
- 列表在数据库分页，最多 100 条/页，不读取公告及日线 JSON 大字段；详情按季度和代码复合主键读取。行业和信号日期有联合索引，减少公网数据库传输。

## 更新网页项目

Linux（既有生产环境）：

```bash
cd /home/ubuntu/showAllOpts
git pull --ff-only
bash scripts/build.sh
sudo rsync -rlt --chmod=D755,F644 frontend/dist/ /var/www/showallopts/
sudo systemctl restart showallopts-api
sudo systemctl status showallopts-api --no-pager
```

以上沿用现有 `showallopts-api` 服务和 `/var/www/showallopts` 静态目录。Nginx 配置不需要新增路径规则，沿用现有 SPA 和 `/api/` 代理。第一次先运行聚宽采集创建表，否则接口会返回数据库不可用；没有写入真实业务数据前，页面不展示模拟股票。

Windows：更新项目后关闭旧开发启动器，再执行 `start.cmd`，确保旧后端已退出；新增 API 需要重启后端。

API：

- `GET /api/v1/earnings-gap/stocks`：`period`、`search`、`industry`、`source`、`sort`、`direction`、`page`、`page_size`。
- `GET /api/v1/earnings-gap/stocks/{code}?period=YYYY-MM-DD`：股票详情，代码使用聚宽完整代码。
