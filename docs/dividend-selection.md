# 高股息选股

## 运行与参数

在聚宽研究环境运行 `collectors/高股息选股_数据库版.py`，或新版 `collectors/策略批量采集_数据库版.py`。两者都是完整单文件，无需额外上传项目代码或配置文件，支持直接粘贴和 `%run -i 文件名.py`，不依赖 `__file__`。真实数据库信息只填在私有副本顶部的 `DB_CONFIG`；GitHub 文件为占位值。

`STRATEGY_CONFIG['高股息选股']` 包含 `end_date=None`、`batch_size=300`、`page_size=2000`。日期每次按北京时间计算，16:00 前只使用截至昨日的最近交易日；周末自动取最近交易日。默认只计算一个最近完整交易日，没有历史补采。两种方法固定各取最多 25 只，条件不满足时不补足。

独立和批量入口均显示控制台进度，支持 `PROGRESS_ENABLED` / `PROGRESS_INTERVAL_SECONDS`。分红、股票池、财务指标按批采集；不创建采集日志文件，不发交易指令。独立入口打印当前完整选股结果，批量入口打印当前结果条数及预览。

## 已确认的两种方法

| 方法 | 筛选和排序 |
| --- | --- |
| 纯高股息 `classic` | 近三年累计分红比例前 10%，再要求 0.1 < PEG < 2、营业总收入同比 > 3%、净利润同比 > 8%、扣非净资产收益率 > 4.5%；最后按三年累计比例降序取前 25 |
| 高股息低估值 `value` | 近一年股息率 > 4%，且 0 < PE < 8；按近一年股息率降序取前 25，不附加第一组的盈利增长条件 |

所有边界均为严格大于/小于；PEG = PE / 净利润同比的百分数数值，例如 15 / 20 = 0.75。使用 `indicator.inc_net_profit_year_on_year`，不是归母净利润增长率字段。三年累计分红比例没有年化；不是 V2 的月度、10 只或更高增长门槛。

两组共用可选股票池：使用历史股票列表，剔除代码以 4、8 开头的股票，以及 ST / 名称含 ST、*、退的股票。**允许 68 开头的科创板股票入选，不剔除停牌、涨停或跌停股票**，不另加上市天数限制。行情只读取收盘价用于展示，停牌时保留数据源填充的收盘价；收盘价缺失或无效仍中止采集并保留旧结果。该程序只做研究选股，没有真实持仓，因此没有持仓豁免，不执行原策略的买卖、资金修改或涨停打开卖出规则。

本次股票池调整后的规则版本为 `dividend_top25_v2`。更新独立或批量采集脚本后需重新运行，两组最新结果会按新股票池重新计算并一起替换，无需修改数据库表结构。

分红数据来自 `finance.STK_XR_XD`，分两种日期口径：

- 第一组沿用原程序：按 `a_registration_date` 股权登记日统计截至选股日最近 1095 天的累计金额。排名分母为可选股票池内有该区间分红记录的股票数量，前 10% 向下取整；不是先做盈利筛选再取前 10%。
- 第二组：按 `a_xr_date` 除息日统计 `(选股日－365天, 选股日]` 的现金分红，左开右闭，避免把恰好一年前的分红重复纳入一年窗口；尚未除息的方案不计入一年股息率。使用除息日判断已实施分红与[聚宽技术支持说明](https://www.joinquant.com/community/post/detailMobile?postId=21247)一致。
- `bonus_amount_rmb` 按原程序的万元口径换算，总市值 `market_cap` 单位为亿元。百分数 = 分红金额 / 100 / 总市值；例如 50,000 万元 / 100 / 100 亿元 = 5%。数据库比例保存为 `5`，网页显示 `5%`。
- 同比例按代码升序稳定排序；筛选和排序使用未舍入值，写入时用 Decimal 统一到 6 位小数，避免浮点尾数截断。页面显示两位小数，紧邻门槛的值可能四舍五入显示为 4.00%，但实际大于 4%。

所有估值和财务查询显式使用所选交易日；股票各自最新已披露报告期可能不同，页面展示报告期和公告日期。相对原来 09:31 调仓所用的前一交易日数据，本程序生成的是所选完整交易日的研究快照。现有源数据后续修订会在重跑时反映，不承诺逐时点还原过去的实时交易结果。

## 数据完整性与写入

这一个模块按用户要求**每次重新计算，只保留最新结果**，是批量入口原先“只新增”的明确例外。原六个策略的增量和只新增行为保持不变。

- `dividend_selection_snapshot`：固定 `id=1`，保存数据日期、最后变更时间、规则版本、股票池规模、各组符合条件数量和入选数量。
- `dividend_selection_stock`：主键 `(method, code)`，唯一索引 `(method, rank)`；最多 50 行。同一股票可以同时出现在两个方法中，属于两组有效结果，不是重复写入。
- 采集、校验全部成功后才开启替换事务。锁定快照头，删除本模块原明细，写入新明细并更新快照头，一次提交；任何错误回滚，两组始终一起更新。
- 同一天也重新查询和筛选，数值、名单或排名变化时覆盖。数据日期、元信息和明细都完全相同时不执行 DML，`updated_at` 表示最后变更时间，不是最近一次运行时间。
- 完整采集后两组都无匹配属于有效空结果，会清空旧名单并保留快照头；尚未采集与已采集零匹配在网页上分别提示。
- 连接失败、行情/ST/估值缺失、分红分页异常、整个股票池财务指标为空等不会用空结果覆盖旧名单。个别股票缺少财务指标时无法通过第一组，对第二组不增加成长条件，缺失字段显示 —。
- 分红按主键分页直至空页，不假设每 300 只股票只有一页；校验重复主键、日期/代码越界。分红金额为空沿用原程序按 0 处理，非空无效或负金额报错。
- 拒绝较旧日期覆盖较新快照；不要在多个研究内核同时运行同一采集。首次并发创建主键冲突会回滚报错，不吞掉错误。
- 新建表使用 InnoDB，事务只涉及本模块的两张表。批量汇总中本模块条数是**当前选股结果数量**，其他策略仍为实际新增数量。

## 网页与部署

总览新增“高股息选股”，地址 `/dividend-selection`。两张方法卡切换独立排名；支持搜索代码、名称、行业，筛选两组共同入选，展示两种分红比例、PE/PB、市值、收盘价、PEG、增长指标、扣非 ROE、报告期和公告日期。宽表支持左右滑动，桌面和手机均可使用。

接口 `GET /api/v1/dividend-selection/latest` 使用一个只读 JOIN 查询同时取得快照头和两组明细，避免更新时读取到不同批次。网页刷新仅读取 MySQL，不调用聚宽或重新选股。没有历史日期选择，因为只保留最新结果。

先在聚宽运行采集脚本，自动创建两张表并写入网页连接的同一数据库；只读账号如按表授权，需要补充两张新表的 SELECT 权限。Linux 按 README 的增量发布步骤拉取代码、重建前端并重启后端；Windows 关闭旧进程后重启 `start.cmd`。此次无新增 pip/npm 依赖。

离线测试使用模拟聚宽数据和 SQLite，覆盖边界、排名、分页、重复运行、原子替换/回滚、接口及页面交互；真实聚宽数据权限、行情完整性和 MySQL 写入仍需在研究环境验证。
