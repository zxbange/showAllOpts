# 聚宽市场情绪与估值标尺历史补采

## 使用

分别将 `collectors/市场情绪历史补采_聚宽研究版.py` 或 `collectors/估值标尺历史补采_聚宽研究版.py` 与自己的 `mysql_connector.py` 放在聚宽研究目录，配置数据库后执行单个脚本。脚本不依赖其他采集脚本、不读取本机文件、不使用外部 JQData 账号认证。真实数据库密码不要提交仓库。

默认 `WRITE_DATABASE=True`、`MAX_DAYS=None`，直接运行即处理本轮全部待采交易日，无需重复执行20日批次。估值脚本从最后完成日期之后续采，空库从2010年开始；市场脚本从平台最早日检查区间缺口。两者逐日事务提交，失败保留之前完成日期，重新运行继续补采。结束日只在启动时确定一次，不会追赶未来日期。

需要限制本轮天数时，可指定1至250日，例如 `run(start_date='2010-01-01', end_date='2020-12-31', max_days=20, write_database=False)`。默认 `None` 不受250日分批上限限制。预览用 `write_database=False`，仍请求聚宽数据，但不导入数据库配置、不连接数据库。数据库实例须已存在，账号需要建表权限；估值旧表仅自动升级下文所述的PE空值约束，其他不兼容结构仍拒绝写入。

日期必须为 YYYY-MM-DD。默认结束日为北京时间最新达到 18:30 的自然日，再取平台交易日。显式未来或未闭市日期被拒绝。区间日历与平台完整交易日历交叉核验，防止区间请求被截断。只接受平台当日数据，不接受上一日填补成当日。

估值补采使用单行进度条，显示阶段、当前日期、已完成/目标天数、百分比和累计耗时。先查询及核对最后完成日期，再采集其后处于请求区间内的交易日。百分比以本轮实际待采日期为分母，只有当日成功提交才增加完成数。预览明确显示未入库，失败或中断保留真实完成数，结束后显示本轮处理及剩余待补天数。

## 两个指标互相独立补洞

市场脚本默认从平台最早交易日扫描至闭市日，分别检查热度和拥挤度的每个既有日期，不使用 MAX(date) 作为起点。拥挤度保留原聚宽股票全集，包含停牌、零成交额股票作为数量分母；取数量的前 5%（向下取整，最少一只）的成交额占比。

热度沿用原脚本的 A 股集合（排除 200/900 B 股），前复权（fq='pre'）、20 个交易日收盘均值，历史停牌日使用平台填充值；当天停牌或不足 20 个交易日的新股不进入样本。股票上市期间行情缺失不是“不合格样本”，而是停止本日，避免静默缩小分母。平台最早 19 个交易日没有完整 MA20 预热，只补拥挤度。之后若没有有效热度样本，也明确停止，不写入假零。

热度沿用 `market-sentiment` 结果日志协议；拥挤度保持其独立表的现有同步方式，不混入热度日志。旧日更热度脚本仍可使用近期采集窗口，但不再自动删除三年前的历史。

## 估值口径及原始凭据

起点为 2010-01-01。每天单独调用 `get_index_stocks('000300.XSHG', date=D)`，必须恰有 300 个唯一成分。`get_fundamentals` 明确请求 valuation.code/day/pe_ratio 并使用 date=D，校验每行日期。指数收盘使用 fq=None 的原始指数行情。

仅有效正 PE-TTM 等权算术平均。负 PE 单独计为负PE样本；源 PE 的 None/NaN 保存为 NULL，不参与均值，也不计为亏损，完整300只成分仍保留。缺失数量为 `member_count - positive_count - loss_count`，项目导入后保存到本地汇总的 `missing_pe_count`，页面及图表提示显示该数量。零、无穷值、非法文本、缺失或多余成分记录仍停止本日；全日没有正 PE 也不写入假零。新读取的有效 PE 按 Decimal HALF_EVEN 保留12位小数，指数收盘价保留8位；越界或舍入后归零仍停止。先规范成分精度，再求和、计算均值，确保汇总与明细一致。成分代码排序后以换行连接、无末尾换行，计算 SHA256。

写入 valuation_ruler_daily / valuation_ruler_member / valuation_ruler_trading_day，来源分别 JQ_PLATFORM.PE_TTM.V1 与 JQDATA.GET_TRADE_DAYS，方法版本 csi300_equal_positive_pe_ttm_v1。保存完整300条成分记录（带符号PE或NULL）、成分哈希、日期、来源和原始指数收盘。全有效历史的计算结果不变，不覆盖旧记录。

运行新版脚本时，若旧 MySQL 成分表的 `pe_ttm` 不允许空值，会在校验其余结构后自动执行 `ALTER TABLE valuation_ruler_member MODIFY COLUMN pe_ttm DECIMAL(30,12) NULL`，需要 ALTER 权限。仅放宽该列的空值约束，不更新已有数值，不新增汇总列。网站代码也需要更新后才能导入带NULL的记录；新版读取器兼容旧非空表。本地SQLite首次启动会在事务内升级成员表的空值约束，保留全部数据；旧汇总未带缺失数时按已有三个数量计算。

这些历史数据是聚宽平台**当前可见的历史修订版本**，不能声称是当时未修订原始快照。日期过滤严格，但不能消除平台自身历史修订。

## 安全与恢复

检查表的完整字段集合、日期/数值/文本类型、主键字段与顺序、NULL 约束与精度，拒绝无符号数值列，MySQL 表必须 InnoDB。每个交易日一个事务，失败回滚当日；已完成的前序交易日不回滚。已有完整记录保留原样；部分结果、来源不符、汇总与原始成员不一致、并发冲突明确报错，不覆盖、不拼接。修复应先人工核实，不要直接删除数据来绕过检查。

估值脚本重新执行时，按指数代码及计算版本查询汇总表最后日期，只校验该日汇总、300条成分明细和日期记录，然后采集其后且处于请求区间内的交易日。空库从指定起点开始；已到请求截止日则不再采集。最后日期之前的旧缺口或异常不扫描、不修订，手动指定更早起点也不会绕过该续采日期。市场脚本仍逐日扫描请求区间缺口。预览不连接数据库，因此从请求起点采集，受显式整数 `max_days` 限制；默认 `None` 预览整个固定区间。错误信息不打印底层连接字符串或原始 SQL 参数；SQL echo 强制关闭。

估值补采兼容 Notebook 全局变量、`jqdata` 模块及平台 `builtins` 注入的研究接口；缺少接口会直接显示接口名。日期、类型及聚合校验显式调用 Python 内置函数，避免研究单元格中 NumPy 同名函数覆盖。未知异常会显示当前日期、执行阶段、异常类型、脚本内函数/行号和可识别的 MySQL 数字错误码，不显示底层异常原文或数据库凭据。若失败，完整重新执行更新后的脚本，将这一行诊断反馈即可；不需要清空已有数据。

## 离线验证范围

`backend/tests/test_recovered_joinquant_history.py` 使用假 jqdata 和 SQLite 验证数值、Python 3.6 语法、懒加载配置、日历覆盖、原始成员完整性、逐日提交、独立补洞和热度日志隔离。未连接真实聚宽或 MySQL；实际上游历史可用区间和平台版本须在聚宽预览确认。发生缺源时不会编造替代值。

当前离线用例还覆盖模拟 MySQL 反射模式（InnoDB、主键顺序、字段集、NULL、精度、符号），以及在第 101 个成分写入时注入异常，确认汇总、成员、日历和同步日志共同回滚。该验证不能替代真实 MySQL/聚宽联调。
