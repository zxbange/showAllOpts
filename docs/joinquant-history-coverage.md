# 聚宽历史采集与恢复范围

这份清单说明实际入口、目标数据和恢复边界。它不表示已经在真实聚宽账号或生产 MySQL 上跑完全部历史。聚宽账号权限、接口覆盖、历史修订和平台限额需要在研究环境预览确认。当前可见的修订历史不等于过去当时保存的原始快照。

所有可写入口只从同目录 `mysql_connector.py` 获取自定义数据库配置，脚本之间不互相调用。不要把密码、令牌或研究结果提交到仓库。新数据库需先存在，建表权限由用户配置；不兼容的旧表应先核对，不能通过删除原始记录绕过检查。

## 已有入口与历史恢复

| 功能 | 聚宽入口 | 数据恢复与边界 |
| --- | --- | --- |
| ETF 份额/收盘/市值 | `ETF历史补采_聚宽研究版.py` | 固定研究基金集合按最早上市日起扫描，逐来源覆盖标记、分窗口事务、只补缺；未知历史份额不补零。见 [说明](etf-joinquant-history.md)。 |
| 行业动量 | `行业动量计算_数据库版.py` | 日常与完整历史模式分别配置，历史成员和20日行情预热必须完整；见[历史说明](industry-breadth-history-recovery.md)。 |
| 市场热度与抱团拥挤度 | `市场情绪历史补采_聚宽研究版.py` | 分别扫描每个历史缺口；热度严格MA20预热与停牌/上市期校验；拥挤度保留停牌零成交额数量口径。已有结果不覆盖。见 [说明](joinquant-market-valuation-history.md)。 |
| 微盘温度计 | `微盘温度计_数据库版.py` | 保留原2021基点序列，最早可计算历史写独立归档序列，不能拼接改变原百分位基点。见 [说明](microcap-history-recovery.md)。 |
| 微盘新高新低 | `微盘新高新低数量统计_数据库版.py` | 完整历史必须核验历史股票池、价格窗口和实际不足样本；源失败不作无样本。见[历史说明](industry-breadth-history-recovery.md)。 |
| 净利润断层 | `净利润断层_数据库版.py` | [历史报告期模式](earnings-gap.md)按当前可见修订财报重建，按披露日限制、逐报告期断点；不是历史未修订公告全文。 |
| 高股息选股、高增长 | 对应独立数据库版脚本 | 最新结果继续原规则；历史重建写独立 `revised_asof` 档案，记录规则和来源、缺口与状态，不覆写最新快照，不能宣称原始PIT。见 [说明](selection-history-recovery.md)。 |
| ETF/LOF 动量热度 | `ETF动量热度_数据库版.py` | 原混合日常算法保留且不再删除旧结果。仅显式 ETF-only 历史写独立档案，不冒充混合图表；LOF历史分类版本无法核实，完整混合恢复跳过。见 [说明](etf-momentum-history-recovery.md)。 |
| 个股机构持仓 | `个股机构持仓_数据库版.py` | `history_mode='all'` 按可见报告身份和历史股票池包含已退市股票，不限最近5年；未解析符号保留未完成证据。见 [说明](ownership-history-recovery.md)。 |
| 创红比/科创红利比 | `创红比历史补采_聚宽研究版.py` | 原始指数399006/000688/000922，完整平台日历、不按指数上市日裁掉回溯；MySQL归档→页面“同步聚宽历史”→SQLite。页面既有2018/2020展示边界保留。见 [说明](growth-dividend.md)。 |
| 估值标尺 | `估值标尺历史补采_聚宽研究版.py` | 2010起逐日真实沪深300成分及PE-TTM，正值等权、负值剔除但保存原值，零/空/缺项阻断；MySQL→页面同步→SQLite，双源重叠对照不覆写。见 [功能说明](valuation-ruler.md)与[历史说明](joinquant-market-valuation-history.md)。 |

十个传统策略仍可使用 `策略批量采集_数据库版.py`；新专用历史入口不需要上传批量文件。历史归档返回的新增日数、待续跑、缺口和来源状态，与最新选股条数不同，控制台分别显示。日常参数不能自动当作全历史参数。

## 缓存及网页入库闭环

- MySQL结果型模块使用页面右上角“数据同步”。更换数据库后保存连接，再同步所需模块。
- 抱团拥挤度旧缓存仍以日期边界增量。若在已有最早/最晚日期之间补洞，务必选择该模块并勾选“完整重新同步”，不能仅凭普通同步成功判断中间缺口可见。全新数据库首次同步读取完整表。
- 行业动量、微盘新高新低、热度、微盘温度计、ETF动量使用结果日志；旧采集器未提供日志时核对完整主键清单，确保中间补缺可见。机构持仓与净利润断层沿用其专属同步版本协议。
- 创红比和估值标尺由专门只读MySQL桥导入SQLite，不进入普通结果表缓存。仅脚本写入成功不表示网页已导入。
- 所有来源缺失、冲突或权限错误应保留此前成功结果；HTTP 202或“任务已启动”不是数据恢复成功。

## 按用户要求跳过的功能

- 两融平均担保比例、A00铝价、CCI煤价：未验证聚宽有与项目一致的指标，不用普通价格或余额替代。
- 微博/雪球监测、账号及个人持仓：不是聚宽公共历史行情数据，不新增替代源或迁移任务。
- 奶牛股：聚宽 `STK_XR_XD.bonus_amount_rmb` 与登记/除权日期不足以证明和项目“已实施现金分红总额、分红对象与每股调整、扣非归母利润”完全等价；未验证部分明确跳过。不能用税前分红乘当前总股本猜现金总额。
- ETF混合池的LOF历史分类、过去原始未修订选股快照：未证明可重现，不能把今天主档或事后修订冒充原始时点数据。

## 验证范围

仓库离线测试覆盖模拟源、日期/字段/精度、事务中断、重复执行、原数据保留和恢复。没有真实聚宽/MySQL全历史联调证据；源缺失期间不能宣称已补齐。部署前仍须通过全部相关后端、前端和共享内嵌同步检查，不能削弱门禁。
