# 机构持仓全历史补洞

独立脚本只需同时上传 `mysql_connector.py`。设置机构持仓配置 `history_mode: 'all'` 或执行 `run(history_mode='all')`。批量脚本对应配置相同，也可传 `options={'个股机构持仓': {'history_mode': 'all'}}`。默认 `recent` 保留现有增量行为。全历史模式不受 `history_years` 的 5 年默认值或 20 年上限限制。

全历史通过三个既有财务源的 ID 去重分页索引发现账号可见的全部报告日期和股票身份，不按今天在市股票筛选。十大流通股东保持 `change_reason_id=306019` 和 `sharesnature_id=308007` 原口径。公募保留完整报告优先、披露版本及基金份额归并规则；报告的 `pub_date` 必须截至运行日期已公布，户数保留原有空发布日期语义。公募的裸证券代码只通过历史报告日股票池及两类股票源身份解析，不根据代码前缀猜交易所；无法确认的符号记录在 `ownership_disclosure_probe/history-scope` 的 `unresolved_symbols`，不能宣称这些符号已恢复。包括境外证券在内的未确认符号不生成 A 股记录。

新出现的退市股票元数据以证券代码为显示名、行业为空，避免把今日名称/行业伪装成历史分类。已存在股票元数据不修改。历史名称/行业不是本次恢复的承诺。

每个报告期/户数期单独事务并沿用原有 sync head/change journal。重复运行重新核对源索引与库内主键，恢复中间缺口，不依赖最大日期水位；失败重跑即可。已存在报告和户数记录原样保留（不会用空查询覆盖已确认数据），不生成零值。报告期断点只是完成记录，不是跳过缺口的依据。此模式不替代日常新增披露刷新；不会推进正常 `main` 披露探针。已有记录内部缺失分类仍走原有分类修复/日常刷新机制，不在插入式恢复中覆盖。

`history-scope` 分源记录实际首末可见日期。`verified_empty_visible_scope` 仅表示本次账号、发布日期范围及原口径过滤下成功查无记录，不等于聚宽自建库以来没有数据。接口异常、权限不足、缺少表直接失败，不伪装成空数据或支持完成。没有可核实的统一历史起始年，不能把 A 股上市起点、账号可见最早日期或某张表最早日期当作所有来源的保证。季度基金披露仅覆盖披露持仓；半年报/年报口径不同；不恢复未公开持仓或交易记录。

测试采用真实 SQLite 查询模拟聚宽财务接口，覆盖 1995 年已退市股票户数、未来披露排除、重复运行、确认值保护、中间缺口重建及源异常。不意味着已使用真实聚宽账号运行全量或已导入生产数据库。

这些历史报告按本次聚宽账号当前可见数据重建，可能包括事后修订。发布日期过滤防止使用明确晚于截止日的披露，但不等于已恢复每个过去时点的原始未修订数据库快照。新增补采不覆盖既有已确认记录。
