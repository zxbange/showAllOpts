# 抱团拥挤度：采集与展示

> 默认启用本地缓存：采集入库后，等待每天北京时间 18:00 自动同步，或在网页“数据同步”/服务器命令中手动同步。页面刷新读取当前快照，详见[本地缓存说明](local-cache.md)。


本模块将原聚宽程序的每日「前 5% 股票成交额占比」写入 MySQL，并在首页及侧边导航增加抱团拥挤度入口。网页只读数据库，采集仍在聚宽研究环境运行。

## 计算口径

每个交易日用 `get_all_securities(types=['stock'], date=当天)` 获取当时的股票列表，再用 `get_price` 获取同一天的日成交额 `money`。

- 股票总数为 N，取 K = max(floor(N × 0.05), 1)。
- 按当日成交额降序，选取前 K 只股票。
- 原始占比 = 前 K 只股票成交额合计 / 全部股票成交额合计。
- `TOP_PCT = 0.05` 保持不变。股票范围沿用原程序返回的列表，不另行添加上市期限、ST、停牌或交易所过滤；零成交额股票计入 N。
- 入库比例范围为 0～1，页面乘以 100 显示百分比。区间变化以「百分点」显示，统计卡片全部使用原始占比。
- 少于 100 只股票、缺失/负数/非有限成交额、股票列表不完整、重复股票、日期不一致、总成交额为零时停止，不写入失真的数值。

原程序对异常和空数据直接跳过。新版本会停止并提示失败日期；已提交的日期保留，修复后重跑从最后已提交日期继续。聚宽接口权限、请求限额或行情尚未就绪也可能使采集停止。

## 聚宽运行方法

仓库提供脱敏模板 [抱团拥挤度_数据库版.py](../collectors/抱团拥挤度_数据库版.py)，复制到聚宽私有研究目录。在其中 `MysqlCrowding` 类填写 host、port、dbname、dbuser、dbpassword，指向网页所读取的同一个数据库。该独立文件沿用现有入库脚本的 `mysql+mysqldb` / SQLAlchemy 连接方式，不读取网页项目的 `config/app.config`。

默认参数：

```python
START_DATE = '2020-01-01'
END_DATE = None
TOP_PCT = 0.05
```

`END_DATE=None` 是动态日期标记，**每次调用 run() 时**取北京时间当天；不是空日期查询，也不会在第一次导入后固定日期。启动输出会打印本次实际起止日期。使用统一参数名 `end_date`，不使用 `end_data` 拼写。

在 Notebook 中粘贴整个文件，或上传文件后执行：

```python
%run -i 抱团拥挤度_数据库版.py
```

本地工作区的 `original/抱团拥挤度_数据库版.py` 已沿用原行业动量脚本的私有连接参数；该目录不属于 showAllOpts Git 仓库。GitHub 仅有占位配置，真实账号密码不要提交。

首次自动创建 `market_crowding` 表；当前 TOP_PCT 没有记录时，从 2020-01-01 采集至当天。后续运行仅查询当前 TOP_PCT 的最新日期（按日期倒序取一条，使用现有复合主键），再获取该日期（含）至当天的交易日历与行情，不再读取全部已有日期或扫描历史缺口。包含最新日期以刷新上次盘中快照；若指定 start_date 晚于最新日期，则以该 start_date 为下限。按交易日单独提交；替换失败则回滚该日旧数据。首次多年回填可能较慢，受聚宽配额和数据库网络情况影响，失败后可再次运行。

建议收盘且聚宽日行情就绪后运行。盘中采集可能得到未完结的当天成交额，页面不宣称它已收盘；下一次重跑会刷新最后一天。已有更早历史值若被数据源修订，不会自动全部重算，可用 `run(start_date='YYYY-MM-DD', end_date='同一天', incremental=False)` 刷新指定交易日。不要同时运行多个采集实例。

增量模式的日期查询等价于：

```sql
SELECT trade_date
FROM market_crowding
WHERE top_pct = 0.05
ORDER BY trade_date DESC
LIMIT 1;
```

这会减少读取与传输的历史日期数量；行情采集、逐日事务写入和网络延迟仍会影响总耗时。原版本也只读取日期列，历史仅几千行时性能提升通常有限。数据库已有表时仍有建表检查，日期查询的一次 SELECT 不代表整个程序只有一次数据库操作。

**本模块默认完整保留从 2020 年以来的数据，不执行 180 个交易日删除。** 行业动量的清理只操作 `industry_momentum` 表，不影响本模块。一次记录对应整个市场，不按行业拆分，因此使用趋势图和成交额占比条展示。

## 表结构与权限

| 列 | 类型 | 含义 |
| --- | --- | --- |
| top_pct | DECIMAL(8,6) | 前几成股票，本模块为 0.05 |
| trade_date | DATE | 交易日期 |
| ratio | DECIMAL(18,10) | 原始成交额占比 |
| top_money | DECIMAL(24,2) | 前 K 只股票的成交额合计，元 |
| total_money | DECIMAL(24,2) | 全部股票成交额合计，元 |
| stock_count | INT | 股票数量 N |
| top_stock_count | INT | 选取数量 K |
| updated_at | DATETIME | 本次计算时间，北京时间 |

复合主键为 `(top_pct, trade_date)`，同时保证幂等和支持按 TOP_PCT + 日期范围的索引查询，无需为新表重复增加同列索引。采集使用有 SELECT、INSERT、DELETE 和首次 CREATE 权限的账号；网页账号只需该表的 SELECT 权限。若网页账号原先仅能访问 `industry_momentum`，须由数据库管理员补充新表 SELECT 权限。网页不会建表或执行数据迁移。

新表的模型、查询、业务统计、接口定义各自放在 backend 的 models / repositories / services / schemas / api/routes；前端拥有独立的页面、图表和 API 类型。

## 网页展示与接口

入口：`/market-crowding`。展示最新占比、最新入库日、前 K / N 只股票、成交额、区间最高/最低/均值及百分点变化。曲线支持 30 / 90 / 180 / 365 个自然日和全部历史，默认一年，区间终点为最新入库日；底部滑块可缩放。

`GET /api/v1/market-crowding/history?days=365`

- `days` 支持 0、30、90、180、365，0 表示全部；固定读取 TOP_PCT=0.05。
- 可传 `end_date=YYYY-MM-DD` 查看截至历史日期的数据，拒绝未来日期。
- 一次 SELECT 读取从 2020 年至查询结束日的日记录，同时生成最新值、统计及曲线，减少公网数据库往返。
- 返回原始比例 `ratio` 和平滑比例 `smoothed_ratio`，两者均为 0～1；`change_pp` 已是百分点。
- 空表返回 200 和空数据；表尚未创建、连接失败或权限不足返回统一 503，界面支持重试；非法参数返回 422。
- 数据库没有独立交易日历，网页仅展示实际存储日期，不把周末或缺失日期填零，也无法仅凭该表区分节假日与采集缺口。默认增量模式不会自动修复早于最新日期的历史缺口；需要补录时，明确传入起止日期和 `incremental=False`，将重算并替换指定区间的所有交易日。

平滑线采用原程序的备用算法 `ewm(span=10, adjust=True)`，可取消勾选。每次使用完整已存历史计算，再裁剪显示范围，因此切换范围不会改变同一天的平滑值。平滑仅用于展示，不写入数据库。

原程序优先使用 Savitzky–Golay 平滑，其中心窗口及拐点识别依赖后续日期，新增数据可能改变历史局部结果。本模块统一使用只依赖当前及过去数据的 EMA 10，不复制该平滑算法及拐点箭头。原始指标口径保持一致，原始线、最新值标记及区间均值参考线同时可见。

## Linux 已部署项目升级

先在聚宽完成建表和至少一天入库，并确认网页只读账号有新表权限。服务器以当前部署账号执行：

```bash
cd /home/ubuntu/showAllOpts
git pull --ff-only
bash scripts/build.sh
sudo rsync -rlt --chmod=D755,F644 frontend/dist/ /var/www/showallopts/
sudo systemctl restart showallopts-api
sudo systemctl status showallopts-api --no-pager
curl -fsS 'http://127.0.0.1:8000/api/v1/market-crowding/history?days=30'
```

本功能未增加运行依赖。以上适用于现有依赖已安装的 systemd + Nginx 部署；新环境按 [Linux 部署指南](linux-deployment.md) 安装。保留现有 `config/app.config`、systemd 覆盖配置及 Nginx 自定义端口，不必更改代理规则。浏览器仍用原访问地址，首页会出现新模块；若仍显示旧版请刷新页面。Docker 环境重新构建镜像后启动即可。
