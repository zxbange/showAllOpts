# 聚宽单文件批量采集

`collectors/策略批量采集_数据库版.py` 将五个数据库版策略嵌入一个 Python 文件。只需上传这个文件到聚宽研究环境，无需额外上传其他策略文件或安装网页项目。兼容 Python 3.6 语法，沿用已有聚宽、pandas、SQLAlchemy 和 MySQLdb 环境。

## 使用方法

1. 下载单文件，在聚宽私有副本顶部的 `DB_CONFIG` 填写连接信息；五个策略统一使用这套配置。不要把真实配置提交到 GitHub。
2. 将文件上传聚宽研究环境，在 Notebook 单元格执行：

   ```python
   %run -i 策略批量采集_数据库版.py
   ```

   也可以将完整文件内容直接粘贴到单元格执行。`-i` 用于沿用 Notebook 提供的聚宽 API。
3. 查看控制台日志和末尾汇总。全部成功时，`batch_summary` 是逐策略结果列表，包含策略名称、状态、处理条数、耗时和异常类型。

本地 `original/策略批量采集_数据库版.py` 是已填好本机现有连接配置的私有副本，位于 Git 仓库之外；GitHub 只发布占位配置版。不要在部署服务器直接运行此脚本，它依赖聚宽研究环境。网页后端继续只读数据库，无需为此重新发布网页。

## 执行顺序与数据规则

默认顺序为：**行业动量 → 抱团拥挤度 → 微盘温度计 → ETF份额 → 净利润断层**。同一时间只执行一个策略；每个策略拥有独立命名空间，避免 `run`、`Base`、日期参数和其他同名对象相互覆盖。

| 策略 | 原有采集、清理规则 |
| --- | --- |
| 行业动量 | 先清理整张表 180 个交易日前的数据，再从该分类最新入库日（含）续跑 |
| 抱团拥挤度 | 从当前 TOP_PCT 最新入库日（含）续跑，保留完整历史 |
| 微盘温度计 | 保留 2021-01-01 起、每 5 个交易日采样；重算最新一期并继续，保留历史 |
| ETF份额 | 首次最近 300 个交易日；每只基金独立续传并回查最近 5 个交易日；保留历史 |
| 净利润断层 | 重查最新已结束季度，整批替换该季度结果；保留其他季度 |

整合不改变各策略的唯一键、事务和增量规则，也不增加“内容相同跳过写入”的优化。日志中的条数包含覆盖更新，不等于数据库净新增条数。各策略 `run()` 的默认参数仍然有效，`end_date=None` 在执行该策略时取北京时间当天。

## 日志与失败处理

控制台和文件同时输出标准日志，每行包含北京时间、级别、批次编号及策略名称，例如：

```text
2026-10-17T17:00:00.000+08:00 | INFO    | run=20261017-170000-example | 行业动量 | ========== [1/5] 开始 ==========
2026-10-17T17:00:03.000+08:00 | INFO    | run=20261017-170000-example | 行业动量 | 2026-10-16 计算并入库完成，共 124 个行业（含零分行业）。
2026-10-17T17:00:03.100+08:00 | INFO    | run=20261017-170000-example | 行业动量 | ========== 成功 | 本次处理/写入 124 条（含覆盖） | 耗时 3.10 秒 ==========
```

默认文件为研究环境当前目录下的 `log/collector-batch-YYYY-MM-DD.log`。同一天多次运行追加保存，使用批次编号区分；跨北京时间午夜自动切换日期文件。日志不会自动删除。可在文件顶部修改 `LOG_DIR`。这些是聚宽采集日志，与 Linux 网页项目的 `log/app.log` 独立。

- 保留各策略原有逐日、逐窗口输出；标准错误输出标记为 WARNING，捕获到的失败标记为 ERROR。
- 文件和控制台均脱敏数据库主机、库名、用户名、密码及其 URL 编码形式；异常不打印局部变量或源代码行。
- 普通异常发生后，记录失败策略并继续后续策略。最终打印五个策略的结果表和总耗时。
- 有失败时，汇总后默认抛出 `BatchRunError`，避免部分成功被误认为全部成功。异常的 `summary` 属性保留逐策略结果；失败策略的条数标为“未完成”，已提交数量以过程日志为准。
- **不是整个批次一起回滚**：各策略已成功提交的数据仍然保留；行业动量已提交的过期清理也不会因为后续失败而撤销。修复后按原策略增量规则重跑。
- 用户中断（如 Notebook 中断执行、KeyboardInterrupt）会停止整个批次，不继续后续策略。
- 同一日志目录通过文件锁阻止批量入口重叠运行，进程退出自动释放。不要删除或替换运行中的锁文件；锁文件留存不表示仍有任务运行。此锁不覆盖直接运行的旧单策略脚本、不同日志目录或不同研究容器，所以仍不要同时启动这些任务。
- 日志目录不可写时，在运行策略前就停止。

## 只重跑失败策略或传入参数

最简单的方式是先编辑文件顶部的 `STRATEGY_ORDER`，只保留需要执行的名称，再运行整个文件。已有 Notebook 已加载入口后，也可以调用：

```python
# 只重跑这两个策略，仍按给出的顺序串行执行
batch_summary = run_all(strategy_names=['ETF份额', '净利润断层'])

# 默认允许各策略继续执行；结束时不抛出批次失败异常，供手动检查结果
batch_summary = run_all(raise_on_failure=False)
```

参数通过顶部的 `STRATEGY_OPTIONS` 或 `run_all(options=...)` 传入，参数名与独立策略的 `run()` 一致。例如只采集沪深300 ETF：

```python
batch_summary = run_all(
    strategy_names=['ETF份额'],
    options={'ETF份额': {'groups': ['hs300']}},
)
```

只有最后一个参数示例限制了采集范围；常规使用保持 `STRATEGY_OPTIONS = {}` 即可。不要随意改变微盘温度计起始日期、数量或采样步长，这些参数会生成不同的序列编号。

## 维护方式

独立策略仍保留为业务逻辑源文件，批量入口由构建脚本生成，避免手工维护两套算法。修改任一独立策略或 `scripts/collector_batch_template.py` 后执行：

```bash
python scripts/build_collector_batch.py
python scripts/build_collector_batch.py --check
```

生成器只读取仓库内已脱敏源码，不读取 `original`、`config/app.config` 或 `backend/.env`。生成后发布新的批量文件，并在聚宽私有副本顶部填写连接配置；不要手动修改嵌入的 `_SOURCES`。离线测试验证嵌入源码与五个独立策略一致、Python 3.6 语法、串行执行、异常继续、命名空间隔离、日志脱敏、按日切换和互斥；实际行情权限及 MySQL 连通性仍需在聚宽运行时验证。
