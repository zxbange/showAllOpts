# 聚宽单文件批量采集

`collectors/策略批量采集_数据库版.py` 包含十二个完整策略，依次串行调用。依赖统一在文件开头导入，参数按策略集中配置；数据库连接、重试、会话回滚关闭和日期转换共用一套实现。每个策略保留独立模型和计算函数，代码直接定义在文件中，不把源码存成字符串，也不使用 `exec` 动态执行。

**运行时不读取其他策略文件、配置文件或日志文件，不使用 `__file__`，也不创建日志或锁文件。** 仍需聚宽研究平台自带的 API，以及 numpy、pandas、SQLAlchemy、MySQLdb 等常规 Python 依赖；数据库通过网络连接。

## 运行方法

1. 打开单文件，在顶部 `DB_CONFIG` 填写真实数据库连接。十二个策略共用这套配置；不要将真实值提交到 GitHub。
2. 将完整代码粘贴到聚宽 Notebook 单元格执行即可，无需上传另外十二个策略文件。
3. 也可以只上传这一份文件，然后执行：

   ```python
   %run -i 策略批量采集_数据库版.py
   ```

   `-i` 沿用 Notebook 中提供的聚宽 API。入口也会从 `jqdata` 和内置命名空间读取平台接口。
4. 查看每个策略完成后的结果和末尾汇总；`batch_summary` 保存名称、状态、条数、耗时、脱敏错误信息；高股息和高增长条数是当前结果数量，机构持仓为实际新增或更新条数，其余为实际新增条数。

本机 `original/策略批量采集_数据库版.py` 已同步完整实现，并保留原有私有数据库连接，位于 Git 仓库之外。GitHub 只发布占位配置版本。采集脚本需在聚宽研究环境运行，Linux 网页后端继续读取数据库；仅修改采集参数/进度无需部署网页，新增高股息模块需要按 README 重建前端并重启后端。

## 顶部集中配置

日常调整只需要查看文件开头的配置区：

| 配置 | 用途 |
| --- | --- |
| `DB_CONFIG` | 十二个策略共用的数据库地址、端口、库名及凭据 |
| `DB_OPTIONS` | 连接超时、连接重试次数/间隔、连接池回收时间 |
| `PROGRESS_ENABLED` | 默认 `True`，显示每个策略的控制台进度条 |
| `PROGRESS_INTERVAL_SECONDS` | 默认 `5.0`，等待接口/数据库时的进度刷新间隔（秒，须为有限正数） |
| `STRATEGY_CONFIG` | 按策略配置起止日期、计算参数、分页大小、ETF 名单等 |
| `STRATEGY_ORDER` | 执行哪些策略以及执行顺序 |
| `STRATEGY_OPTIONS` | 可选的 `run()` 参数覆盖，通常保持 `{}` |
| `PREVIEW_ROWS` | 每个策略在控制台预览多少条结果数据，默认 5；0 为不预览 |

`STRATEGY_CONFIG` 的默认值保持原采集口径：

- 行业动量：`start_date='2025-01-01'`、`industry_type='sw_l2'`、`retention_trade_days=180`。
- 市场情绪跟踪：`end_date=None`、`batch_size=300`、`window_size=40`；保留最近三年。
- 抱团拥挤度：`start_date='2020-01-01'`、`top_pct=0.05`。
- 微盘温度计：`start_date='2021-01-01'`、`micro_num=1000`、`sample_step=1`、`batch_size=1000`。
- ETF 份额：`start_date=None`、`initial_trade_days=300`、`window_size=120`，`funds` 保存两组跟踪名单。`lookback_days` 兼容原接口，在只新增模式下不回查覆盖。
- 微盘新高新低：首次近 180 个自然日、`micro_num=400`，每天采样，后续只新增并保留历史；配置组包含 `initial_days`、`batch_size`、`price_batch_size`。详见 [微盘新高新低说明](microcap-breadth.md)。
- 高增长：`end_date=None`、`batch_size=100`、`page_size=2000`；累计归母净利润与基本 EPS 四类报告筛选，规则见 [高增长说明](high-growth.md)。
- 高股息选股：`end_date=None`、`batch_size=300`、`page_size=2000`；两组 Top25，规则和最新结果更新见 [高股息选股说明](dividend-selection.md)。
- 净利润断层：自动筛选最新已结束季度，`page_size=1000`。

各策略 `end_date=None` 均表示**每次运行时**计算北京时间当天，不在导入时固定日期。需要修改参数时，例如：

```python
STRATEGY_CONFIG['行业动量']['industry_type'] = 'sw_l2'
STRATEGY_CONFIG['净利润断层']['page_size'] = 500
batch_summary = run_all()
```

每次调用都会读取一份新的策略配置快照，修改配置后重跑即可生效。调用 `run_all(options=...)` 时，这次传入的选项替代 `STRATEGY_OPTIONS`；其中 `run()` 参数优先于分组默认配置。分页/窗口等内部参数请直接修改 `STRATEGY_CONFIG`，不要作为 `run()` 参数传入。原六个策略的 `skip_existing=True` 固定开启，不能通过配置关闭；高股息选股和高增长每次替换最新结果。

连接重试仅用于建立连接，默认最多 5 次、间隔 10 秒；不会自动重放写入事务。各策略独立创建和释放连接。机构持仓一次运行内复用同一连接池与 Session 工厂，只检查一次表结构；各阶段仍使用独立会话，成功、失败和中断均关闭会话并最终释放连接池。公共会话管理只负责异常回滚与关闭，提交时点仍由对应策略决定。不同用途的数值转换保留原精度，例如微盘指标使用 Decimal，未强制统一成浮点数。

## 执行顺序与数据规则

默认顺序为：**行业动量 → 抱团拥挤度 → 市场情绪跟踪 → 微盘温度计 → ETF份额 → 净利润断层 → 微盘新高新低 → 高股息选股 → 高增长 → ETF动量热度 → 个股机构持仓 → 短线选股**。同一时间只执行一个策略；每个策略拥有独立命名空间，避免 `run`、`Base`、日期参数和其他同名对象相互覆盖。

原六个策略固定传入 `skip_existing=True`，只写入业务主键尚不存在的数据，不再覆盖最新一天或 ETF 回查窗口。已有行即使源数据发生变化也保留原值。

| 策略 | 批量入口的采集、清理规则 |
| --- | --- |
| 行业动量 | 先清理整张表 180 个交易日前的数据，再从该分类最新入库日之后采集；已有日期不重算 |
| 市场情绪跟踪 | 全市场站上 MA20 比例，分窗口回填最近三年，只补缺失日期并清理三年前数据 |
| 抱团拥挤度 | 从当前 TOP_PCT 最新入库日之后采集，保留完整历史 |
| 微盘温度计 | 2021-01-01 起逐交易日检查、补采缺口；复用旧五日原始指标，重新衔接每日分位与指数；保留历史 |
| ETF份额 | 首次最近 300 个交易日；每只基金从自己的最新入库日之后续传，不再回查或覆盖最近 5 日；保留历史 |
| 微盘新高新低 | 首次近 180 个自然日；从最新入库日之后每天采样，缺失数据时停止，已有日不覆盖；保留历史 |
| 高增长 | 每次重算截至当天的最新名单，四类报告全部通过；事务替换、失败保留旧名单、相同结果跳过写入 |
| 高股息选股 | 每次重算最近完整交易日，两组各最多 25 只，事务替换最新结果；不保留历史；相同结果不重复写库 |
| 净利润断层 | 扫描最新已结束季度中尚未入库的股票；按“报告期＋股票代码”只新增，已入库股票保留首次快照，不覆盖、不删除 |

高股息选股和高增长的条数是当前选股结果数量，其他策略条数是实际新增业务记录数；没有新增数据会输出“无新增数据（已有记录跳过，或本次尚无可入库数据）”。唯一键仍用于兜底；如果其他独立任务并发抢先写入导致冲突，该事务回滚后报告失败，不通过删除旧记录解决冲突。

净利润断层的市值、PE、PB、信号日期及公告信息保留首次入库时的值，不随以后运行刷新。其 `earnings_gap_run` 运行元数据仅在扫描截止日、累计股票数等内容变化时更新，重复运行且内容不变时也不写入；汇总中的新增条数只统计股票明细。页面的扫描截止日不代表每只股票的估值日期，应以股票自身的 `valuation_date` 为准；“命中数”表示该季度累计保留数量，不是当次重新筛选的数量。

行业动量、抱团拥挤度和微盘温度计在只新增模式下，北京时间 16:00 前不写当天日数据，避免盘中快照被永久保留。净利润断层沿用已有完整交易日规则；ETF 以数据源实际发布为准。历史已写入的不完整值或源后续修订不会自动纠正，微盘温度计会检查并补齐历史缺口，行业动量和抱团拥挤度仍从最新日期续传。

独立历史采集策略的 `run()` 默认也使用 `skip_existing=True`；高股息、高增长和机构持仓沿用各自的最新快照或披露更新规则。常规任务使用模块化批量入口即可，不要再同时运行旧版单策略脚本。原六个策略不允许通过参数关闭 `skip_existing`；高股息选股和高增长不接收该开关，每次重算并替换最新结果。

## 控制台进度、结果与失败处理

入口不生成日志目录或日志文件。默认显示当前策略序号/名称、进度条、已处理/待处理数量、当前日期或基金、采集阶段和耗时；进度独立于被屏蔽的第三方输出，避免长时间没有反馈。每个策略完成后显示名称、成功/失败、实际新增条数和耗时，并预览最后 5 条新增数据的关键字段；没有新增数据时明确提示。高股息选股和高增长展示当前结果数量，不标为新增条数。字段名和单位沿用各策略：ETF `shares` 为份，温度计 `score` 为原始 0–1 分值。设置 `PREVIEW_ROWS = 0` 可关闭数据预览，只看汇总。

```text
【1/8 行业动量】交易日 [##########----------] 90/180 50% 2026-06-01 | 获取行业成分及行情，计算动量 | 已用 125s
【行业动量】成功：新增 124 条，耗时 3.10 秒。
本次结果预览（最后 5 条，字段单位沿用策略）：
...
【净利润断层】成功：新增 0 条，耗时 2.20 秒。
无新增数据；已有记录跳过，或数据源尚无可入库数据。

采集结果汇总
策略 | 结果 | 条数（高股息/高增长为当前结果，其余为新增） | 耗时（秒）
行业动量 | SUCCESS | 124 | 3.10
...
净利润断层 | SUCCESS | 0 | 2.20
成功 8，失败 0。
```

- 行业动量、抱团拥挤度、微盘新高新低按待采集交易日显示进度，微盘温度计按待补齐／修复的交易日显示；日期循环体处理完毕才增加完成数。
- ETF 按基金显示进度，同时显示当前采集窗口及日期范围。基金已是最新也算“已处理”，不等于新增入库；失败基金在最终结果中标记失败。
- 净利润断层先显示公司映射/快报/预告的已读取条数（分页总数未知时不虚构百分比），再显示正式财报批次、股票筛选和入选股票估值批次进度。
- 默认每 5 秒刷新，计数阶段开始/结束会立即刷新。即使接口或数据库请求尚未返回，也会刷新当前阶段和累计耗时；这表示程序仍在等待，并不表示已经收到新数据。后台线程只刷新文字，行情读取、计算和写库仍串行执行。
- `PROGRESS_ENABLED = False` 可关闭进度，保留结果和汇总；`PROGRESS_INTERVAL_SECONDS = 10.0` 可降低刷新频率。采用标准控制台文字进度条，无需安装 tqdm 或 Notebook 小组件，不读取外部文件。不同 Notebook 前端可能保留多条刷新输出。
- 进度条的 100% 表示该阶段的任务已处理，不等于整个策略成功；以最终成功/失败和实际新增条数为准。无新增数据会正常结束；失败或中断不强行补成 100%，刷新线程随策略结束而停止。
- 普通异常在控制台展示脱敏后的类型和简要原因，然后继续后续策略；失败策略新增条数标为“未完成”，不会误报为 0。最后默认抛出 `BatchRunError`，其 `summary` 属性保留结果。
- 各策略独立提交事务，**不会整个批次一起回滚**。失败前已成功入库的数据、已完成的过期清理保留，修复后只补新增数据。
- Notebook 中断会停止整个批次，不再执行后续策略。
- 使用内存锁阻止同一 Notebook 内核重叠执行，不读取或创建锁文件。不同 Notebook 内核或研究容器之间不共享此锁，请勿同时采集同一批数据；数据库唯一键继续约束重复记录。
- 网页服务的 `log/` 日志功能不受影响；独立策略直接运行时仍保留原有输出方式。需要本页的统一进度和只新增规则，请统一使用此入口。

## 只运行部分策略或调整参数

可修改入口顶部的 `STRATEGY_ORDER`，仅保留需要的策略，顺序就是调用顺序。例如只执行净利润断层：

```python
STRATEGY_ORDER = ['净利润断层']
```

已通过 `%run -i` 加载入口后，也可以在 Notebook 中调用：

```python
# 只重跑两个策略，按给出的顺序串行执行
batch_summary = run_all(strategy_names=['ETF份额', '净利润断层'])

# 展示汇总，不预览新增数据；有失败时不抛出批次异常，供手动检查
batch_summary = run_all(preview_rows=0, raise_on_failure=False)

# 只采集沪深300 ETF；run() 参数通过策略名称传入
batch_summary = run_all(
    strategy_names=['ETF份额'],
    options={'ETF份额': {'groups': ['hs300']}},
)
```

默认 `STRATEGY_OPTIONS = {}` 保持各策略原参数。不要随意改变微盘温度计起始日期、数量或采样步长，这些参数会生成不同序列，同日期不同序列不属于重复记录。

## 维护方式

市场情绪按历史窗口及股票批次显示进度，每个窗口提交后可续传；已有日期完整时跳过行情请求。详细口径见 [市场情绪跟踪](market-sentiment.md)。

完整策略代码直接位于批量文件内的十二个 `_…_strategy` 函数中。末尾 `STRATEGY_SPECS` 集中登记策略函数、写入模式（只新增／替换最新／更新变化）与预览字段，并生成 `STRATEGIES`；顶部 `STRATEGY_CONFIG` 管参数、`STRATEGY_ORDER` 管执行顺序。后续发布只需更新这一份批量文件。

仓库仍保留独立采集脚本供单独使用；它们不是批量文件的运行依赖。修改业务算法时，需要同步独立脚本和批量文件内对应策略；批量文件中的公共工具只定义一次，独立脚本携带各自所需的同版工具函数。离线测试检查核心计算、选股规则和表结构与独立脚本一致，并验证配置生效、连接重试、会话回滚关闭、无 `__file__` 的 Notebook 执行、无外部策略文件、串行顺序和只新增规则。真实行情权限及 MySQL 连通性仍需在聚宽验证。

## 公共逻辑与采集开销

普通主键分页统一由 `_source_pages` 处理，适用于公告、分红、ETF 资料及机构持仓明细。它检查主键缺失、重复、乱序与游标停滞，并一直读取到空页；即使聚宽返回的行数小于请求上限，也不会提前结束。接口异常直接上报，已有事务规则继续决定回滚范围。相比旧版，ETF 资料可能多一次用于确认结束的空页请求，以避免平台限页导致漏采。

净利润断层的公司映射、快报和预告改为逐页消费，不再先累积完整分页列表。机构持仓仍分批处理明细，只对新增披露影响的股票复查最近四季；基金／报告版本索引继续在查询端分组去重。分组游标和高增长的“报告期＋主键”倒序游标保留专门实现，不与普通主键分页混用。ETF 后续筛选需要完整资料表，因此仍在读取完毕后合并 DataFrame。

有限数值、可空日期与完整日行情截止时间共用工具函数；Decimal 与浮点用途、四舍五入位数、持仓负数校验保持各自口径。短线选股去掉未使用的诊断字典与空 ST 集合，复用补票龙筛选器；ST 和总市值门槛仍在股票池阶段执行。

本次整理不修改选股公式、表结构、历史保留窗口或提交时点。无需清库或重新全量采集；更新聚宽中的脚本后按原入口运行即可。平台接口响应和公网数据库耗时仍取决于实际环境，代码精简不代表采集耗时会同比减少。

## ETF动量热度

已加入默认执行顺序的末尾，`STRATEGY_CONFIG['ETF动量热度']` 配置日期、180日回补窗口、180个交易日保留期（`retention_trade_days`）和30亿元门槛。候选筛选、行情采集和热度计算均在批量文件内，无外部文件依赖；计算完成后写入结果表。每次先按实际运行日清理整张热度表中过期结果（包括退出池的基金），日历异常时不删除；仅在保留区间内按日期+基金新增，不重复写入。最早结果所需的25日预热行情仍会读取，但不入库。候选池在最新结果完整后更新；控制台展示进度。详见 [ETF动量热度](etf-momentum.md)。


## 个股机构持仓与社保新进

新增七类机构披露持仓、股东户数和社保新进筛选，采用 MySQL JSON 存储。聚宽运行 `collectors/个股机构持仓_数据库版.py` 或新版批量采集；首次近五年；之后先检查新增披露，没有变化直接跳过，有变化只复查受影响股票最近四季和户数，有变化才更新。完成后在页面“数据同步”选择“个股机构持仓”。详见 [使用说明](institution-ownership.md)。本模块条数表示新增或更新，不适用已有日期一律跳过的规则。


个股机构持仓默认每页 1,000 条、每批 50 只股票计算和写入，不累积整季源数据或全市场历史 JSON。可在该策略配置中调整 `page_size`、`stock_batch_size`；低内存环境建议 500 / 20，详见 [内存控制](institution-ownership.md#研究环境内存控制)。


个股机构持仓采集器同时维护 `ownership_sync_head` / `ownership_change`，用于项目按变更序号快速同步。本模块内容没有变化时不会推进序号；应用首次升级需建立一次完整基线。不要与旧版机构持仓采集脚本混用，详情见 [同步加速](institution-ownership.md#本地同步加速)。

- 短线选股：串行顺序末尾新增，`end_date=None`、`batch_size=50`，内含补票龙、红悬停龙、蓄力龙三个筛选模块；最近三个交易日完整快照，近30日日K线及均线。详见 [短线选股](short-term.md)。
