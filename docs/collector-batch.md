# 批量策略采集

默认入口为 `collectors/策略批量采集_数据库版.py`，完整粘贴到聚宽研究环境运行。九个模块串行执行，无外部策略文件、配置文件或日志文件依赖；imports和参数集中在顶部。每个模块显示进度、耗时、成功/失败和结果预览，失败后继续其他模块。

## 当前数据链路

**聚宽基础过滤及原始数据采集 → MySQL → 项目每日18:00或手动增量同步 → 本地计算及SQLite结果 → 页面展示。** 七个计算型模块已切换原始快照；ETF份额原本就是原始数据，ETF/LOF热度继续采集行情。完整分工、首次迁移、表名及重复执行规则见 [原始采集与本地计算](raw-pipeline.md)。

独立 `*_数据库版.py` 与批量入口采用相同原始采集协议。旧计算入库版本归档在 `collectors/legacy/`，仅用于旧公式对照，不与新版混用。

## 顶部配置

- `DB_CONFIG`：连接信息只配置一次，仓库仅包含脱敏占位值。
- `STRATEGY_CONFIG`：每个模块的起始日期、采样步长、TOP_PCT等参数。
- `STRATEGY_ORDER`：默认按行业动量、拥挤度、微盘温度计、ETF份额、净利润断层、微盘新高新低、高股息、高增长、ETF动量热度执行。
- `STRATEGY_OPTIONS`：按模块覆盖运行参数。历史采集固定增量，不允许 `skip_existing=False` 或 `incremental=False`。
- `PROGRESS_ENABLED`、`PROGRESS_INTERVAL_SECONDS`：控制台进度开关及刷新间隔，接口等待时也显示耗时。
- `PREVIEW_ROWS`：展示新增/更新原始快照的日期、序列、分片数量和压缩后字节数；0只展示计数。

```python
# 初次迁移可以分模块完成，避免一次采集耗时太长。
STRATEGY_ORDER = ['行业动量', '高增长']
```

七个原始快照模块的汇总条数是新增/更新的日期快照数量，**不是入选股票数量**。高股息、高增长内容不变时为0；最终入选名单在项目同步成功后查看。ETF模块仍统计新增业务记录数。单个模块失败时，已提交日期不会回滚，也不会从头重复写入；修复后重新运行即可续采。

同一Notebook进程通过锁避免重复运行，但不要在多个研究进程同时运行同一模块。源库主键和事务仍作最后保护；并发冲突会明确失败，不能通过删除他人的历史记录重试。

## 默认范围

| 模块 | 初次范围 / 保存方式 |
| --- | --- |
| 行业动量 | 2025-01-01起，但只采集并保留最近180个交易日 |
| 抱团拥挤度 | 2020-01-01起，TOP_PCT不变 |
| 微盘温度计 | 2021-01-01起，每5个交易日采样 |
| ETF份额 | 最近300个交易日，随后逐日积累 |
| 净利润断层 | 最新已结束季度，按完整交易日扫描；首次命中股票冻结 |
| 微盘新高新低 | 近180个自然日，随后逐日积累 |
| 高股息、高增长 | 每次采集最新原始快照；本地重算最新名单 |
| ETF/LOF热度 | 当前候选近180个交易日及预热行情，随后增量 |

初次原始数据采集不能从旧得分恢复，可能比旧版首次运行耗时更久。完成后部署新版项目并手动同步；具体步骤见 [原始数据迁移](raw-pipeline.md#运行与升级顺序)。
