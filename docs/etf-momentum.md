# ETF/LOF 动量热度

入口 `/etf-momentum`。聚宽采集行情并计算热度，写入MySQL结果表，项目同步结果到本地 SQLite，页面直接读取。全部九个策略采用计算后入库模式；本模块不执行买卖。

## 从旧版升级

1. 更新聚宽中的完整 `collectors/ETF动量热度_数据库版.py` 或完整批量采集脚本，填写自己的 `DB_CONFIG`。两者都是单文件，不引用外部策略文件。
2. 在聚宽运行新版采集，补齐 `etf_momentum_heat` 结果，全部候选最新结果完整后将候选池版本更新为 `etf_close_momentum_v3`。已有同日期同基金的结果不覆盖。若之前只采集了原始行情，需在聚宽重新计算缺少的结果。
3. Linux 在项目目录执行 `bash deploy.sh`；Windows 完整关闭旧进程后运行 `start.cmd`。统一同步默认07:00，可在页面保存其他时间；旧默认20:00自动迁移，其他自定义时间保留。
4. 页面“数据同步”选择“ETF动量热度”。同步只下载结果，验证后发布缓存。每天北京时间07:00也会自动同步；聚宽采集需先完成。

本次恢复会使用新的缓存签名，首次需要重新同步结果。旧 `etf_momentum_bar` 和 `raw_*` 表不再读写，但不会自动删除；确认恢复完成后再自行备份处理。应用不向 MySQL 建表或写业务数据。

## 采集参数与候选池

`STRATEGY_CONFIG['ETF动量热度']` 配置 `end_date`、`initial_trade_days`（默认180）、`retention_trade_days`（默认180）、`min_size_yi`（默认30）。北京时间16:00前使用此前已结束交易日；16:00后可采集当天，源数据延迟时稍后重跑。仅运行这一项可设置 `STRATEGY_ORDER = ['ETF动量热度']`。

- ETF 按跟踪指数或明示商品方向去重，取规模最大且严格大于30亿元的产品。
- 加入聚宽上市 LOF 中，能通过基金主体信息确认的国内股票型、混合型产品。每只独立保留，不把不同主动组合强行合并；规模同样严格大于30亿元。
- 跨境仍限原七只 ETF；债券仍仅511220城投债ETF。跨境和债券LOF不纳入，南方原油不再作为例外。
- ETF 使用同日份额×单位净值；LOF 使用六位基金代码对应的已披露 `total_tna`，代表对应份额类别净资产，不是所有份额类别合计，也不是场内流通市值。报告期最多落后180自然日。
- 信息缺失、冲突、未知分类或过旧规模进入审计清单。分类依赖聚宽元数据及名称规则，无法保证覆盖所有产品；研究脚本提供明细核对。详见 [筛选规则](etf-selection.md)。

每次运行先按北京时间当天的聚宽交易日历确定最近180个交易日，清理整张 `etf_momentum_heat` 表中早于边界日的结果，包含已退出候选池的基金；边界日保留。日历不足180期、重复、乱序或包含未来日期时停止，不执行删除。该边界以实际运行日期为准，手动指定历史 `end_date` 也不会恢复过期结果。与行业动量一致，交易日上午运行时当天计入保留区间，但仅采集此前已完成交易日，所以此时最多有179天已完成结果。

清理提交后才筛选和计算；后续采集失败不会恢复已清理的过期数据，仍在保留区间内的旧结果和候选池保留。历史结束日期早于保留边界时，仅清理并返回空结果。

按当前池回补窗口内尚未入库的日期，默认窗口180个交易日；`initial_trade_days` 即使大于180，也受保留边界限制。停采很久后只补保留区间内的缺口，不重新写入过期历史。新入选基金从当前窗口回补，不代表历史当时已入选。退出基金的结果也只保留180个交易日。

为计算最早保留日的热度，仍额外读取此前25个交易日的行情；这些预热行情只用于当次计算，不作为过期热度结果入库。

## 数据表与重复执行

- MySQL `etf_momentum_heat`：主键 `(trade_date, code)`；热度、年化趋势收益率、R²、实际收盘价及更新时间，均由聚宽计算后保存。
- MySQL `etf_momentum_pool`：最新候选池及规模、规模日期、规则版本、观察日期。全部候选最新热度结果完整后才发布。
- 本地 SQLite：同步上述两张结果表，不读取全量原始行情，也不重新执行回归模型。

同日期、同基金只新增，不覆盖。每只基金计算完成后批量提交，失败回滚该批；已提交其他基金保留，重跑补缺。上市前不造数据；上市后行情缺日、停牌状态缺失或正常交易日价格无效时明确报错，保留旧候选池。停牌日有记录但热度为空。

后复权价格使用聚宽 `get_price(fq='post')`；实际收盘价使用 `fq=None`。每个回归窗口的价格来自同一次接口返回，不拼接不同批次的复权价格。若源历史发生修订，已入库的结果仍保留首次值；需要修订时应明确核查并备份后重算对应记录。

## 聚宽计算与项目同步规则

热度使用前25个交易日及当天，共26个后复权收盘价，取对数后做权重1至2的线性回归。纯Python实现保持原 `numpy.polyfit(..., w=weights)` 的拟合口径（最小化权重平方加权的残差）。年化趋势收益率=`exp(slope*250)-1`；R²保持原策略用权重乘残差平方、未加权对数均值的定义。热度=年化趋势收益率×R²。

这种R²与拟合使用的加权统计定义并不完全一致，为保持原排序而保留。年化值不是实际收益或收益预测。前、后复权在同一窗口内若仅差一个常数倍，得分相同；本程序按完整窗口获取后复权价格。详情价格图展示不复权实际收盘价。

负分、零分及高分均保留；同分按代码排序。恒定价格得分为0；不足26期、缺失有效价格或当日停牌时热度为空。聚宽计算只使用截至观察日的数据，不使用未来价格。已删除参考条件通过/未通过、RSRS、量比等展示及计算，本模块只做热度观察。

首次同步读取源表现存结果，之后同步按主键及更新时间增量下载两张结果表，包含回补和删除；成功并完成 SQLite 检查后才发布快照。同步中网页继续读取上一快照，失败也保留旧快照。页面只执行排名、筛选、区间变化等轻量展示操作。

聚宽运行新版采集器清理源库后，网页手动同步“ETF动量热度”或等待07:00自动同步，本地当前快照会同步删除过期主键，不需要清空缓存或执行 `--full`。同步仍读取完整主键及更新时间清单，但未变化的热度详情不会重新下载。本机为安全发布而复制 SQLite 文件，不代表从 MySQL 全量下载；旧文件按通用缓存规则在超过24小时后的同步结束时清理。

关闭 `CACHE_ENABLED` 时直接查询 MySQL 结果，不进行行情回归计算；生产环境仍建议开启缓存。若候选池仍标记 `etf_raw_market_v1`，同步或直接访问会提示先运行计算入库版脚本，避免显示未完成迁移的旧结果。

## 验证

离线测试覆盖公式与原 numpy 实现对照、负分/零分、缺失行情、预热与未来数据隔离、主键防重复、重复运行、候选池发布、LOF范围限制、缓存同步及断开源库后的页面读取。前端测试覆盖桌面/手机分类、搜索、下钻和曲线。实际聚宽账户权限、LOF元数据覆盖和生产数据库网络仍需首次运行验证。

## 全部热度显示“—”的修复

聚宽研究环境可能预先导入 NumPy 的同名函数。旧版回归函数使用未限定的 `any()`、`sum()`，在 Notebook 中会误判生成器，导致有效行情被标记为空热度。v3 显式使用 `builtins.any`、`builtins.sum`；不改变热度公式。

先部署最新项目，使后端识别v3候选池，再在聚宽完整替换并运行独立或批量采集脚本（仅重新同步网页不会重新计算源库）。从旧版本升级时自动检查当前候选的历史空得分，包括观察窗口之前、但仍在180个交易日保留区间内的空记录；只有重新计算出有效数值才填补，已有非空得分不覆盖。上市不足26期、停牌等仍可能保留空值，不强行填0。非当前候选的历史不在本次自动修复范围。

失败不会提前升级候选池版本，修复事务已成功的记录保留；重跑继续检查。升级完成后恢复常规只新增模式，避免每天反复重算合法空值。如需再次检查当前候选的空值，可在配置区使用：

```python
STRATEGY_OPTIONS = {'ETF动量热度': {'repair_missing': True}}
```

此参数仅允许填补空得分，不能覆盖已有有效得分；修复完成后恢复 `STRATEGY_OPTIONS = {}`。返回条数包含新增与修复记录。完成聚宽入库后，在网页“数据同步”选择“ETF动量热度”立即同步（不是仅点页面刷新），再查看热度。

## 增量快照缺成员时的自动恢复

日志协议启用后，如果旧入口曾直接写入热度而未记录变更键，后续仅更新候选池的增量可能出现“源库完整、本地候选快照缺行”。当前同步仅针对这种 ETF 增量成员缺失执行一次恢复：在读取日志头的同一个源库一致性事务内严格检查候选池及其日期的全部成员。源池缺行、为空、无效或尚未发布时仍失败并保留旧快照；源池完整时，仅清理未发布的 ETF 临时文件中的两张业务表，并重新分页读取该模块基线，严格校验后连同游标提交，最后原子发布。不会清空原缓存或修改源库，也不会每次同步都全量读取。

页面进度包含“核对源库 ETF 候选池完整性”“源库完整，重建 ETF 临时快照”“ETF 临时快照恢复校验通过”；成功后的同步说明显示自动重建。日志记录起始模式、前后 revision、候选池日期、成员数、缺失数，以及 `mode=recovered-baseline` 完成结果，不记录成员内容、SQL、连接或凭证。网络错误可按原同步有限重试策略重新尝试，但一次复制最多重建一次；取消或任何重建异常均保留旧快照及旧游标。

部署后用户正常重试 ETF 同步即可触发条件恢复，无需清缓存或重新采集已经完整的源数据。未变更 revision 的快速跳过及普通增量行为保持；本功能不承诺发现所有绕过日志的历史修改。长期仍应确保独立和批量采集入口全部使用带变更日志的版本。
