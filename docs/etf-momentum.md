# ETF 动量热度

入口 `/etf-momentum`。聚宽独立脚本 `collectors/ETF动量热度_数据库版.py`，同时加入单文件批量采集的第九个策略。网页只读取本地缓存，不访问聚宽、不执行买卖。

## 运行与部署

1. 在聚宽完整粘贴独立采集脚本，或更新完整批量采集脚本。顶部 `DB_CONFIG` 填写已有数据库连接；仅仓库中的模板需要自行填写。两份脚本均自带筛选与计算，不需要上传研究筛选脚本或其他依赖文件。
2. 建议北京时间 16:00 后运行。默认当天，16:00 前自动使用此前已结束交易日；遇非交易日使用最近交易日。行情或净值延迟时可以稍后重跑。
3. 独立脚本和批量脚本的顶部 `STRATEGY_CONFIG['ETF动量热度']` 可配置 `end_date`、`initial_trade_days`（默认180）、`min_size_yi`（默认30）。只跑批量中的本策略可设置 `STRATEGY_ORDER = ['ETF动量热度']`。
4. Linux 在项目目录执行 `bash deploy.sh`；Windows 更新后完整关闭旧进程，再运行 `start.cmd`。前后端都需要更新，旧后端可能返回 Not Found。
5. 页面打开“数据同步”，单独同步“ETF动量热度”，成功后查看总览中的新模块。每天北京时间18:00也会自动同步。采集应在同步前完成；否则手动再同步一次。

增加新表改变缓存 schema 签名，首次启动会准备新签名下的缓存，其他模块也可能需要首次重新同步。采集脚本负责建 MySQL 表；应用不会向 MySQL 建表或写业务数据。

## 候选池

沿用 ETF 分类研究版的现行规则：按指数或明示商品方向去重，取规模最大产品，规模严格大于30亿元；跨境仅原 ETF 动量策略的七只，债券仅511220城投债。黄金、豆粕、有色期货补充商品方向，501018南方原油作为指定LOF例外，用其最新披露A类净资产。详见 [ETF分类去重](etf-selection.md)。没有满足条件的候选时保留旧快照并提示检查数据源，不发布空名单。

每次运行重新确定当前候选池，回补这些基金最近180个交易日的历史。这不是历史当日选股回测：筛选所用规模来自本次运行，不能把历史曲线理解为当时实际入选名单。不同基金代码的历史不会拼接成同一基金。

## 热度与参考条件

热度用前25个交易日收盘价加当天收盘价，共26点。使用前复权价格，取对数；权重从1递增至2，以 `numpy.polyfit(..., w=weights)` 回归。年化趋势收益率为 `exp(slope*250)-1`，R²保持原代码用权重乘残差平方、使用未加权对数均值的口径。热度为两者相乘。

保留原公式而不修改其权重定义：polyfit拟合与该R²并非完全一致的加权统计定义。年化趋势收益率不是实际收益率或预测收益。恒定价格的热度为0。数据不足26期、当日停牌或无有效价格时存空值，不伪造成0、不参与有效得分排名。

全部有效得分参与降序排名，包括负分、0和大于6的得分；同分按代码排序。以下标识仅作收盘口径参考，不删除基金或将分数归零：

- `0 < score < 6`。
- 最近3段相邻收盘价跌幅均不超过5%。
- 当日收盘/开盘跌幅严格小于3%（跌3%不通过）。
- 当日成交量不超过前7日均量2倍；缺少有效均量则待定。
- RSRS沿用原策略：此前18日高低价回归斜率，与此前250日、20日滚动斜率的均值减2倍标准差比较；均线条件用此前5/10日收盘价。历史不足、无有效回归或beta为0时待定。

原交易脚本在11:00使用盘中价格，成交量代码把最后1分钟与日均量比较。仪表盘使用收盘价和整日成交量，所以“参考条件通过”不是原策略实际买入信号。任一条件未通过则总体未通过；没有失败但存在未知则总体待定。

为避免缺少预热数据，历史价格额外获取至少250个交易日。只计算截止每个观察日的窗口，不使用观察日以后的价格点。前复权价基准会随采集日期变化，历史记录按首次采集保留；价格图仅作参考，不用这些跨批次价格拼接计算真实收益。

## 数据与重复执行

- `etf_momentum_heat`：主键 `(trade_date, code)`，保留原始热度、收益率、R²、复权收盘价、参考条件、更新时间；额外索引 `(code, trade_date)` 加速历史查询。
- `etf_momentum_pool`：最新候选池及筛选规模、规模日期、规则版本、观察日期。只有当天全部候选有记录后才发布。
- 在当前回补窗口内补缺，不覆盖已有日期/基金记录；同日事务失败整体回滚。重复运行已完整数据时无业务写入。中断后可继续补缺；已退出候选池的历史不删除。
- 基金上市前无价格的日期不生成记录；源数据缺少日期不插入伪造值。最新日缺失任何基金时保留旧候选池；正常停牌和预热不足以明确的空热度记录表示。
- 当前排名及上一记录日排名，都按最新候选池计算；不存容易因名单变动失真的历史名次。详情支持已经退出当前名单但仍有历史的基金。
- 规则版本固定 `etf_close_momentum_v1`。以后改变公式必须设计显式迁移/重算，不能默默混用旧得分。

缓存沿用主键及 `updated_at` 对比，增量更新候选池和历史两张表。网页 API 为 `/api/v1/etf-momentum/latest`、`/api/v1/etf-momentum/funds/{code}/history?days=365`。

## 验证范围

离线测试覆盖原回归公式、负分/零分、过滤条件、缺少历史、表结构一致、重复写入保护、采集中断恢复、候选池发布、API排序和缓存断网读取。桌面/手机端测试覆盖分类、搜索、负分和空值展示、详情下钻和两条曲线。实际聚宽权限、产品数据覆盖和生产MySQL网络仍需在运行环境验证。
