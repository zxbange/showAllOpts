# ETF/LOF 动量热度

入口 `/etf-momentum`。聚宽采集基础行情，项目同步时计算热度，页面读取本地 SQLite 快照。其余策略也采用统一原始采集与本地计算链路，见[统一说明](raw-pipeline.md)；本模块不执行买卖。

## 从旧版升级

1. 更新聚宽中的完整 `collectors/ETF动量热度_数据库版.py` 或完整批量采集脚本，填写自己的 `DB_CONFIG`。两者都是单文件，不引用外部策略文件。
2. 在聚宽运行一次新版采集。它创建 `etf_momentum_bar` 并回补当前候选的原始行情，完成后将候选池版本更新为 `etf_raw_market_v1`。旧 MySQL `etf_momentum_heat` 表保留，但新版缓存不再读取它。
3. Linux 在项目目录执行 `bash deploy.sh`；Windows 完整关闭旧进程后运行 `start.cmd`。
4. 页面“数据同步”选择“ETF动量热度”。同步下载基础行情、计算结果、验证后一次发布缓存。每天北京时间18:00也会自动同步；聚宽采集需先完成。

旧得分不能还原原始行情，因此迁移首次需要采集和同步。新模型及计算版本改变缓存签名，其他模块可能需要首次重新同步。无需手动删表。应用不向 MySQL 建表或写业务数据。

## 采集参数与候选池

`STRATEGY_CONFIG['ETF动量热度']` 配置 `end_date`、`initial_trade_days`（默认180）、`min_size_yi`（默认30）。北京时间16:00前使用此前已结束交易日；16:00后可采集当天，源数据延迟时稍后重跑。仅运行这一项可设置 `STRATEGY_ORDER = ['ETF动量热度']`。

- ETF 按跟踪指数或明示商品方向去重，取规模最大且严格大于30亿元的产品。
- 加入聚宽上市 LOF 中，能通过基金主体信息确认的国内股票型、混合型产品。每只独立保留，不把不同主动组合强行合并；规模同样严格大于30亿元。
- 跨境仍限原七只 ETF；债券仍仅511220城投债ETF。跨境和债券LOF不纳入，南方原油不再作为例外。
- ETF 使用同日份额×单位净值；LOF 使用六位基金代码对应的已披露 `total_tna`，代表对应份额类别净资产，不是所有份额类别合计，也不是场内流通市值。报告期最多落后180自然日。
- 信息缺失、冲突、未知分类或过旧规模进入审计清单。分类依赖聚宽元数据及名称规则，无法保证覆盖所有产品；研究脚本提供明细核对。详见 [筛选规则](etf-selection.md)。

每次按当前池回补近180个交易日，另外采集25个预热交易日。已有基金补齐窗口内缺口；停采超过窗口时，也补齐上次记录至今的间隔。新入选基金从当前窗口回补，不代表历史当时已入选。退出基金历史保留。

## 数据表与重复执行

- MySQL `etf_momentum_bar`：主键 `(trade_date, code)`；实际收盘价、后复权收盘价、停牌状态、展示起始日、更新时间。只采集热度所需基础字段，不额外存全市场行情。
- MySQL `etf_momentum_pool`：最新候选池及筛选规模、规模日期、版本、观察日期。全部候选最新行情完整后才发布。
- 本地 SQLite `etf_momentum_heat`：由项目生成的热度、年化趋势收益率、R²和实际收盘价，不回写 MySQL。

同日期、同基金只新增，不覆盖。每只基金批量提交，失败回滚该批；已提交其他基金保留，重跑补缺。上市前不造数据；上市后行情缺日、停牌状态缺失或正常交易日价格无效时明确报错，保留旧候选池。停牌日有记录但热度为空。

后复权价格使用聚宽 `get_price(fq='post')`；实际收盘价使用 `fq=None`。增量采集会核对一个已有重叠日期的后复权价格；若数据源历史调整导致不一致则停止，不能把不同基准静默拼接。应先核对数据源，再备份并重建受影响基金行情，而不是忽略报错。

## 本地计算与同步规则

热度使用前25个交易日及当天，共26个后复权收盘价，取对数后做权重1至2的线性回归。纯Python实现保持原 `numpy.polyfit(..., w=weights)` 的拟合口径（最小化权重平方加权的残差）。年化趋势收益率=`exp(slope*250)-1`；R²保持原策略用权重乘残差平方、未加权对数均值的定义。热度=年化趋势收益率×R²。

这种R²与拟合使用的加权统计定义并不完全一致，为保持原排序而保留。年化值不是实际收益或收益预测。前、后复权在同一窗口内若仅差一个常数倍，得分相同；后复权便于跨批次拼接。详情价格图展示不复权实际收盘价。

负分、零分及高分均保留；同分按代码排序。恒定价格得分为0；不足26期、缺失有效价格或当日停牌时热度为空。项目只使用截至观察日的数据，不使用未来价格。已删除参考条件通过/未通过、RSRS、量比等展示及计算，本模块只做热度观察。

同步仍按主键及更新时间增量下载两张源表，包含回补和删除；下载后对本地完整行情重新计算热度，避免新旧算法混用。计算成功并完成 SQLite 检查后才发布快照，同步中网页继续读取上一快照，失败也保留旧快照。增加历史会增加本地计算量，但不会每次从公网重拉全量行情。

计算版本 `weighted-momentum-26-v1` 纳入缓存签名；以后公式改变应同步更新版本。关闭 `CACHE_ENABLED` 的直接数据库模式仍可用，但会请求原始行情并临时计算，速度较慢，生产环境建议保持缓存开启。

## 验证

离线测试覆盖公式与原 numpy 实现对照、负分/零分、缺失行情、预热与未来数据隔离、主键防重复、重复运行、候选池发布、LOF范围限制、缓存同步及断开源库后的页面读取。前端测试覆盖桌面/手机分类、搜索、下钻和曲线。实际聚宽账户权限、LOF元数据覆盖和生产数据库网络仍需首次运行验证。
