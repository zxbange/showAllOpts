# 页面内短线胜率验证

入口：短线选股的同级策略导航 → 胜率验证（独立地址 `/short-term/validation`），不再嵌在选股结果内。只开放补票龙、红悬停、蓄力龙、超跌后止跌反弹，可单选或多选。起始日默认2024-01-01，两个截止日留空时使用已采集最新收盘交易日。先选择策略/日期，再开始验证；刷新页面并重新解锁后会显示最近30个任务。暂停后点击“从断点重试”。若源数据已修复，点击“准备重新读取数据”，再开始验证，会建立新任务并保留旧结果；同参数正在执行的任务仍会合并。

统一原四策略沪深股票池与基础过滤、后复权OHLC和原始成交量；原90交易日形态窗口、内部60/65行截取和EMA初始化不变。指标是T收盘相对T+1/2/3收盘的严格正收益，持平计入有效分母；各期限独立剔除停牌和缺行情，末尾未到观察日单列。没有有效样本显示空值，有效样本不足30提示不稳定。这不是可成交收益或逐笔实盘回测。红悬停价格取整和统一股票池可能改变生产信号。

## 数据和部署依赖

仅SELECT现有 `ultra_research_calendar`、`ultra_research_universe`、`ultra_research_bar`；不建源库表、不触发采集或同步。连接沿用服务Settings/APP_ENV_FILE；不读取命令行脚本私有JSON。运行依赖新增numpy、pandas，已纳入锁定依赖。股票池清单上限20000、单股行数上限4000、日期范围上限10年；需开始日前160个交易日预热数据。

任务、旧模式冻结输入、逐股信号和聚合行持久化在 `Settings.log_path/short-validation/jobs.sqlite3`。该目录与既有服务器log持久目录一致，不属于前端构建或发布清理目录；容器仍须挂载现有log持久卷。备份时使用SQLite在线备份或停服务后复制整个目录，不应删除数据库。验证管理通过终端配对确认站主身份，旧管理密钥配置保留兼容，详见下文。

每个进程启动轮询线程，OS文件锁覆盖整个工作单元，SQLite事务将输入/结果和断点一并提交。服务重启可重新领取未完成单元；取消时不提交当前计算；已提交股票不会重算或重复计数。请求不执行统计。查询连接/读取超时分别8/20秒，新任务每批最多20股、每表最多80001行哨兵读取，旧任务逐股有界；没有定时虚增进度，每20个实际处理信号日更新活动。源库缺表、缺列、缺预热、无基础样本均失败而非当作0。

新任务默认 `input_mode=static-batch-v1`：持久保存固定股票清单、日期计划、策略/算法版本和连接版本；每批最多20股，在同一个源库连接和事务中读取两张表的必要列，每股最多4000行，超限直接失败而不截断统计。读取后退出源事务、归还连接，再逐股计算；物理空闲连接在该批工作单元结束时关闭。每股结果、覆盖统计和done断点在同一SQLite事务提交，不保存整段原始行情JSON。只有已提交股票计入进度，失败/暂停/进程重启后跳过这些股票，未提交的批次部分重新读取。源历史数据需在任务期间保持静态；若修订行情或历史股票池，应新建任务，避免混合不同修订的数据。

旧任务缺少input_mode或为frozen时仍先逐股冻结输入、再计算，不静默转换。每股两表在同一源事务读取，已保存输入重试不重读，冻结完成后可离开源库继续计算。结果聚合仍由SQLite完成（含中位数），不会在内存拼接所有股票明细。

页面“任务参数与数据源版本”显示输入方式、阶段开始时间及最近连接/行情读取/快照读取/单股计算/断点提交耗时（秒，非累计）。日志仅记录任务ID、固定阶段名和耗时，不记录凭证、连接地址或SQL参数。读取超时是socket读取超时，不是整项工作总时限；活动与已提交进度不按时钟虚增。

升级操作：用户先暂停原冻结任务，再新建任务使用静态模式。原任务的67/5133等已保存输入不会删除，仍可选择按原方式继续；不会自动导入新模式。后台按任务顺序处理，未暂停的旧任务可能先于新任务继续运行。本次发布不代为暂停、取消、删除或新建任务；已有等待/运行任务仍按原机制在重启后恢复。

旧七策略/原四策略CLI入口保留，内部实现迁入 `backend/app/services/short_statistics.py`；原参数、CSV和历史结果不删除。CLI需完整项目目录，相对配置路径仍以原 `脚本/本地统计` 目录为基准。网页新任务共用该引擎但只提供上述四种，不会计算未选择策略。

## 验证和已知范围

离线合成数据覆盖结果口径、浮点无损恢复、失败恢复、进程实例重启、互斥、重复点击、暂停时不提交、单/多策略一致、缺行情和空信号。浏览器测试覆盖选择、失败重试、刷新后任务恢复与空值展示。未连接生产数据库，不能据此确认真实库索引、容量或实际长跑性能；旧脚本热点是代码风险观察，不是已确认现场根因。

## 首次使用：终端一次配对，之后在网页操作

应用没有通用账户系统，所以仅由服务器终端签发一次性配对码证明站主身份；公网不存在领取配对码或抢占管理员的接口。所有成功配对的浏览器均代表同一站主，能访问验证历史与配置，不是多用户租户系统。

原生Linux部署：在服务器项目目录、以API服务账户执行（现有标准部署为ubuntu，配置路径为 `config/app.config`）：

```bash
APP_ENV_FILE=config/app.config backend/.venv/bin/python backend/validation_pair.py --origin 'http://119.28.106.127:8081'
```

地址必须是浏览器实际使用的站点来源，包含非默认端口，不含页面路径。命令使用既有API配置，不需要编辑文件；若现有部署使用不同 `APP_ENV_FILE`，应沿用该路径，不能创建另一套配置或状态目录。命令仅在终端显示配对码，不在程序日志保存；不要将配对码发送到聊天。代码开发和测试不等于实际执行此生产命令的授权。

Docker部署：在compose项目目录执行，下例的站点地址应换成浏览器实际地址；`--user appuser` 与镜像API身份相同，继承容器现有配置和日志卷：

```bash
docker compose exec --user appuser backend python validation_pair.py --origin 'http://example.com:8080'
```

1. 打开“短线选股 → 胜率验证”（独立地址 `/short-term/validation`）。HTTP下先由本人勾选明文传输风险确认，输入终端配对码。
2. 填写数据库地址、端口、库名、只读用户名、密码和适用TLS选项。配置名称有默认值。可以直接填写新连接，也可以选择已加密保存的版本。
3. 四策略选择一个或多个，填写开始日期等参数，点击“开始验证”。页面先加密保存有修改的连接并绑定版本，再创建后台任务；不必单独点保存。“测试连接”和“加密保存并使用”仍可单独使用。
4. 刷新或返回页面仍可查看任务。暂停后可继续，取消是不可继续的终态；关闭网页不停止后台任务。

配对码具有256位随机熵，仅保存SHA-256摘要，绑定命令指定的完整站点来源；10分钟有效、最多10次失败/消费尝试，事务一次性消费。重新运行命令使旧未使用配对码失效，但不撤销已有会话。会话有效期最多8小时，刷新不重新配对；通过“锁定验证管理”注销、会话过期或更换浏览器后重新领取码。

需要撤销所有已有浏览器会话（例如设备遗失）时，站主在同一命令末尾加 `--revoke-sessions`。撤销不删除任务、结果或连接配置；无需重启API。

认证使用HttpOnly、SameSite=Strict的会话Cookie，HTTPS下同时设置Secure；服务端仅保存会话摘要。浏览器不向localStorage/sessionStorage写配对码、会话令牌、数据库密码或管理密钥。写操作需Origin及会话CSRF校验，读操作也受鉴权保护。兼容既有Nginx丢失外部端口的Host头：请求只提供候选来源，最终完整来源必须匹配终端签发或持久会话授权；不直接信任任意转发头。

HTTP风险由本人在网页确认并绑定到会话，页面持续显示风险；无旧配置的新部署不需要 `VALIDATION_ALLOW_HTTP`。HTTP可能泄露或被篡改配对码、会话凭证、数据库密码与查询结果，后台加密不保护传输。

## 自动密钥、管理存储与升级

新Linux部署无需设置 `VALIDATION_ADMIN_KEY`、`VALIDATION_ENCRYPTION_KEY`、`VALIDATION_ALLOWED_TARGETS` 或HTTP开关。

- 连接配置和任务存在 `LOG_DIR/short-validation/jobs.sqlite3`，连接字段为认证加密密文。
- 加密密钥自动保存在独立的 `LOG_DIR/short-validation-secrets/source.key`，目录0700、文件0600。多worker文件锁、原子发布和同步落盘；升级重启复用，不覆盖。密钥需单独受限备份，恢复管理库时同时恢复匹配密钥。
- 配对摘要、会话摘要和限流计数在 `LOG_DIR/short-validation-auth/access.sqlite3`，目录0700、文件0600，跨worker和重启共享。所有目录须处于既有持久日志卷；不写入用户选择的统计源库。

已有环境加密密钥仍兼容，先验证能解密旧数据后持久化。密钥缺失、损坏或不匹配时明确报错，不重新生成替代密钥或删除数据。Windows保持旧外部加密密钥模式；新的自动密钥和终端配对存储面向Linux，Windows尚不提供无配置初始化。

**旧管理模式不会被自动放宽：** 若现有 `VALIDATION_ADMIN_KEY` 非空，即使格式错误也不开放配对。继续使用原管理密钥、原HTTP要求和原目标限制。显式配置的非空目标允许列表也继续生效。不存在这些旧设置的新部署直接使用终端配对和网页流程；不要为绕过旧安全策略而自动清空配置。

## 数据库连接授权与结果保存

站主配对后填写的精确连接就是连接意图，无需运维手工添加地址。仅针对该连接执行MySQL握手及三张研究表的只读检查，不扫描网段。连接测试每会话每分钟最多5次。若已有显式允许列表，则继续遵循该策略。

DNS解析最多等待5秒且最多4个后台槽位，解析后固定IP建socket，TLS仍校验原主机名。元数据、链路本地、未指定、多播和保留地址始终阻断。源库仅SELECT，不创建表或触发采集。失败信息脱敏。建议使用源库只读账户；MySQL TLS与网站HTTP是不同连接，网页可选择校验证书、仅加密或不使用TLS。

保存创建不可变版本，任务绑定ID及版本；修改连接不会把已有任务切换到另一数据源。密码不回显，编辑留空保留原密码。成功保存、清空、注销或过期后清除页面内存密码；失败时保留输入供修正。旧模式冻结完成后继续复用输入，不重新连接源库；新静态模式恢复时仅重读未提交股票。

## 暂停与取消

暂停保留断点，可以继续；取消保留历史和已提交结果，但不能继续。运行中先显示“正在取消”，在途查询返回或超时后协作停止，确认无在途工作再标记“已取消”。不使用KILL QUERY。重复取消幂等，取消中/已取消任务不会被重试、重启或旧worker复活；未取消的等待/运行任务重启后自动恢复，暂停/失败需手动继续。

## 删除单条验证记录

每条记录提供“删除记录”，打开确认框后再次选择“永久删除记录和数据”才执行；“保留记录”或 Escape 关闭确认框不删除。此操作不可恢复，仅删除该任务管理记录（含计划、断点和聚合结果）、冻结输入、逐股计算明细、收益结果及三日窗口结果。源 MySQL 的 `ultra_research_*` 行情、共享连接配置及其版本、密钥、认证会话和其他任务不受影响。不提供全量清空。

运行中/正在取消的任务必须先取消并等到“已取消”。即使显示等待、暂停、失败或完成，服务端仍需取得跨进程 worker 锁；任何 worker 正在执行工作单元时都会拒绝删除（包括其他任务占锁），稍后可重试。锁持有期间用同一 SQLite 事务删除所有关联行，失败整体回滚；重复删除已不存在的任务返回成功。API 为 `POST /api/v1/short-term/validation/jobs/{id}/delete`，沿用验证管理鉴权以及配对会话的同源、CSRF检查。

当前任务不产生独占文件，关联数据均在共享 `jobs.sqlite3` 内。删除保留数据库和 worker 锁文件，不触碰源库，也不自动执行 VACUUM；释放的数据库页可供后续任务复用，单条删除不保证 SQLite 文件立即缩小，也不属于存储介质安全擦除。历史备份不随此操作删除。


## 源MySQL索引建议（不自动执行）

现场提供的MySQL 8.4.13两表当前仅有PRIMARY(trade_date,code)。批量读取仍需合适索引，不能保证程序升级独自解决全部现场慢查询。先对当前逐股查询及20股IN批次运行普通EXPLAIN（不是EXPLAIN ANALYZE），检查实际key和估计rows，再由用户决定执行。确认引擎为InnoDB且没有等价索引时，可逐表选择：

```sql
SET SESSION lock_wait_timeout = 10;
ALTER TABLE ultra_research_bar
  ADD INDEX idx_urb_code_date (code, trade_date), ALGORITHM=INPLACE, LOCK=NONE;
ALTER TABLE ultra_research_universe
  ADD INDEX idx_uru_code_date (code, trade_date), ALGORITHM=INPLACE, LOCK=NONE;
```

InnoDB的单列code辅助索引也会携带主键日期列，这里显式写code,trade_date便于检查；不要两种都建。不改主键、不加宽覆盖索引，暂不加入收益有限的asset_type。建索引需要扫描、额外空间和I/O，仍可能短暂等待元数据锁；选低负载时执行，不支持指定算法或锁选项时报错停止，不去掉限制强行重试。执行后重跑同样EXPLAIN比较key/rows。此文档不是已执行索引的声明。

### 数据库名称与保存行为

页面以配置名称选择数据库，不要求管理连接版本。重新输入相同密码、测试连接后启动、重复保存相同信息均复用已保存连接；测试连接只读且不保存配置。后台仍保留不可变连接快照，修改密码、地址等实际内容不会影响已创建任务。同名且内容相同的新建请求复用已有配置；同名但内容不同需选择原配置编辑或换名，不自动合并。已有历史记录和密文不会删除。

选中已有密码的配置时，输入框显示固定 `********` 占位提示，不反映实际密码长度；不输入或清空表示保留原密码，主动输入表示替换（包括主动输入八个星号）。新增配置需填写密码。HTTP 首次配对风险确认保留，进入后不再常驻重复长警告。

测试连接按钮以中性/绿色勾/红色叉显示未测试、成功、失败，失败时保留脱敏原因；修改连接字段会清除旧状态，晚返回的测试结果不会覆盖新选择。顶部五个入口统一使用 `ShortTermNavigation` 和公共导航样式，独立验证路由保持不变。
