# 页面内短线胜率验证

入口：短线选股 → 短线胜率验证。只开放补票龙、红悬停、蓄力龙、超跌后止跌反弹，可单选或多选。起始日默认2024-01-01，两个截止日留空时使用已采集最新收盘交易日。先选择策略/日期，再开始验证；刷新页面会恢复最近30个任务。暂停后点击“从断点重试”。若源数据已修复，点击“准备重新读取数据”，再开始验证，会建立新任务并保留旧结果；同参数正在执行的任务仍会合并。

统一原四策略沪深股票池与基础过滤、后复权OHLC和原始成交量；原90交易日形态窗口、内部60/65行截取和EMA初始化不变。指标是T收盘相对T+1/2/3收盘的严格正收益，持平计入有效分母；各期限独立剔除停牌和缺行情，末尾未到观察日单列。没有有效样本显示空值，有效样本不足30提示不稳定。这不是可成交收益或逐笔实盘回测。红悬停价格取整和统一股票池可能改变生产信号。

## 数据和部署依赖

仅SELECT现有 `ultra_research_calendar`、`ultra_research_universe`、`ultra_research_bar`；不建源库表、不触发采集或同步。连接沿用服务Settings/APP_ENV_FILE；不读取命令行脚本私有JSON。运行依赖新增numpy、pandas，已纳入锁定依赖。股票池清单上限20000、单股行数上限4000、日期范围上限10年；需开始日前160个交易日预热数据。

任务、冻结输入、逐股信号和聚合行持久化在 `Settings.log_path/short-validation/jobs.sqlite3`。该目录与既有服务器log持久目录一致，不属于前端构建或发布清理目录；容器仍须挂载现有log持久卷。备份时使用SQLite在线备份或停服务后复制整个目录，不应删除数据库。沿用现有cache/margin写操作的部署访问边界，没有另设公开账户权限。

每个进程启动轮询线程，OS文件锁覆盖整个工作单元，SQLite事务将输入/结果和断点一并提交。服务重启可重新领取未完成单元；取消时不提交当前计算；已提交股票不会重算或重复计数。请求不执行统计。查询连接/读取超时分别8/20秒，读取逐股有界；没有定时虚增进度，每20个实际处理信号日更新活动。源库缺表、缺列、缺预热、无基础样本均失败而非当作0。

先逐股冻结输入，再开始计算；每股两个表在同一源库事务读取。已保存输入不会在重试时重新查询。冻结过程中源库若同时修订不同股票，并不保证跨全部股票的同一数据库时刻；研究时应使用已完成采集的日期。冻结完成后，一次计算与断点重试使用同一份输入。结果聚合由SQLite完成（含中位数），不会在内存拼接所有股票明细。

旧七策略/原四策略CLI入口保留，内部实现迁入 `backend/app/services/short_statistics.py`；原参数、CSV和历史结果不删除。CLI需完整项目目录，相对配置路径仍以原 `脚本/本地统计` 目录为基准。网页新任务共用该引擎但只提供上述四种，不会计算未选择策略。

## 验证和已知范围

离线合成数据覆盖结果口径、浮点无损恢复、失败恢复、进程实例重启、互斥、重复点击、暂停时不提交、单/多策略一致、缺行情和空信号。浏览器测试覆盖选择、失败重试、刷新后任务恢复与空值展示。未连接生产数据库，不能据此确认真实库索引、容量或实际长跑性能；旧脚本热点是代码风险观察，不是已确认现场根因。
