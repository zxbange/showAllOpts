# 短线选股

从 `D:/project/stock/src/strategies/` 的补票龙、红悬停龙、蓄力龙实际代码移植；只做收盘筛选和展示，不下单。另接入四策略胜率统计中的“超跌后止跌反弹”（规则见文末）。四种形态共用股票扫描，同一股票同日只保存一份展示行情，可同时属于多个形态。

## 使用

1. 在聚宽研究环境运行 `collectors/短线选股_数据库版.py`。在文件顶部填写 `DB_CONFIG`，与其他数据库版使用同样的连接方式。GitHub 版本只有占位值。
2. 或使用新的 `collectors/策略批量采集_数据库版.py`，默认串行顺序最后增加“短线选股”，无需任何外部策略文件。仅运行本模块可调用 `run_all(['短线选股'])`。
3. 首次自动补齐最近三个完整交易日，之后只补这三日窗口内尚未完成的快照；已有日期不重复写入。
4. Linux 执行 `bash deploy.sh`，网页“数据同步”中选择“短线选股”，然后从总览进入独立的“短线选股”页面。

北京时间 16:00 前使用上一交易日，16:00 后允许采集当天日线。非交易日使用最近已收盘交易日。API 数据异常时该日不写入，修复后可重跑。若当天供应商行情仍在校正，建议等收盘数据稳定后采集。

## 规则

三个战法统一先按目标交易日过滤：非ST、总市值≥30亿元（不是流通市值）。ST批量返回缺失时逐只补查，仍缺失或总市值缺失则报出日期和代码，该日不提交，避免未知数据误入选。升级后最近三个交易日的旧规则快照会自动重新筛选，逐日原子替换；同版本已完成日期仍跳过。

- 补票龙：按原程序截取最近60条行情；BBI=(MA3+MA6+MA12+MA24)/4，在原算法的候选窗口里检查归一化差分20%分位数非负；最近三日长RSV(21)均≥80，短RSV(3)首尾≥80且其中有值<20，DIF(12,26)>0。RSV分母采用窗口最高**收盘价**减最低价，保持原程序口径。
- 红悬停龙：T-2涨幅达到原阈值（普通股票9.5%、300/301/688开头19.5%、9开头29.5%），T-1和T日最低价均不低于按T-2前收盘价估算的涨停价，T日未达到涨停阈值；三个战法统一排除ST。原程序虽然声明放量参数，但实际没有1.5倍放量判断，此处按已确认要求保持实际逻辑。
- 蓄力龙：至少65条行情。T-2阳线、涨幅>3%、量>T-3的1.2倍；T-1阴线、收盘>T-2开盘、-4%<涨幅<0、量<T-2的0.8倍；T日阳线、收盘>T-2收盘、涨幅>3%、量>T-1的1.2倍；MA10>MA20>MA30>MA60。

数据源改为聚宽，前复权行情；日涨幅按相邻前复权收盘计算。沿用原战法固定阈值，不以交易所涨停价接口替代。因供应商、复权和停牌数据口径不同，不承诺与原Tushare历史CSV完全相同的入选名单。聚宽使用交易日日历、不跳过停牌日；行情缺日期或数值无效时拒绝保存该日，而非默默遗漏股票。上市不足30日的入选股票展示实际可用K线，不补造数据，不增加原战法没有的上市天数过滤。

## K线与存储

- 每批默认50只股票，共读取90个交易日作为指标预热；入库只存入选股票最后30根日K线及预先计算的MA5/10/20/30/60，另附成交量、行业、市值（亿元）、PE、PB。
- 新上市股票历史不足长期均线长度时，缺少的均线为 null，页面不补零。
- `short_term_run`：以交易日为主键，记录四种形态入选数量、扫描数量、规则版本等。零入选也保存完成记录。
- `short_term_stock`：以交易日+股票代码为联合主键，JSON保存战法列表、股票信息及K线。整日四种形态与完成记录在同一事务内提交，失败回滚。
- 每次更新开始按最近三个完整交易日清理两张表的过期快照；K线的30日历史属于快照内必要数据，不按K线日期删成三根。
- 本地同步会删除源表已经清理的记录，页面只读本地快照。数据库清理后需要同步才能在本地体现；服务启动不自动同步，每日20:00或手动同步。
- 新模块沿用旧缓存根目录，不影响机构持仓首次全量的断点续传文件。

页面可切换四种形态和保留日期，按代码顺序分页，每页6只，避免一次创建太多图表；支持K线缩放、均线图例开关和成交量对照。

接口用法参考：[聚宽官方 JQData API 源码](https://github.com/JoinQuant/jqdatasdk/blob/master/jqdatasdk/api.py)。实际研究环境由 Notebook 提供 API，采集代码不导入外部策略文件。

## 历史胜率研究

独立研究脚本 `collectors/短线选股胜率_研究版.py` 从2026年7月1日起回放三个策略，直接展示入选后第2、4、10个交易日的胜率、是否超过50%及涨跌幅门槛次数。支持断点续算，不生成CSV，不连接业务数据库。运行和统计口径见[短线胜率研究](short-term-winrate.md)。

## 超跌后止跌反弹（第四种形态）

此项沿用四策略收盘胜率统计的默认参数。T为所选已收盘交易日：

- 后复权 `close[T-1] / close[T-4] - 1 <= -0.08`；T收盘严格高于T-1最高价，且严格高于T开盘价。
- T未复权成交量不低于T-5至T-1五日未复权均量，不把T计入参考均量。
- 沪深主板、创业板、科创板，排除B股、北交所和存托凭证；T非ST、总市值至少30亿元、上市至少365自然日、成交额至少5000万元、非停牌且有成交，并有60个交易日有效收盘价。

只使用T及之前的数据，不读取未来收益或胜负标签。统计中的“第1、2、3日胜率”指后续对应日收盘相对T收盘严格上涨的样本占比，不是次日开盘买入、含成本收益或未来胜率承诺。本页面只显示收盘候选，不显示未经计算的胜率。

新策略额外读取未复权行情（成交量、成交额、停牌状态）及后复权价格，与统计库口径一致。原三个战法和展示K线继续采用前复权数据；共用股票卡片和30根K线，页面明确标注两种用途。数据缺失会拒绝保存该日，不以零候选掩盖错误。

规则版本升级为 `stock_four_patterns_v3_oversold`。运行新版单独或批量采集脚本会重算最近三个完整交易日的旧快照，然后通过“数据同步→短线选股”更新本地缓存。旧版本快照在新策略页显示“尚未计算”，区别于已计算但零入选。不改变表结构、缓存命名空间或过期清理机制；仅部署网页不会触发聚宽采集。

共享规则源为 `strategy_rules/oversold.py`。修改后运行 `python scripts/sync_oversold_rules.py`，将同一规则嵌入两个可独立运行的采集脚本及本地统计脚本；测试校验嵌入内容一致。参数使用统计默认值并写入快照 `oversold_params`，当前网页不提供临时调参。更改采集参数时须同步升级规则版本，避免沿用旧快照。
