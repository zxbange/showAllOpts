# 七策略统一数据库统计

入口：[七策略胜率统计_本地版.py](../脚本/本地统计/七策略胜率统计_本地版.py)。只读四策略采集已有的 `ultra_research_calendar`、`ultra_research_universe`、`ultra_research_bar`，重算七种策略信号，结果写本地CSV。不新增表、不联网采集、不写生产库，不读取网页短线观察期内的候选名单。

**这是“统一四策略数据口径的验证”。** 七策略采用同一个历史股票池、通用过滤、后复权价格和统计口径，目的是横向比较。红悬停、蓄力龙、补票龙保留原形态条件和阈值，但不再使用原生产三策略的另一套股票池与前复权数据，红悬停价格取整等可能使信号不同。不能称为原三策略生产选股的精确复现。CLI启动时和结果参数JSON均保留此说明。

## 配置与运行

直接复用原四策略的私有配置，无须另填一套：

`脚本/本地专用/本地统计/超短线四策略胜率统计配置.json`

内容仍只有 `DB_CONFIG`（host、port、dbname、dbuser、dbpassword）、`DB_TLS_VERIFY`、可选 `DB_TLS_CA_PEM`。不删除、不覆盖用户配置。首次使用可参考[脱敏示例](../脚本/本地统计/数据库配置.example.json)，只在本机填写，不提交真实配置。

项目根目录执行：

```powershell
python -m pip install pandas numpy sqlalchemy pymysql
python "脚本/本地统计/七策略胜率统计_本地版.py" --list-strategies
python "脚本/本地统计/七策略胜率统计_本地版.py" --strategies all
python "脚本/本地统计/七策略胜率统计_本地版.py" --strategies "超跌后止跌反弹"
python "脚本/本地统计/七策略胜率统计_本地版.py" --strategies "红悬停" "蓄力龙"
```

`four`：原四策略；`three`：三个短线形态；`all`：全部七个。也可空格或逗号分隔多个中文策略名。重复选择去重，未知名称报错。`红悬停`为`红悬停龙`别名。不指定时默认`four`，兼容旧入口。

默认开始日期 **2024-01-01**，实际交易日取数据库日历（元旦后首日应为2024-01-02）。结束和观察日期沿用原四策略：数据库最新股票行情日、北京时间最近已收盘日、显式观察截止日的最早者。可加：

```powershell
--start 2024-01-01 --end 2024-12-31 --as-of 2025-01-06 --output "统计结果" --no-progress
```

`--config "配置绝对路径"`指定其他私有JSON；相对路径以程序目录为基准。默认配置不存在时使用统一脚本顶部参数。TLS参数保持四策略原行为。策略、日期不写入数据库连接JSON。

旧命令 `python "脚本/本地统计/超短线四策略胜率统计_本地版.py"` 继续可用，它是同目录统一脚本的兼容入口。统计实现只维护一份。保留的 `短线三策略胜率验证_研究版.py` 是旧聚宽取数方案，不是本次本地数据库入口。

## 七策略共同标准

| 项目 | 统一口径 |
| --- | --- |
| 股票范围 | 原四策略采集的沪深主板、创业板、科创板，历史当日快照，不用当前存续股票池 |
| 基础过滤 | 共用 `signal_eligibility`：eligible=1、非ST、总市值≥30亿元、上市≥365自然日、连续60个有效后复权收盘、信号日不停牌、成交额≥5000万元、成交量及基准价格为正 |
| 价格和成交量 | 形态统一使用 `adj_*` 后复权OHLC；成交量使用数据库 `volume`；原四策略中依赖实际涨跌停价的条件仍使用原始价 |
| 日期 | 所选策略使用同一信号区间和观察截止日；统一加载开始前160个市场交易日 |
| 形态窗口 | 保留策略本身所需长度。三个新增策略读取截至信号日90条上下文，补票龙内部60条，蓄力龙内部65条，红悬停最近3条及前收盘；不使用未来行 |
| 收益和胜率 | 信号日为0，后续市场第1/2/3日后复权收盘相对信号日收盘；严格正收益计胜，持平入分母不计胜 |
| 排除和窗口 | 待观察、观察日停牌及缺行情不进有效分母，不顺延交易日；三日窗口需三个观察日全部有效 |
| 重复 | 同策略同日同股一次，不同策略和不同信号日分别计数 |

`--params`并不存在；通过Python调用时传入原四策略 `params` 的通用门槛，会同时作用于七个策略。形态专用参数仍只作用于对应形态。新增三策略没有独立覆盖通用门槛的选项。

必要数据不足会提示：缺表/字段、日期非法、开始前160日预热不足、三策略90日上下文缺行或无效价格/量均不自动补采，不伪装成未触发。三策略额外检查上下文是数据完整性检查，不是另一套股票池过滤；发现缺口就停止此次统计。原四策略基础样本数据覆盖继续输出供复核。

## 输出

`超短线统计结果/<运行时间>/` 包含：收盘胜率汇总、三日窗口汇总、策略信号明细、按月收盘胜率、数据覆盖CSV，以及运行参数JSON。只输出所选策略；参数JSON记录统一口径提示、共用基础样本数、价格字段、窗口与所选策略，不含凭据。各策略最终有效分母可因信号日期和观察期成熟程度不同而不同，但计算定义一致。

未模拟买入成交、费用、滑点，不能视为可实现交易收益。本地测试使用合成SQLite数据，没有运行用户真实数据库，没有提供真实胜率。

## 提交与部署

所有main推送仍执行后端与前端CI。整个推送差异仅在根目录 `脚本/`、`scripts/` 内（含全部子目录和文件），以及 `scripts/deployment_impact.py` 明列的独立统计文档/测试白名单内时，跳过deploy。这是用户明确批准的两个完整目录范围，`scripts-other/`、`脚本备份/` 等相似名称不包含在内。

目录外的应用、共享策略、采集器、工作流、依赖、未知路径及混合变更仍部署。改名同时检查旧、新路径；比较推送前后完整差异，覆盖多个提交。**比较失败、SHA缺失/非祖先或空差异时分类失败，阻止自动部署，不猜测需要部署。** 手动deploy/check不执行推送分类，保留原有显式操作、部署开关及安全验证。

目录内 `scripts/deploy.py`、同步工具、分类脚本等修改也跳过自动部署；若要立即激活这些工具的更新，请在CI通过后手动deploy，否则随下一次正常部署一起进入服务器。首次引入本规则的变更包含工作流，因此本次仍部署一次；不为验证跳过行为另造空提交。
