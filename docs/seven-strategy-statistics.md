# 七策略统一数据库统计

主入口为 [`脚本/本地统计/七策略胜率统计_本地版.py`](../脚本/本地统计/七策略胜率统计_本地版.py)。这是本地 Python 程序，只读已有数据库、重算策略、导出本地CSV；不调用聚宽，不自动采集，不建表、不写生产库。七种策略指原四策略加红悬停龙、蓄力龙、补票龙。选择的是策略，不是启动其他采集脚本。

## 配置和最短命令

**直接沿用四策略的现有配置，无须另填一套：**

`脚本/本地专用/本地统计/超短线四策略胜率统计配置.json`

配置保留 `DB_CONFIG`（host、port、dbname、dbuser、dbpassword）、`DB_TLS_VERIFY`、可选 `DB_TLS_CA_PEM`。程序不删除或覆盖它。尚无配置时，参考[脱敏示例](../脚本/本地统计/数据库配置.example.json)，仅在自己的本机填写；不要覆盖已有配置，不要提交真实凭据。

在项目根目录执行：

```powershell
python -m pip install pandas numpy sqlalchemy pymysql
python "脚本/本地统计/七策略胜率统计_本地版.py" --list-strategies
python "脚本/本地统计/七策略胜率统计_本地版.py" --strategies four
python "脚本/本地统计/七策略胜率统计_本地版.py" --strategies "超跌后止跌反弹"
python "脚本/本地统计/七策略胜率统计_本地版.py" --strategies "红悬停" "蓄力龙"
python "脚本/本地统计/七策略胜率统计_本地版.py" --strategies all
```

`four` 为原四策略；`three` 为三个短线策略；`all` 为七个。默认选择 `four` 保持旧命令行为，默认起始日期改为 **2024-01-01**，首个实际交易日由数据库日历确定。`--strategies` 可空格分隔多个中文名称，或逗号分隔；重复选择自动去重，未知名称报错。`红悬停` 为 `红悬停龙` 的别名。

可添加 `--start 2024-01-01 --end 2024-12-31 --as-of 2025-01-06 --output "统计结果" --no-progress`。不指定结束/观察日期时，与原四策略一样采用数据库最新股票行情日、北京时间最近已收盘日、显式观察截止日的最早者。四策略需要信号开始前160个市场交易日；仅运行三策略需89个前置交易日，连同信号日组成90日窗口。新上市股票按上市日起实际可用行数套用原策略门槛。

`--config "配置绝对路径"` 可指定其他私有JSON；相对路径以统一脚本目录为基准。缺少默认配置时使用统一脚本顶部脱敏参数，不能据此连接真实数据库。TLS选项与四策略相同。策略和日期用命令行选择，不写入连接配置JSON。

旧命令 `python "脚本/本地统计/超短线四策略胜率统计_本地版.py"` 仍可用，但该文件现在是兼容入口，实际代码只有统一脚本一份；复制旧入口时必须带上同目录统一脚本。原聚宽 `短线三策略胜率验证_研究版.py` 保留，仅适用于需要通过聚宽取数的研究场景，**不是本地数据库统计入口**。

## 已有数据库能否直接运行全部七策略

四策略继续使用 `ultra_research_calendar`、`ultra_research_universe`、`ultra_research_bar` 原结构，不读取 `short_term_stock` 最近三天名单。对所选策略重算历史信号，再用相同 `forward_outcomes`、`summary_table`、`window_summary` 统计。

**仅完成目前项目的四策略历史采集，不足以保证三策略精确复现。** 已核实：

- 历史采集的 `included_stock()` 仅沪深主板/创业板/科创板，而三策略生产池允许0/3/4/6/8/9开头代码。没有北交所等历史股票，不能把缺失当作从未入选。
- 已存 `open/high/low/close` 为未复权，`adj_*` 为独立查询的后复权。三策略原函数使用前复权日线，红悬停执行 `round(pre_close * (1 + rate), 2)`，并非对复权比例严格不变。补票龙RSV也包含固定 `1e-9`。后复权价格已取整，不能保证反推出当次前复权的相同数值。
- 现有 `factor` 原样保存，没有明确记录每次前复权参考基准和未取整源值。不能仅凭字段名断定可精确转换。聚宽[官方接口源码](https://github.com/JoinQuant/jqdatasdk/blob/master/jqdatasdk/api.py)也有独立的复权和取整选项，但不足以证明本库已存精确前复权窗口。

因此，只有原四策略数据时运行 `--strategies four`；选择三策略/全部会明确报出缺失，不悄悄缩小股票池、改变复权方式或输出部分七策略结果。若用户已有另外保存的完整历史数据，需要先确认其结构再适配；本程序不会自动补采或迁移真实数据。

### 三策略精确回放的最小输入约定

在原三个表之外，读取以下两项已有数据（仅定义读取约定；程序不创建、不填充）：

1. `short_research_window`：每个候选日、每个当日合格股票实际使用的前复权行情窗口。字段 `signal_date, code, trade_date, open, high, low, close, volume`，唯一键为前三项。覆盖截止信号日的90个市场交易日，上市前行不需要；价格及量与生产接口当次输出一致，含停牌填充值，不允许混用不同参考基准。不能把后复权列改名冒充。
2. `short_research_coverage`：按信号日的完整性证据，每日一行。字段 `signal_date, universe_scope, universe_count, eligible_count, rule_version, price_mode, window_days`。固定标识分别为 `production_prefix_0_3_4_6_8_9`、`stock_three_patterns_v2_nonst_cap30`、`jq_pre_exact_signal_window`、90；两项计数分别对应当日完整生产范围历史池、非ST且总市值至少30亿元的股票数量。

`ultra_research_universe` 也必须包含该完整历史池当日的名称、上市日、ST及市值；四策略仍限制为原沪深范围，不随数据库扩充而扩大股票池。三个策略不附加上市满一年、成交额、信号日不停牌等四策略特有限制。已退市股票使用当时历史快照，不用当前存续股票代替。`ultra_research_bar` 还需涵盖这些股票信号日及随后三日的未复权/后复权收盘及停牌状态。

完整性清单须来源于已核实的全量历史导出，不能将当前库行数自行写成“完整”来绕过检查；仅靠当前数据库无法独立证明遗漏股票不存在。若原始数据只包含候选名单而没有全池窗口，也不足以验证策略条件。三策略实现保留精确规则，但用户真实数据是否满足输入约定尚未验证。

所有信号窗口只读到信号日，后续行情另行读取，仅用于表现统计。缺表/字段/信号日/窗口、股票池计数不符和无效值会停止，且不导出部分报告。观察期未成熟、停牌、缺价沿用四策略状态和分母规则。

## 统计结果

第0日为信号日，按市场第1、2、3交易日后复权收盘相对信号日收盘计算表现；严格正收益计胜，持平进分母不计胜，每个期限独立分母。观察日停牌/缺行情/待观察单列，不顺延、不进有效分母。三日窗口只纳入三个观察日均有效的样本。跨策略、不同信号日分别计数，同策略同日同股不重复。

统一输出至 `超短线统计结果/<运行时间>/`：收盘胜率汇总、三日窗口汇总、策略信号明细、按月收盘胜率、数据覆盖CSV和运行参数JSON。仅输出选中的策略；参数文件不保存凭据。三策略覆盖记录按日期列示，四策略按股票列示。没有模拟买入成交、费用或滑点，不能视为可实现交易收益。
