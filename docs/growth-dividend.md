# 创红比与科创红利比

入口为“市场情绪 → 创红比”，地址 `/growth-dividend`。该模块默认采集公开指数日线并保存本地 SQLite；也支持可选的聚宽历史归档与配置MySQL同步，页面始终读取本地历史。公开源路线不需要聚宽账号或行情接口密钥。

“市场情绪”的标签顺序为：国家队动态 → 创红比 → 抱团拥挤度 → 市场热度 → 两融担保比例。

## 指标口径与图表

| 曲线 | 代码或公式 | 线型 | 坐标轴 |
| --- | --- | --- | --- |
| 创业板指 | 399006，原始收盘点位 | 实线 | 左轴，指数点位 |
| 中证红利 | 000922，原始收盘点位 | 实线 | 左轴，指数点位 |
| 科创50 | 000688，原始收盘点位 | 实线 | 左轴，指数点位 |
| 创红比 | 同一交易日创业板指 ÷ 中证红利 | 虚线 | 右轴，比值 |
| 科创红利比 | 同一交易日科创50 ÷ 中证红利 | 虚线 | 右轴，比值 |

五条曲线使用不同颜色。指数采用价格指数点位，不使用ETF价格、全收益指数、市盈率或归一化净值。两个比值均为无量纲数，不乘100，也不显示为百分比。任一分子、分母缺失时对应比值为空，不使用前日数据拼接。

历史起点设为2018-01-01，首个实际交易日为2018-01-02。科创50的基日为2019-12-31、基点1000；上交所在2020-07-22发布回溯历史、次日开始发布实时行情，见[上交所原始公告](https://www.sse.com.cn/aboutus/mediacenter/conference/c/c_20200619_5130972.shtml)。当前公开接口提供的首日为2020-01-02，因此更早的科创50与科创红利比为空，不合成2018年的历史，也不把基点当作接口采集值。

后端始终返回完整历史，前端默认显示以最新有效数据日为终点的五个自然年。可选择近1年、近3年、近5年、全部，或输入日期、拖动底部滑块与在图内缩放。图例可分别开关五条曲线，后台更新保留用户当前缩放范围。缺失交易日显示断点，不补零、不前向填充；正常周末及休市日不作为缺口绘制。

### 历史10%与90%分位基准

创红比与科创红利比分别附加 P10、P90 两条淡色细点线，颜色跟随对应比值，使用右轴；图下完整标明比值名称、分位和数值，避免移动端右侧文字裁切或相近基准重叠。

- 创红比只取2018-01-01及之后的真实有效比值，实际首个采集交易日为2018-01-02。
- 科创红利比从其首个真实有效比值起算；当前历史接口的科创50首日为2020-01-02，更早日期不补零、不参与分位计算。
- 两组样本均包含截至最新数据的完整已加载历史。切换近1/3/5年、全部、输入日期或手动缩放只改变显示范围，基准值保持不变；新增、修正或补齐历史数据后重新计算。
- 排除缺失、非有限和非正数比值，对各自样本升序排序。采用线性插值：位置为 `(n - 1) × p`，其中 `p` 为0.1或0.9；在相邻样本之间按小数部分插值。无有效样本时不绘制；单样本或 P10、P90 相同则合并为一条标注 `P10/P90` 的基准线。
- 图例隐藏某个比值时，同步隐藏它的基准线和图下数值。右轴始终覆盖当前显示比值的历史基准，局部放大不会把基准裁到图外；左轴继续根据可见指数点位调整。

这些是比值历史分布的分位数，并非固定为0.1、0.9的数值线。

## 公开数据来源与完整性

日线优先使用腾讯公开行情接口：

```text
https://proxy.finance.qq.com/ifzqgtimg/appstock/app/newfqkline/get
```

例如参数 `param=sz399006,day,2018-01-01,2018-12-31,640,`。另外两个证券标识分别为 `sh000922`、`sh000688`。返回数组中的日期、开盘、收盘、最高、最低、成交量需按原字段顺序读取，收盘价位于第三项。

接口可能忽略请求开始日，并围绕截止日返回最多约640条记录，不能用一次请求宣称2018年以来历史已经完整。采集按年度窗口请求，再在本地严格筛选日期。对代码、返回结构、日期、正数且有限的收盘值进行校验；超出本次已结束交易日范围的数据不入库。

独立交易日历来自[新浪公开交易日历](https://finance.sina.com.cn/realstock/company/klc_td_sh.txt)。程序只按已知格式解码日期，不执行下载的JavaScript。日历与行情分别保存；每次用日历计算所有应有的“指数 × 交易日”，因此三个指数同时缺某一天也能发现。不能以工作日代替交易日，不能在日历未知时把本次采集标记为全部成功。

## 初始化、每日更新与失败补采

首次服务启动在后台回填历史，网页可查看进度，API与其他模块不必等待全量下载。科创50从2020-01-02开始计入应有记录，之前的空值不计为采集失败。

默认每个交易日北京时间18:00触发更新，使用 `Asia/Shanghai` 时区，不依赖服务器系统时区；新加坡时间与北京时间相同。18点前的自动或手动任务仅采集此前已结束的交易日，不把盘中点位写为当天收盘价。任务优先处理最近日期，再补齐任何历史缺口。

每个窗口校验并提交后，已保存日期形成断点。下次任务只请求仍缺失的窗口和当天数据，不重复回填全部历史。远端网络错误、空响应、日期缺失、取消或进程中断不会删除已保存行情；待补项保留并在之后的任务中重新检查。所有应有记录齐全且交易日历可确认时，才更新“最近成功时间”。

采集使用进程间文件锁，两个API worker或手动与定时任务同时触发也只允许一个任务运行。取消保留已提交批次；再次更新继续补缺。数据、日历、任务状态保存在 `LOG_DIR/market-data/growth-dividend/`，部署沿用现有日志持久化路径。

配置项 `GROWTH_DIVIDEND_WORKER_ENABLED` 默认 `true`，无需修改既有配置即可启用。设置为 `false` 可关闭自动回填和定时任务，手动更新仍可用。该模块不受07点 MySQL快照同步及 `CACHE_REFRESH_TIME` 控制。

## API

以下接口沿用站点账号认证，写操作沿用浏览器CSRF校验。

| 请求 | 返回或行为 |
| --- | --- |
| `GET /api/v1/growth-dividend/history` | 完整 `points`、`latest`、起止日期和采集 `status` |
| `GET /api/v1/growth-dividend/status` | 是否运行、处理进度、待补日期及记录数、最后检查/成功时间与下次计划 |
| `POST /api/v1/growth-dividend/refresh` | 异步启动补采，返回 `{ "started": true/false }` |
| `POST /api/v1/growth-dividend/cancel` | 请求停止当前任务，保留已保存记录 |

每个历史点包含 `date`、`chinext`、`dividend`、`star50`、`chinext_dividend_ratio`、`star50_dividend_ratio`。缺失值为JSON `null`。历史查询不会触发公网采集，任务进度和数据日期分别展示，避免把最近尝试时间当成行情日期。

## 聚宽全历史归档与 MySQL → SQLite 同步

可选入口 `collectors/创红比历史补采_聚宽研究版.py`，独立支持 Python 3.6+。仅依赖同目录 `mysql_connector.py` 获取数据库配置，不调用其他策略。先 `run()` 预览，确认后 `run(preview=False)` 写库。预览不会导入数据库配置或连接数据库；写库强制关闭 SQL echo。不要将真实连接配置上传到代码仓库。

默认 `DEFAULT_START_DATE=None` 使用聚宽平台返回的完整交易日历起点，显式 `start_date='2010-01-01'` 等早于2018年的日期也允许。不依据 `get_security_info().start_date` 截断指数回溯价格。三个指数严格使用 `399006.XSHE`、`000922.XSHG`、`000688.XSHG`；中证红利不能替换成上证红利000015。`get_price(..., frequency='daily', fields=['close'], fq=None)` 保留原始有限正点位，双精度存储，不先四舍五入。平台缺失留空、不补零、不伪造发布前价格。每指数报告实际观测首日、缺失条数；早于首个观测的缺失原因标记 unknown。来源是当前聚宽平台可见历史，可能含修订，不声称历史时点可见性或全市场最早完整覆盖。

聚宽脚本与后端同步使用北京时间18:00确认边界：之前最多请求前一日，之后可请求当日；实际日期仍取平台交易日历。启动时固定本次截止日期。显式未来或未确认收盘的 `end_date` 会在请求行情前拒绝，防止盘中日线被作为不可覆盖的历史值保存。

新表 `growth_dividend_index_history` 主键 `(index_code, trade_date)`，`growth_dividend_trading_day` 主键 `trade_date`；均为 InnoDB，来源与更新时间非空，close 必须双精度。脚本拒绝不兼容字段类型、主键、nullable和表引擎，不修改已有表结构或删除记录。全范围扫描缺口、逐日事务提交，已有价格不重写。`max_days`（默认20000）、`max_windows`（1000）、`window_days`（250）限制运行范围，取消回调 `check_cancel` 可抛异常，已提交数据保留以便重跑。首次大范围采集可通过显式起止日期分批。

管理员点击“同步聚宽历史”调用 `POST /api/v1/growth-dividend/sync-joinquant`。沿用登录、管理员和CSRF保护；与公开行情更新共用排他锁，支持停止。后端以只读 REPEATABLE READ 一致快照读取配置MySQL，检查全量元数据、来源、数值、交易日与行情一致性后，才在单个SQLite事务中追加。任何失败或发布前取消回滚本次新增，不修改源库。已有相同键永不覆盖，数值冲突在同步摘要中计数。仅新补入记录标识聚宽来源，不把公开源历史改称聚宽来源。网络结果不确定时界面禁止立即重复提交，重新加载状态后恢复。

早于2018年的记录与日历保存在SQLite归档中，公开交易日历刷新不删除这些归档。页面与分位计算仍从2018年起，科创50仍从2020-01-02起；归档更早数据不会改变既有比值、P20/P80窗口或图表标签。

公开源更新同样只追加缺失行情，不覆盖已确认的聚宽或公开源记录；即使当天再次采集、数值一致，也保留原来源和时间。不同点位写入本地对照记录，状态与页面展示差异条数及最近的日期、指数和点位，不展示底层响应或连接信息。重复相同候选不重复计数。公开日历也只追加；若新响应遗漏已知交易日，则保留原日历并提示错误，不用缩小日历掩盖待补日期。
