# CCI 数据更新与断档恢复

## 更新范围

手动“更新数据”和北京时间每天 21:00 的自动采集调用相同逻辑：先核查当天三档，再按 CCI5500、CCI5000、CCI4500 分别补齐缺失日期。

- 首次使用恢复逻辑时，按每档数据库中**最后一条真实报价日期**固定恢复起点。较新报价的成功不会抬高这个起点，也不会掩盖其他日期或档位的缺口。
- 某档没有任何报价时，使用持久化的服务首次初始化日期（北京时间），不任意从 2026 年初抓取全量历史。恢复起点及依据随状态返回。
- 不回溯起点之前的既有历史缺口。已有历史记录不删除、不覆盖；当天记录仍可按来源真实修订更新。
- 定点修复例外：仅针对已报告的 2026-11-05、2026-11-06。若某档已有更早和更晚的真实报价，而这两个日期缺失且早于固定恢复起点，则单独查询这两个日期中的缺口，不改变起点、不扩展为全量历史补采。已存在的记录不覆盖；空响应或失败继续保留待查，补齐后不再为该缺口发起请求。状态中的 `historicalRepairDates` 标明本轮的定点修复日期。
- 数据库主键为 `(day, grade)`，重复点击、重试、重启不会产生重复报价。人工更新与定时更新共用跨进程锁；权限及 CSRF 要求保持不变。

## 来源与真实性

来源是 `https://coalindex.com/api/market`，属于非官方网络汇集。请求使用公开的 `tab=steamcoal-index`、`date_from`、`date_to`、`index_name` 过滤条件。

2026-11-09 的只读探测确认历史区间查询可用：CCI5500 在 2026-10-01 至 2026-11-09 的请求返回 HTTP 200，`total=23` 与 23 条记录一致，实际记录日期为 2026-10-08 至 2026-11-06。公开页面的翻页发生在客户端，没有发现可依赖的服务端页码契约。此探测不保证来源未来可用，也不代表当前所有档位都已发布报价。

每次请求最多 31 个自然日，校验响应 total 与记录数量、日期边界、币种/单位、档位、日指数类型、价格及重复记录。不猜测分页，不接受被截断响应。单响应上限 2 MB，禁止重定向。严格使用来源记录日期，不把最新报价改成请求日期。

空日期只表示“来源暂无报价”，无法据此认定节假日或永久缺失。不会补零、沿用前值或捏造交易日。无报价和请求失败都保留在恢复范围中，后续更新继续核查；来源删除或始终不提供的报价无法可靠恢复。

## 上限、延续与重试

- 单次最多 36 个请求，包括优先核查当天的 3 个请求；历史区间按每档最多 31 天分段。
- 单次采用 120 秒协作式截止时间，流式读取及请求之间检查。单次读超时 25 秒、连接超时 10 秒，正在等待的读取可能稍晚于总截止时间退出。
- 每个完整验证的窗口单独事务保存。后续窗口失败不撤销已恢复的数据；被截断、冲突或未验证的窗口不写报价。
- 未完成窗口不会被静默丢弃。持久化每个缺口的检查结果/时间，优先从未检查及最久未检查的窗口继续，避免最早的无报价日期阻塞后面的有效历史。
- 当天三档未完整取得，或历史请求失败/达到预算时，21:00 定时任务维持每 30 分钟一次、最多额外 3 次的当日预算。重启、旧版 18:00 记录与并发实例仍计入原有当日配额；跨日停止旧时点重试，下一次正常更新继续补历史。
- 当天三档已核验，且全部待查窗口均已完成查询时，可标记更新完成；这并不表示来源空日期已有报价。页面单独显示仍缺多少、来源暂无多少及本次未查询多少。

## 可观察性与验证

状态及日志包含恢复范围、三档各自起点与依据、总返回量、当天命中档位、新增/变更、已尝试缺口、来源空缺、延后缺口、实际请求数，以及逐档/逐窗口的 HTTP 状态、真实最新日期与耗时。日志不输出异常正文、请求凭据或响应内容。

离线测试覆盖三档不同起点、跨日/跨年、停机恢复、晚发布补齐、某档网络失败、来源无报价、无初始记录、重复更新、预算延续、截止/停止、真实日期校验、并发锁、管理员/CSRF 与 21:00 当日重试迁移。浏览器 E2E 仍需可启动 Chromium 的环境运行。
