# 四策略本地收盘胜率统计

唯一程序入口：[超短线四策略胜率统计_本地版.py](../脚本/本地统计/超短线四策略胜率统计_本地版.py)。原 `scripts/` 副本已删除。程序是完整单文件，不导入其他项目代码，也不调用聚宽接口。数据库只读，结果写到本地。

运行时默认读取 `脚本/本地专用/本地统计/超短线四策略胜率统计配置.json`，该文件被 Git 忽略。原本机脚本中的数据库连接和 TLS 验证设置已迁移到此配置，业务代码只保留一份。GitHub 上的程序仅含占位连接值，不含真实凭据。

## 运行

本地Python建议3.9或以上，安装依赖：

```powershell
python -m pip install pandas numpy sqlalchemy pymysql
python "脚本/本地统计/超短线四策略胜率统计_本地版.py"
```

默认统计信号日从 **2026-07-01** 到数据库最新已收盘日，并读取信号区间之前160个交易日供指标预热。示例：

```powershell
python "脚本/本地统计/超短线四策略胜率统计_本地版.py" --start 2026-07-01 --end 2026-09-30 --as-of 2026-10-23
```

以上命令在项目根目录执行。`--end` 为信号截止日，`--as-of` 为后续表现观察截止日，可以更晚。没有指定时，观察截止日取股票行情最新日期，且不使用北京时间16点前的当日日线。数据库地址、用户或 TLS 有变化时，修改私有 JSON 中的 `DB_CONFIG`、`DB_TLS_VERIFY`、可选 `DB_TLS_CA_PEM`。

默认配置位置根据程序文件定位，不依赖当前工作目录。可用 `--config "配置文件绝对路径"` 指定其他配置，相对路径以程序所在目录为基准；显式指定的文件缺失时会报错，不会悄悄改用另一套连接。默认配置不存在时沿用顶部参数，因此也可以单独复制此程序并填写顶部 `DB_CONFIG` 运行。导入模块不会自动读取本机配置。

私有 JSON 结构如下，勿提交真实配置：

```json
{
  "DB_CONFIG": {
    "host": "your_mysql_host",
    "port": 3306,
    "dbname": "your_database",
    "dbuser": "your_database_user",
    "dbpassword": "your_password"
  },
  "DB_TLS_VERIFY": true,
  "DB_TLS_CA_PEM": ""
}
```

当前版本 `2026-10-28.1` 默认开启动态进度条，每半秒在同一行刷新。显示连接/日历、股票清单、行情读取与逐只计算、汇总、文件导出等阶段，以及实际完成数、百分比和总耗时。数据库查询等待期间也会刷新；未知任务量的阶段只显示“处理中”，不会伪造进度。中断或失败会停止后台刷新并标记当前阶段。`--no-progress` 或顶部 `PROGRESS_ENABLED=False` 可关闭进度条。

### certificate verify failed

程序默认 `DB_TLS_VERIFY=True`，本机 JSON 可覆盖此设置，迁移时保留原设置。该错误表示服务器证书验证未通过，可能涉及信任链、证书有效期或使用IP连接时与证书身份不匹配。使用与证书匹配的数据库域名，私有CA的PEM证书全文可直接填写在 `DB_TLS_CA_PEM`，不需要独立证书文件。

若只是临时排查，且已确认目标可信，可以显式跳过证书验证：

```powershell
python "脚本/本地统计/超短线四策略胜率统计_本地版.py" --start 2026-07-01 --no-tls-verify
```

此选项仍请求TLS连接，但不能验证服务器身份，有连接到冒充服务器的风险。排查后应配置可信证书并恢复验证。`--tls-verify` 强制开启验证，`--no-tls-verify` 显式关闭；两者不能同时使用。未传选项时沿用当前加载的 `DB_TLS_VERIFY`。脚本不会在证书失败后自动切换验证设置。

## 胜率定义

信号日为T，分别找市场日历中的T+1、T+2、T+3：

```text
第N日涨幅 = (第N个交易日收盘价 / 信号日收盘价 - 1) × 100%
第N日胜率 = 第N日涨幅严格大于0的样本数 / 第N日有效样本数 × 100%
```

持平和下跌都不算胜，持平保留在有效分母内。**没有沪深300、超额收益、指数过滤、次日开盘买入或交易成本口径。** 不读取指数行情。

默认比较同口径后复权收盘价 `RETURN_PRICE_FIELD='adj_close'`，避免除权、拆股造成虚假的价格下跌。若要求比较实际未复权收盘价，改成 `RETURN_PRICE_FIELD='close'`。明细同时保留信号日未复权与后复权收盘价；策略形态指标统一使用后复权OHLC。

例如信号日收盘10元，后续三个交易日分别为10.2、10.0、9.8，则第1日胜，第2日不胜，第3日不胜。“三日内任一收盘上涨”另列窗口统计，例中为胜，不能与第三日收盘胜率混为一项。

未来日期尚未到观察截止日时标为“待观察”；目标日没有行情标为“缺少行情”（可能包括退市）；目标日停牌标为“停牌”。这些情况分别报告，不填0、不顺延到之后有成交的日期，也不计入该期限有效胜率分母。三个期限的分母可能不同；三日窗口要求三个期限均有效。每次评估须同时看缺失和停牌数量，不能只看胜率。

## 默认筛选与四个规则

共同条件：信号日历史快照 `eligible=1`、非ST、总市值至少30亿元；上市至少365个自然日，当日成交额至少5000万元，非停牌且有成交，有60个交易日的完整价格历史。上市天数与成交额过滤都是显式研究参数，可在 `PARAMS` 修改。板块包括沪深主板、创业板、科创板。

| 策略 | 默认规则 |
| --- | --- |
| 强势股首次缩量回踩 | 高点日创此前20日收盘新高、10日涨幅至少8%、MA20上行；之后连续下跌1—3日，再首次收盘转涨。最低价较高点回撤3%—8%，下跌阶段均量不超过高点日5日均量的80%，信号收盘守住MA10和MA20。信号日10日涨幅的百分位严格超过当日合格股票池80%。 |
| 超跌后止跌反弹 | 信号前3日跌幅至少8%，信号日收盘高于前日最高价，且收阳、成交量不低于此前5日均量。 |
| 平台突破后的首次回踩 | 突破前20日高低区间不超过15%；收盘突破此前20日最高价，量至少为此前20日均量1.5倍。随后1—5日首次触及突破价上下2%区域，低点不低于突破价98%、收盘守住突破价且收阳，量不超过突破日80%。首次触及不合格，则不再重复使用同一突破日。 |
| 首板后的分歧转强 | 按数据库实际涨停价判断收盘涨停，且此前20日没有收盘涨停。次日收盘回落但较首板收盘跌幅不超过6%，量不低于首板80%。首板后第2或第3日首次收盘超过前日最高价、收阳，量至少为前日1.1倍，收盘不低于首板97%，分歧期间最低价不低于首板92%。 |

这些是将讨论思路固定下来的日线研究假设，不代表经过优化或已经证实高胜率的策略。参数全部在顶部 `PARAMS` 中，实际运行参数写入JSON；JSON中的默认规则描述是上述默认值，修改后以实际参数为准。日线不能还原盘中“分歧转强”的具体时刻，本脚本采用收盘确认。

信号只使用T日及之前的数据。先对每只股票完整历史计算指标，再筛信号日期；不能先删除ST、低市值或停牌行后再做均线/shift。ST、市值条件只决定信号日能否入选，之后变ST或跌破30亿元仍保留后续表现。对候选股票按批读取，不使用今天仍上市股票的名单回筛历史。

同一股票在不同日期触发分别计样本；同日触发多个策略分别计入各策略，不模拟持仓去重。样本可能重叠或相关，结果是信号后的价格表现统计，不是可成交交易回测。没有公告利空、历史行业或分钟线过滤。

## 输出

终端显示进度和四策略×三个期限的12行汇总。本地 `超短线统计结果/运行时间/` 保存：

| 文件 | 内容 |
| --- | --- |
| `收盘胜率汇总.csv` | 每个策略第1、2、3日的有效样本、上涨/持平/下跌次数、胜率、平均/中位/最差/最好收益，以及待观察、停牌、缺失数量 |
| `策略信号明细.csv` | 策略、股票、信号日、锚点日、参考收盘价，以及三个目标日的价格、状态、涨幅、胜负；`d1_win/d2_win/d3_win` 为1胜、0不胜、空值不可统计 |
| `三日窗口汇总.csv` | 三个期限全部有效时，三天内是否至少有一天收盘高于信号日 |
| `按月收盘胜率.csv` | 按信号月份拆分的同口径结果 |
| `数据覆盖.csv` | 每只股票读取的行情/快照行数、快照存在但行情缺失数、可用基础样本数 |
| `运行参数.json` | 日期区间、观察截止日、价格口径、实际参数、默认规则描述及统计限制；不保存数据库密码 |

CSV使用UTF-8 BOM，便于Windows Excel打开。无触发或无有效样本时胜率为空，终端显示 `--`，不会伪装成0%胜率。只有快照、行情尚未完成时，应先完成行情采集后统计，并检查数据覆盖文件。
